0 结论

P0 完成一条可落地闭环：用户默认从“我的 Agent”使用和管理已有能力，也可以进入市场发现或添加 Agent，或通过导入和对话创建本地 Agent；市场来源的本地 Agent 出现新版本时，仅在“我的 Agent”列表提示并由用户手动确认覆盖更新。

1 目标与范围

1.1 用户和场景

ToC 用户需要像使用应用一样发现、添加和启动 Agent，不应先理解 Prompt、Skill、MCP 或运行架构。

工业工程师需要清楚 Agent 的数据输入、运行位置、能力边界、依赖资源和输出结果，并能够检查本地文件。

Agent 管理页承担能力发现和配置管理；具体任务仍在对话页发起，文件上传和高风险确认由统一策略负责。

1.2 P0 目标

1.  用户可在 Agent 市场快速判断 Agent 是否需要添加、运行在本地还是云端，以及核心能力是否受保护。

2.  用户可通过对话创建或导入 Agent，并在“我的 Agent”中找到。

3.  本地 Agent 可查看提示词和完整 Agent 目录，并可进入对话或本地文件夹修改。Agent 所需 Skill 随 Agent 目录存放，不建立外部关联。

4.  市场本地 Agent 检测到新版本后，可由用户手动确认覆盖更新。

5.  用户可从详情页或“我的 Agent”卡片删除 Agent；市场来源的 Agent 删除后仍可在市场再次添加。

1.3 P0 不做

市场评分、评论、付费、排行、复杂运营位和发布审核。

自动更新、本地修改检测、差异合并和文件级冲突解决。

详情页内直接手动编辑完整 Agent 配置，以及常驻助手浮窗。

本地 Agent 选择云端运行；后续仍由新任务层选择运行域。

3.3 简介弹窗

市场 Agent 与“我的 Agent”中的云端 Agent 共用一套简介弹窗。顶部只显示系统语言对应的展示名称与描述；下方显示作者、版本、来源、运行类型、标签和系统语言对应的推荐问题。

简介弹窗不展示内部 name、description，也不同时展示另一语言的名称与描述；推荐问题不提供中英文切换按钮。字段缺失时按当前语言、另一语言、内部字段的顺序回退。

显示推荐问题和必要的输入说明，但不展示本地文件授权、数据上传授权或高风险确认。云端 Agent 不返回提示词、目录文件或内置 Skill 内容。

底部操作根据添加状态显示“添加”或“使用”；市场简介不展示新版状态和更新入口。本地 Agent 添加后才能进入完整查看页。

4 我的 Agent

4.1 页面布局

“我的 Agent”是页面默认入口，聚合当前账号可用的全部 Agent。对话创建和导入统一显示为“我创建的”，市场本地 Agent 和已添加的云端 Agent 统一显示为“市场添加”。

[table]



4.2 创建入口

顶部栏右侧保留“导入 Agent”和“新建 Agent”两个入口。“新建 Agent”进入对话创建，不增加第三种空白表单创建方式。两种方式生成的 Agent 在来源字段中均显示为“我创建的”。

[table]



4.3 导入校验

检查 Agent 根目录、metadata、agent.md 及目录内文件的基本完整性；Skill 如有需要，直接放在 Agent 目录中。

“我创建的”Agent 内部名称冲突时提示“覆盖现有 Agent”或“作为副本导入”；默认选择副本并生成新的内部名称。

缺失可选文件不阻止导入；缺失必填文件时展示可修复错误，不产生半成品 Agent。

5 Agent 查看与编辑

5.1 页面定位

P0 将该页定位为“完整配置查看页＋编辑入口”。用户可以理解 Agent 的组成并进入合适的编辑方式，但不在主页面堆叠完整表单。

[table]



提示词阅读采用长窗口嵌入方案。完整内容始终在页面内可达，默认窗口可独立滚动；需要连续阅读时可点击“展开阅读”增加窗口高度。P0 不采用提示词铺满整页的方案，以免用户难以返回推荐问题和顶部操作。本地目录不再单独占用底部卡片，统一放在顶部信息区。

5.2 对话编辑

1.  点击“去对话编辑”后进入与 Skill 原型一致的完整对话页，左侧边栏保持不变。

2.  输入框上下文明确显示当前 Agent 和“编辑模式”，避免用户误认为在执行普通任务。

3.  Agent 先返回修改说明和影响范围；用户点击“应用修改”后才写入 Agent。

4.  应用成功后展示变更摘要，并提供返回 Agent 查看页。

5.3 本地文件夹编辑

详情页右上角保留唯一“打开文件夹”入口，调用系统文件管理器打开当前 Agent 根目录；提示词区域不再重复提供打开目录按钮。

用户可使用外部编辑器修改 agent.md、资源文件、目录内 Skill 和配置；P0 不进行文件变化监听或冲突检测。

重新打开 Agent 查看页或手动刷新时重新读取目录；格式错误时保留原文件并展示校验错误。

localPath 是桌面端本地状态，不写入 Agent 公共元数据。若字段未保存但可按固定安装根目录＋内部名称推导，则无影响；若客户端最终无法解析到实际目录，顶部显示“本地目录缺失”，并禁用运行、打开文件夹、对话编辑和覆盖更新，提示重新定位或重新导入。

5.4 删除与移除

入口一：本地 Agent 查看页右上角显示“删除”；入口二：“我的 Agent”卡片右下角三个点菜单提供删除或移除。市场卡片不提供删除入口。

我创建的本地 Agent：确认后从“我的 Agent”删除并删除本机 Agent 目录，弹窗明确说明不可撤销。

市场添加的本地 Agent：确认后删除本机下载目录并从“我的 Agent”移除；市场源不受影响，可再次添加。

云端 Agent：仅删除当前账号或空间的使用引用，不删除市场云端 Agent，也不涉及云端配置内容。

P0 不提供“仅移除记录但保留本地文件”选项，避免保留无法管理的孤立目录；删除失败时保留 Agent 记录并允许重试。

6.2 手动更新流程

1.  联网时以“市场来源＋作者＋内部名称”匹配市场 Agent，并直接比较本地记录的 version 与市场当前 version；客户端不保存 latestVersion。

2.  发现新版本后，仅在“我的 Agent”列表卡片显示“有新版本”状态与更新按钮；市场仍只显示是否已添加。

3.  用户点击更新，弹窗明确提示将覆盖当前 Agent 本地目录，可能丢失自行修改。

4.  用户确认后下载新包至临时目录，完成包结构和完整性校验。

5.  校验通过后替换本地 Agent；失败时继续保留旧版本并提供重试。

[table]



6.3 P1 自动更新预留

P1 可在设置中增加“自动更新市场 Agent”开关，仅对市场来源的本地 Agent 生效。自动更新必须建立在可判断“无本地修改”的基础上；建议由市场包提供文件清单和安装基线，只检查清单内文件，并排除缓存、日志、任务输出和工作区。

10.2 交付清单

产品：提供市场本地 Agent、云端受保护 Agent，以及“我创建的”Agent 真实示例；“我创建的”需覆盖对话创建与导入路径。

设计：输出市场页、我的 Agent、卡片删除菜单、删除确认、简介弹窗、导入弹窗、更新确认、查看页、提示词展开态、对话创建和对话编辑关键状态。

客户端：实现本地 Agent CRUD、系统语言回退、完整提示词读取、顶部目录与文件夹打开、删除或移除、市场版本匹配和原子更新。

云端：市场列表与版本元数据、云端 Agent 引用和调用、受保护配置隔离。
