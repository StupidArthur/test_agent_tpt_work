1. 文档目标

本文用于产品、设计、研发和测试共同评审 TPT 桌面端 Skill 模块，明确：

Skill 管理、查看、使用、修改、创建、导入和市场更新的 P0 用户闭环。

P0 必须交付的逐项需求、核心规则和验收口径。

2. 产品目标与核心结论

2.1 产品目标

Skill 模块面向大量普通工程师用户，提供低门槛的本地能力扩展机制。用户无需理解复杂的 Agent 编排、代码结构和版本管理，即可完成：

查看、启用、停用和使用本机已有 Skill。

从 Skill 市场发现、查看并添加 Skill。

导入已有 Skill，或通过对话生成新 Skill。

查看 Skill 名称、描述和按实际数据存在的扩展字段。

查看 Skill 完整目录和文件内容。

通过对话或本地文件夹修改 Skill，并使有效修改作用于后续任务。

删除不再需要的 Skill，并通过 Windows 回收站保留系统级恢复能力。

在与桌面端其他任务一致的对话界面中使用、修改或创建 Skill。

4. 核心对象与数据分层

4.1 两层存储模型

Skill 自身内容与桌面端管理状态必须分开存储：

[table]

skill-registry.json 是逻辑数据文件名。研发可使用 JSON 或本地数据库实现，但必须满足：不放入 Skill 目录、不被用户导入或导出、不因用户编辑 Skill 包而丢失。

4.2 SKILL.md 字段

P0 统一从 SKILL.md YAML Front Matter 读取可移植字段，不要求 Skill 包额外提供 meta.json。

[table]

示例：

---
name: report-generator
description: Generate a standardized handover report from user data and templates.
name_cn: 交接班报告助手
name_en: Handover Report Assistant
description_cn: 根据数据和固定模板生成标准化交接班报告
description_en: Generate a standardized handover report from data and a fixed template.
tags:
  - 报告生成
  - 生产管理
source: market
version: 1.2.0
author: TPT
icon: report-documents
suggested_prompts:
  - 根据这份数据生成本周交接班报告
---

字段显示规则：

中文界面名称按 name_cn → name_en → name 回退；英文界面按 name_en → name_cn → name 回退。

中文界面描述按 description_cn → description_en → description 回退；英文界面按 description_en → description_cn → description 回退。

name、description 仍是导入兼容和 Agent 调用所需的阻塞性必填字段，双语字段不能替代它们。

TPT 新生成和市场上架的标准 Skill 应写入四个双语展示字段、type、author 和 icon；外部导入包缺失兼容字段时允许通过回退规则正常使用。

type 仅允许 market、user：可信市场通道添加的 Skill 为 market；对话创建、本地创建及本地导入统一为 user。

本地导入包即使声明 type: market，也不能因此建立市场关系；导入后的受管副本统一规范为 type: user。

标签、版本、作者和推荐问题不存在或为空时不展示，也不保留空占位。

本地创建或导入的 Skill 可不声明 version；市场 Skill 必须声明 version。

P0 的版本仅为只读元数据，不代表支持用户创建版本、查看历史或回退。

4.3 P0 图标规范

图标用于提高卡片识别效率，不用于区分市场下载、用户创建或本地导入。不同来源使用同一套视觉规则。

4.3.1 视觉规格

图标容器固定为 40×40 px，圆角 8 px。

采用扁平化填充风格，不使用拟物、高光、复杂渐变或细线图标。

预置图标由“纯色或浅色底板 + 单色填充图形”构成，前景和背景必须满足桌面端可读性要求。

我的技能卡片、Skill 市场卡片统一使用该规格；完整 Skill 页面可保持 40×40 或等比放大，不改变圆角比例和图形风格。

PNG 加载失败、字段非法或资源缺失时立即显示通用默认图标，不显示破图，也不阻断 Skill 使用。

4.3.2 P0 图标来源

[table]

P0 采用以下14类流程工业日常工作图标。每个 Skill 选择一个主图标，交叉能力继续通过 tags 表达，避免多图标和分类歧义。

[table]

系统可根据名称和描述作简单关键词匹配，例如“报告/总结”匹配 report-documents，“数据/统计”匹配 data-statistics，“故障/设备诊断”匹配 equipment-diagnosis；无匹配时使用 general。模型只需输出上述 ID，没有生图能力不影响 Skill 创建。



[blockquote]

4.3.3 字段值、图片格式与安全

使用预置图标：icon: report-documents。

使用自定义图片：icon: assets/icon.png。

P0 自定义图片仅支持 PNG；推荐原始尺寸 256×256 px、正方形、文件不超过 512 KB，展示时缩放为 40×40 px。

图标路径必须是 Skill 根目录内的相对路径；禁止绝对路径、../、网络 URL、Base64、GIF、ICO 和未经安全处理的外部 SVG。

应校验文件真实 MIME、尺寸、大小和规范化路径，不能只根据扩展名判断。

预置图标资源打包在桌面客户端；自定义图标放在 Skill 目录 assets/icon.png，随导入、导出、市场下载和更新迁移。

桌面端可生成缩略图缓存，但缓存不是权威数据，不能替代 SKILL.md 的 icon 声明和包内源文件。



4.6 来源与市场关联规则

P0 界面不按来源分组，也不在卡片上展示来源标签。

type 在 P0 只回答“是否来自可信市场”：从市场添加且具备稳定市场关联的 Skill 为 market；对话创建、本地创建、本地导入及没有市场关联的预装 Skill 统一为 user。

市场 Skill 添加后始终保持 source.type = market 和原 source.id；P0 不判断、展示或存储“已本地修改”状态。

SKILL.md 中的 type 用于包自描述和可选展示；桌面端注册信息用于可信市场关联。用户修改 YAML 中的 type 不得新增、删除或伪造市场关联。

市场新版通过 检测id、name、source、version 与市场最新版本比较发现。用户手动确认更新后，以市场新版替换当前本地文件；更新前需提示可能覆盖本地修改。

展示名称允许重复；本机有效 Skill 的id必须唯一。

Agent 选用 Skill 时，将 Skill 内容复制到 Agent 自身目录形成独立副本，不保存对原 Skill 目录的共享引用。删除原 Skill 不删除或修改已有 Agent 副本。



5. 信息架构与页面关系

5.1 桌面端全局框架

Skill 模块沿用 V15.5 桌面框架，不单独建设一套导航与对话容器。

顶部为桌面窗口栏，左侧展示 SupWork / Skill 管理，右侧依次展示最小化、最大化/还原、关闭。

窗口按钮在真实桌面客户端中调用原生窗口能力；HTML 原型只演示位置与状态反馈。

左侧边栏固定展示品牌、新建任务、定时任务、文件数据、应用和“更多”分组。

“更多”下展示 Agent、Skill、MCP 和 IM；进入本模块时 Skill 处于选中状态。

边栏下部按“置顶—项目—最近”展示历史任务，底部固定用户信息。

进入 Skill 使用、修改或创建对话时，全局边栏保持可见，用户可通过返回按钮回到原 Skill 页面。

不展示 Skill 一级“设置”、顶部 Skill 工具或消息通知栏。

5.2 Skill 管理页结构

左侧导航：“更多 → Skill”。

Skill 页面顶部直接展示页签和操作区，不设置独立“技能管理”标题栏。

内容区顶部左侧：我的技能、Skill 市场页签。

内容区顶部右侧：搜索框、导入 Skill、新建 Skill。

我的技能页签额外提供启用状态筛选；Skill 市场页签提供分类筛选。

Skill 页面不提供一级“设置”、顶部 Skill 工具和消息通知入口。

6. 我的技能

6.1 列表范围与筛选

“我的技能”展示本机存在的全部 Skill，包括系统内置、市场添加、本地创建和本地导入。P0 不提供来源筛选，仅提供：

搜索：按 name_cn、name_en、description_cn、description_en、技术 name、技术 description 和标签匹配。

启用状态：全部状态、已启用、未启用。

6.2 Skill 卡片

卡片展示 Skill 图标、当前界面语言对应的名称和描述、标签胶囊、启用开关和快捷使用。右下角使用独立三点按钮承载低频危险操作。图标统一为 40×40 px、圆角 8 px、扁平化填充风格。市场来源 Skill 检测到新版时额外展示“有新版本”、版本变化和“更新”。卡片不展示来源、分类、本地运行、作者、详情或编辑按钮；版本仅在确有市场更新时用于说明 已安装版本 → 市场版本。

交互规则：

单击卡片主体：打开完整 Skill 页面。

单击启用开关：仅切换启用状态，不触发卡片跳转。

单击“快捷使用”：进入统一对话并显式选中当前 Skill。

单击“更新”：打开更新确认弹窗，不触发卡片跳转，也不改变启用开关。

单击右下角三点：展开卡片菜单；P0 菜单仅包含“删除”，菜单操作不触发卡片跳转。

单击“删除”：打开删除确认弹窗，不立即移除数据。

市场来源 Skill 的卡片状态：

[table]

启用状态与更新状态彼此独立。未启用的 Skill 也可以更新；更新不会自动启用或停用 Skill。



[blockquote]

6.3 启用与停用

启用后，General Agent 可以自动发现并调用该 Skill。

自定义 Agent 仍受自身配置的 Skill 和工具可见范围限制。

停用后，Skill 不参与自动发现和自动调用。

快捷使用是用户显式选择，即使 Skill 已停用仍允许使用，不自动改变启用状态。

开关切换立即生效，但不终止已经开始运行的任务。

7. 完整 Skill 页面

7.1 页面定位与顶部操作

完整 Skill 页面是本地 Skill 的统一查看和操作页面。P0 页面只读，不提供字段或文件内联编辑，也不显示保存状态。

左侧展示返回按钮和 Skill 名称；右侧提供：

使用：进入统一对话并选中当前 Skill。

对话修改：进入统一对话页的 Skill 修改模式。

本地打开：使用系统文件管理器打开 Skill 根目录。

删除：打开删除确认弹窗；仅“我的技能”的本地完整页展示，市场未添加 Skill 的只读页不展示。

P0 不展示保存、保存为版本、版本记录、调试、发布和产品内编辑按钮。

7.2 基础字段

内容区顶部使用独立只读字段展示：

Skill 图标：固定展示；缺失或异常时显示通用默认图标。

技能名称、技能描述：按当前界面语言及统一回退链固定展示。

标签、来源类型、版本、作者：存在时展示，缺失时不占位；type 显示为“市场”或“用户”。

图标位于名称左侧；名称和描述构成主要信息区，可选字段置于下方并自然补位。字段区域不可输入，不展示分类字段。后续新增字段由统一字段配置决定，避免我的技能完整页、市场简介和市场只读页出现不同逻辑。

7.3 Skill 目录

基础字段下方按 Skill 包实际内容展示完整目录，采用“文件树 + 文件预览”结构：

默认选中并打开 SKILL.md。

文件夹支持展开和收起；单击文件后在右侧切换预览。

Markdown、JSON、代码和文本以只读文本展示；图片直接预览。

Office、压缩包和其他二进制文件展示名称、类型、大小和本地打开提示。

不强制要求 meta.json、scripts、references 或 assets 必须存在。

P0 不提供文件新建、重命名、移动、删除和内容编辑。

7.5 外部修改监听

TPT 监听 Skill 根目录变化。

文件保存后进行结构、必填字段、路径和格式校验。

校验成功后更新最新有效内容，新任务立即使用。

校验失败时提示文件和原因，运行继续使用最近有效内容。

P0 不比较当前目录与市场安装内容，也不生成“已本地修改”状态。

7.6 删除 Skill

删除入口位于“我的技能”卡片右下角三点菜单和本地完整 Skill 页面右上角。全部本地 Skill 均可删除，包括系统内置、市场添加、本地创建和本地导入；市场未添加 Skill 的简介与只读页不提供删除。

删除流程：

用户点击“删除”后弹出确认窗口，展示 Skill 名称，并说明该 Skill 将从“我的技能”和可调用范围移除，完整本地目录将移入 Windows 回收站。

用户取消时不改变文件、注册信息、启用状态和市场添加状态。

用户确认后，系统先锁定该 Skill，阻止新的自动发现与调用，再调用 Windows 回收站能力移动完整 Skill 根目录。

目录成功移入回收站后，删除本地注册信息、运行索引和搜索索引，并立即刷新列表。

任一步骤失败时，本次删除视为失败，界面保留原 Skill 和原状态并提示原因，不产生目录已删但卡片仍存在等半删除状态。

市场来源 Skill 删除成功后，其市场卡片由“已添加”对勾恢复为“添加”；用户后续可重新下载安装。

删除不终止已经开始运行的任务，运行中任务继续使用启动时锁定的内容快照；后续新任务不能再选择或自动调用该 Skill。

Agent 使用 Skill 时已将内容复制到 Agent 自身目录，属于独立副本；删除原 Skill 不影响已有 Agent 副本，也不需要引用检测或级联删除提示。

P0 不在产品内提供撤销按钮。用户从 Windows 回收站恢复目录后，需通过“导入 Skill”重新加入“我的技能”。

8. 对话使用

8.1 入口与跳转

入口包括“我的技能”卡片的“快捷使用”和完整 Skill 页面的“使用”。

点击后跳转到桌面端统一对话/任务页，并将当前 Skill 作为已选上下文带入输入区。

Skill 模块仅定义跳转、预选和运行规则；左侧边栏、输入框、附件、权限、模型和发送等通用交互沿用桌面端对话模块，不在本需求重复建设。

8.2 Skill 使用规则

Skill 作为当前任务的显式能力，不替换 General Agent。

已停用 Skill 仍允许用户显式选择使用，不因快捷使用而自动切换启用开关。

任务启动时锁定当前 Skill 最新有效内容；运行期间发生的修改仅影响后续新任务。

Skill 运行仍受当前 Agent 可见能力、工具权限、数据权限和桌面端统一安全策略约束。

9. 对话修改

9.1 入口与上下文

完整 Skill 页面点击“对话修改”后进入桌面端统一对话页的 Skill 修改模式，不打开产品内编辑器。

系统带入 Skill 的稳定 skill_id 和本地最新完整目录；修改对话与普通任务历史隔离。

Skill 模块不重复定义通用对话页面，只定义修改对象、写入和生效规则。

9.2 修改与生效

用户用自然语言描述修改要求。

Agent 判断意图、影响范围、冲突和校验风险。

明确且低风险的修改完成校验后直接原子写入并生效，不固定要求“应用修改”。

需求含糊、影响范围较大、可能覆盖外部变化或存在其他风险时，由 Agent 动态生成确认交互；取消不得写入。

成功后说明修改摘要、涉及文件、校验结果和生效范围；后续新任务立即使用，运行中任务保持原快照。

校验失败不替换当前有效内容；P0 不额外记录或展示市场 Skill 的本地修改状态。

10. Skill 市场

10.1 页面定位与浏览

Skill 市场与我的技能并列为同一页面的页签，不放入弹窗，也不在本期与 Agent、插件市场合并。市场只加载目录和当前查看内容，不将全部 Skill 下载到本地。

市场支持中英文名称、描述和标签搜索，支持市场分类筛选和分页或增量加载。



[blockquote]

10.2 市场卡片与状态

卡片展示 40×40 扁平化填充图标、当前界面语言对应的名称和描述、标签、添加状态和“查看简介”；不展示版本、作者、本地修改或市场更新状态。图标缺失或加载失败时使用通用默认图标。

[table]

Skill 市场只承担发现、查看和添加。用户添加后的维护状态统一回到“我的技能”处理，避免市场和本地管理页出现重复更新入口。

10.3 市场简介弹窗

点击卡片主体或“查看简介”打开弹窗，展示图标、当前界面语言对应的名称和描述、标签、来源、版本、作者、推荐问题和 SKILL.md 摘要；除图标、名称和描述外，其他字段存在时才展示。

底部只保留：

查看：进入市场完整只读页。

添加 / 对勾：未添加时显示“添加”，已添加时显示对勾；不展示更新入口。



[blockquote]

10.4 市场完整只读页

页面结构与本地完整 Skill 页面一致。

图标、技能名称、描述固定展示；标签、来源、版本、作者等字段存在才展示。

下方展示市场 Skill 完整目录，默认打开 SKILL.md。

所有字段和文件均不可修改。

顶部仅保留 添加 / 对勾，不展示更新、使用、对话修改和本地打开。



[blockquote]

10.5 添加 Skill

用户在市场卡片、简介或只读页点击“添加”。

系统下载完整 Skill 包到临时目录并校验。

校验市场包的 type: market、version、作者和图标；校验通过后原子写入 TPT 管理的本地目录。

创建本地 skill_id，在注册信息中记录 source.id 和 source.installed_version。

Skill 进入“我的技能”，默认启用并可离线使用；市场入口变为对勾。

失败时不得留下可调用的半成品目录；需展示失败原因和重试入口。

10.6 更新判断

市场保证每次内容变化都会产生新的不可变版本；市场服务端以稳定 Skill ID 和版本号标识内容。

本地对象通过 source.id + source.installed_version 与市场最新版本比较。

本地 SKILL.md 中的 version 可被用户修改，只用于展示和包自描述，不能作为已安装市场版本的可信记录。

有更新时，仅在“我的技能”对应卡片展示“有新版本”、版本变化和“更新”。

Skill 市场卡片、简介和市场只读页继续只显示“已添加”对勾，不暴露本地维护状态。

P0 不判断本地文件是否修改；只要市场最新版本高于 source.installed_version，即展示更新状态。

10.7 更新流程

P0 仅支持手动更新：

市场最新版本高于本地 source.installed_version 时，“我的技能”卡片显示“更新”。

用户点击“更新”后弹出确认窗口，展示已安装版本、市场版本和生效范围。

确认窗口必须提示：P0 不检测本地文件是否修改，继续更新会使用市场新版覆盖当前本地 Skill 文件；如需保留内容，应先自行备份。

用户取消时不下载、不写入，卡片继续显示更新状态。

用户确认后，系统将市场新版下载到临时目录并校验；校验通过后原子替换当前本地 Skill 文件，包内图标与其他资源一并更新。

更新成功后写入新的 source.installed_version，保持原启用状态，清除卡片更新提示。

后续新任务立即使用新版；运行中任务继续使用启动时锁定的内容快照。

下载、校验或写入失败时保留当前有效内容和更新按钮，并给出失败原因及重试入口。

P0 不提供自动更新、更新设置、本地修改检测、文件差异、自动合并或版本回退，相关能力统一列入 P1。

10.8 离线行为

已添加 Skill 可离线查看、显式使用和按启用状态自动调用。

已缓存市场目录可展示，但需提示可能不是最新。

未缓存的市场内容、添加和更新不可用。

11. 新建与导入

11.1 顶部入口

顶部提供 导入 Skill 和 新建 Skill 两个独立按钮，不使用创建下拉菜单；两个入口在我的技能和 Skill 市场页签均可见。

11.2 新建 Skill：对话创建（P0）

点击“新建 Skill”直接进入统一对话页面的 Skill 创建模式。

用户描述用途、输入、处理步骤、输出要求和可用资料。

Agent 生成 Skill 包并进行基础结构校验；写入 type: user，生成中英文展示字段，并从预置图标 ID 中选择图标，不调用生图能力。

成功后写入本地目录并加入“我的技能”。

回答展示名称、描述、文件摘要、校验结果和启用状态。

创建结果默认不启用，可在当前对话继续修改或显式启用。

回答不提供进入 Skill 查看页的链接；需要查看时从“我的技能”进入。

生成或校验失败时不写入“我的技能”。P0 不展示草稿、版本或保存状态。

11.3 P0 支持的导入格式

[table]

导入弹窗不要求用户先选择格式。统一拖拽区接收上述文件和目录；受操作系统文件选择器限制时，可在同一弹窗中提供“选择文件”和“选择文件夹”两个入口，但二者进入同一扫描、校验和导入流程。用户可连续追加选择。

P0 不支持 .skill 私有扩展名、.tar / .tar.gz、Git 地址或仓库、仅导入 meta.json，也不递归扫描超过一级的 Skill 集合目录。单次数量、文件数量、总大小和解压后大小由研发安全基线配置上限。

11.4 包结构解析

用户添加文件或目录后，系统先扫描全部输入，在弹窗内形成候选 Skill 清单，不立即写入正式目录。

ZIP 或目录根部存在 SKILL.md 时整体识别为一个 Skill，不继续把其内部目录识别为独立 Skill。

根部不存在 SKILL.md 时，仅扫描一级子目录；每个包含 SKILL.md 的子目录识别为独立 Skill。

结构判断时忽略 __MACOSX 和 .DS_Store，且不将其写入正式目录。

SKILL.md Front Matter 必须包含有效的 name 和 description。

name_cn、name_en、description_cn、description_en、tags、type、version、author、icon 和 suggested_prompts 按存在性读取。

本地导入统一按用户侧 Skill 处理；受管副本中的 type 缺失或非 user 时规范为 user，包内声明不能建立市场关联。

icon 为预置 ID 时校验枚举；为文件路径时只允许 Skill 根目录内的合法 PNG。未声明、资源缺失或校验失败时使用 general，图标问题不阻断导入。

meta.json 不是标准必填文件；存在时按 4.7 节兼容读取并原样保留。

其余脚本、参考资料、图片和未知文件在通过安全校验后原样保留。

技术 name 与本机现有 Skill 或本批次其他候选项重复时，将该候选项标记为“同名冲突”并默认跳过；P0 不自动改名、不覆盖已有 Skill。

双语展示名称允许重复；每个成功导入的 Skill 生成新的 skill_id 和唯一受管目录，不根据名称建立市场关联。

11.5 导入安全校验

导入前至少校验：

ZIP 是否损坏、加密或无法完整解压。

文件路径是否包含绝对路径、父目录穿越或规范化后的重复路径。

是否存在指向 Skill 根目录外部的软链接或其他危险链接。

是否包含 Windows 非法文件名、保留名称或当前系统无法写入的路径。

文件数量、目录深度、压缩包大小和解压后总体积是否超过客户端安全阈值。

YAML、已识别 JSON 文件和必填字段是否可解析。

type 是否为允许值；icon 的预置 ID、相对路径、PNG MIME、尺寸与大小是否有效。图标异常采用非阻塞降级，危险路径仍按安全错误阻断。

具体体积、文件数和目录深度阈值由研发安全基线统一配置，不改变产品流程。校验以候选 Skill 为隔离单位：单项阻塞错误只使该项不可导入，不阻止其他有效候选项；失败项的临时内容必须清理。

11.6 导入结果

扫描清单按“可导入、同名冲突、格式或校验失败”展示每个候选项的名称、来源载体和状态。

用户点击“导入可用项”后，仅处理状态为可导入的候选项；冲突和失败项自动跳过。

每个 Skill 独立复制和原子写入；单项失败不回滚已经成功导入的其他 Skill，也不得留下可调用半成品。

每个成功项创建新的本地 skill_id，将受管副本 type 规范为 user，注册 source.type = user、enabled = false，加入“我的技能”且默认不启用。

版本、作者、标签等可选字段按存在性展示；不因包内同名或同版本字段自动建立市场关联。

完成后在原弹窗展示成功、跳过和失败数量及逐项结果；用户点击“完成”返回“我的技能”。

13. 权限、安全与运行边界

Skill 内容不作为需要保密的资产，市场允许在添加前查看完整内容。

Skill 默认保存和运行在本地；工具调用仍受桌面端统一权限策略约束。

Skill 页面不重复建设文件授权、工业软件写入授权等全局安全能力。

工业软件和现场控制遵循“只读分析、不直接写控制”的总体原则。

Skill 启用不突破当前 Agent 的工具、Skill 和数据可见范围。

任务启动时锁定当次 Skill 内容；修改只影响后续任务。

删除操作必须经过明确确认并使用 Windows 回收站，不直接永久删除本地目录。

Agent 内的 Skill 是复制到 Agent 目录的独立副本，原 Skill 删除不触发引用检查或副本级联删除。
