本文指导开发者在真实受控页面或桌面上实现四类交互：滤镜、AI 光标、操作反馈和浮动控制条。界面应让用户持续看清控制范围、当前操作者和实际执行状态，并随时发起暂停或人工接管。

视觉采用简洁的黑白灰工作区风格，辅以低饱和冷灰蓝。下文的尺寸、时序和事件契约为本次实施基线；业务系统负责提供真实控制范围、执行结果和控制权确认。

02  基础样式与覆盖边界

[table]

 

排版与层级

控制条使用系统无衬线字体；中文优先 PingFang SC、Microsoft YaHei。品牌 14 px 半粗，状态 14 px 中等字重，操作补充 12 px，按钮 14 px。正文行高 1.4；主按钮不因被控画面缩放而缩小。阴影采用 0 8px 28px rgba(0,0,0,.12)。

[table]

 

图层与命中

同一叠加容器内按滤镜 10、目标反馈 20、AI 光标 30、光标标签 40、浮动控制条 100、控制条内提示 110 排列。数值仅在本容器内有效；宿主负责让容器位于受控内容上方。

滤镜、光标、目标框和波纹均不参与指针命中；只有控制条及其按钮接收交互。视觉遮罩不能充当输入锁。执行端必须独立保证控制权，接管确认后才能开放人工输入。控制条及其焦点轮廓必须始终清晰。

03  滤镜的视觉与状态规则

默认使用柔和光晕。滤镜类型由产品配置或宿主策略确定，不向被控端增加调参界面。所有参数均为内部设计变量；滤镜只表达状态，不改变执行速度或操作权限。

[table]

 

[table]

 

目标清晰区与裁剪

目标矩形向四周扩展 20 px 形成清晰区，圆角 12 px；清晰区始终裁剪到受控边界内。小目标的清晰区最小为 160 × 112 px，超出范围时按实际范围裁剪。目标不存在、失效或在范围外时，不将其吸附到边缘制造位置提示。

范围变化与滤镜切换使用不超过 180 ms 的透明度过渡。滚动、缩放和窗口移动时直接更新几何；不能让遮罩滞后盖住真实目标。轻透磨砂不作用于控制条、标签及焦点框。减少动态效果时关闭呼吸与淡入滑动，保留静态范围标记。

04  AI 光标的形态与定位

AI 光标是执行端指针的可视化副本。只有收到具有有效位置的数据才显示；读取页面等无指针操作只更新控制条文案，不虚构一个鼠标位置。光标与系统指针通过标签区分，避免用户误认为是自己的鼠标。

[table]

 

位置同步

坐标以受控范围内的 CSS 逻辑像素为统一单位。宿主先完成物理像素、窗口偏移和缩放换算，再传入组件。点击、按下、抬起事件抵达时立即对齐事件坐标；点击波纹中心与光标热点的偏差不得超过 2 px。连续移动数据每帧只消费最新位置。

边界和标签避让

标签依次尝试右下、左下、右上、左上四个位置，与范围边缘至少间隔 8 px，并避开控制条和当前目标。四处均容纳不下时隐藏标签，保留指针。指针出界、geometryVersion 不匹配或位置过期时隐藏；禁止钳制到边缘后继续声称该处正在操作。

状态失效

人工接管、会话结束或连接状态未知时立刻停止移动动画并清除指针。目标已失效但指针数据仍有效时，可保留指针并移除目标框。系统开启减少动态效果时直接定位，不进行光标滑行。

05  操作反馈的触发与生命周期

反馈由实际执行事件触发。操作已发出、动作已落地和业务结果成功是三个不同事实：指针按下反馈只代表按下发生；成功标记必须等待执行端确认该动作的结果。actionId 关联同一操作的多个阶段，事件按会话、控制权版本与序号去重。

[table]

 

去重和优先级

视觉优先级为控制权未知或异常、控制权交接、已暂停、动作失败、当前操作、短暂成功。同一事件不得重播；同一 actionId 下的移动、按下、抬起和结果仍需分别处理。不同动作在同一帧完成时，控制条展示最新有效操作，失败提示按优先级保留。短时节点总数不超过 6 个，超出时淘汰最早的普通效果。

超过 800 ms 无新的动作阶段时允许显示“正在处理”；超过 10 秒仍无结束事件则显示“耗时较长”，并保留接管入口。计时只控制提示，不判定成功或失败。输入反馈不得包含密码、验证码、剪贴板正文等内容。

06  浮动控制条的结构与布局

浮动控制条是被控端唯一常驻的控制入口，包含品牌、控制状态、当前操作、次操作和主操作。它独立于滤镜渲染，不提供配置面板或任务导航。按钮应与权威控制状态一致。

[table]

 

遮挡避让

当前目标与控制条矩形加 12 px 安全区相交时，在顶部居中与底部居中两个候选位置中选择不相交的一处；连续两次几何更新均相交才切换，避免抖动。若两处均冲突，宿主必须预留控制条区域或滚动目标。当前动作应等待可见目标，不允许点击被控制条遮挡的位置。

自动避让不抢夺键盘焦点。指针按在控制条上或控制条持有焦点期间不移动；必要时请求暂停动作以解决遮挡。位置切换过渡 120 ms，减少动态效果时直接定位。控制条不会因任务运行而自动隐藏。

07  浮动控制条的状态与操作

[table]

 

动作结果与会话状态分离

“操作失败”是一条操作结果，可以与 active 或 paused 并存，不能直接推断输入控制权。若执行端暂停后续动作，应另发 paused 状态。会话 ended 仅在执行器已停止、按键和鼠标均释放、人工输入已开放后成立。成功、失败或取消结束使用相应文案，不统一显示成功。

按钮响应

点击后 100 ms 内显示处理中文案；同类命令去重，takingOver 优先于 pausing。点击继续时保留 paused 外观，显示“正在继续”并禁用继续按钮；接管仍可升级请求。returning 保持人工控制时的无 AI 光标和滤镜外观，直到 active 确认。确认前不提前宣称控制权已改变；按钮槽位保持稳定。

关闭与重新显示

仅 manual 和 ended 允许关闭。关闭只移除本地显示，不触发交还、结束或再次执行。manual 下若再次需要交还 AI，由宿主常驻入口重新打开同一控制条；首次关闭前宿主必须已提供该入口。active、paused 和所有等待态禁止隐藏控制条。

键盘交互

Tab 依次访问次操作、主操作及可用的关闭按钮；Enter 或 Space 激活。焦点采用 2 px 深灰外框、2 px 间隔。宿主可注册 Esc 为接管快捷键，但必须确认不会被页面或系统冲突占用；未注册成功时不显示该快捷键提示，屏幕上的接管按钮始终保留。

08  暂停与控制权交接规则

控制条发送用户意图，执行端确认实际控制权。四个视觉模块随同一确认快照更新。只停止前端动画不等于停止真实输入，因此暂停和接管必须走明确的确认流程。

暂停与继续

暂停请求立即关闭本地新动作派发入口并进入 pausing。执行端停止队列，等待或安全终止已派发动作，释放按下状态后确认 paused。确认前只冻结反馈，不宣称输入已归用户。继续需要重新验证目标与控制范围，收到 active 确认后才允许派发新动作。

人工接管

立即接管进入 takingOver，冻结本地反馈并停止派发。执行端撤销旧控制租约、终止后续队列、完成仍在执行的输入清理，再切换为人工输入。收到包含新控制权版本的 manual 快照后，隐藏 AI 光标和滤镜，控制条显示“你正在控制”。已经完成的点击或输入不因接管而撤销。

交还 AI

manual 下点击“交还 AI”进入 returning。执行端重新读取页面或桌面状态，检查目标仍有效，再获得 AI 控制租约；不得盲目延续旧坐标或重放已完成动作。确认 active 后显示新的滤镜与位置。交还失败且明确保留人工控制时回到 manual；控制权不明时进入 unknown。

09  统一事件与数据契约

ownerEpoch 随权威交接递增，seq 在会话内递增。保留 lastAuthoritativeSnapshot、本地 pendingCommand 和连接状态，统一派生 ViewState；超时不能改写权威快照。全量快照中 pointer 或 target 省略即清除。

type ConfirmedState = "active" | "paused" | "manual" | "ended";

type ViewState = ConfirmedState | "pausing" | "takingOver"

  | "returning" | "unknown";

type Point = { x: number; y: number };

type Rect = Point & { width: number; height: number };

type Snapshot = {

  sessionId: string; ownerEpoch: number; seq: number;

  state: ConfirmedState; geometryVersion: number;

  scope: Rect; pointer?: Point; target?: Rect;

  cursor: "arrow" | "text" | "grab";

  actionId?: string; actionText?: string;

  endReason?: "success" | "failed" | "cancelled";

};

type ActionEvent = {

  sessionId: string; ownerEpoch: number; seq: number;

  geometryVersion: number; actionId: string; occurredAtMs: number;

  kind: "move" | "down" | "up" | "scroll"

    | "input" | "target" | "result";

  point?: Point; target?: Rect | null;

  cursor?: "arrow" | "text" | "grab"; delta?: Point;

  phase?: "started" | "succeeded" | "failed" | "cancelled";

  button?: "left" | "right"; message?: string;

};

type Command = {

  commandId: string; sessionId: string;

  expectedOwnerEpoch: number;

  intent: "pause" | "resume" | "takeover" | "return";

};

type CommandAck = {

  commandId: string; sessionId: string;

  status: "accepted" | "rejected";

  snapshot: Snapshot; reason?: string;

};

 

校验与拒绝规则

宿主将快照、动作和结果合并为有序可靠流；高频移动先合并再编序。组件按会话、控制权版本与 seq 去重。旧几何只使坐标无效，结果仍进控制条。待确认时不绘制新动作。occurredAtMs 为单调毫秒；delta 为 CSS px 滚动位移；cursor 为真实输入形态；target 为 null 表示清除。

确认须匹配当前 commandId 与 sessionId，快照 seq 不倒退；允许 ownerEpoch 更新。accepted 是完成后的确认：pause 对应 paused，takeover 对应 manual，resume/return 对应 active，不是收到请求的回执。rejected 也须携带当前快照，否则保持 unknown。message 仅传审定短文案。

10  组件连接与几何换算

[table]

 

坐标约定

所有目标与指针进入组件时均以 scope 左上角为原点，单位为 CSS 逻辑像素；scope 自身使用宿主叠加视口坐标。若宿主提供屏幕物理坐标，先减去当前屏幕范围原点，再除以该屏幕的物理像素比。不同屏幕不能共用一个缩放系数。

// Physical screen coordinates -> scope-local CSS pixels

localX = (physicalX - scopePhysicalLeft) / pixelRatio;

localY = (physicalY - scopePhysicalTop) / pixelRatio;

// Scope-local position -> overlay viewport position

overlayX = scope.x + localX;

overlayY = scope.y + localY;

// For content scaled inside a host viewport

overlayX = contentLeft + localX * scaleX;

overlayY = contentTop  + localY * scaleY;

 

最后一组换算仅用于宿主实际缩放内容时，替代上一组，不能重复应用缩放。像素比与内容缩放是不同概念。留白偏移必须计入 contentLeft、contentTop。矩形四边与光标热点使用同一变换。

几何更新与销毁

宿主在滚动、缩放、页面导航、窗口尺寸改变或显示器切换时递增 geometryVersion，更新 scope。旧几何数据立即隐藏；收到匹配版本的位置和目标后重新绘制。旧目标不能在新布局中沿用。

会话切换、组件卸载或输入交接时取消插值、过期计时器和短时反馈，解除订阅。组件卸载前若 AI 尚有控制权，宿主先执行停止与输入释放；不可仅移除控制条后留下后台 AI 输入。

11  异常表现与质量要求

异常降级

[table]

 

失联停止

执行端独立维护 AI 控制租约，默认每秒续期；超过 3 秒未续期时停止派发，释放按键与鼠标并开放人工输入。界面收到新快照后才宣布人工控制。已暂停时仍需续期；人工控制时不续期。

可访问性

状态同时通过文字与图标表达。普通文字对比度目标至少 4.5:1，按钮边界和焦点目标至少 3:1。控制条提供可读的区域名称“tpt-work 控制”；每个按钮有明确可访问名称，禁用时保留语义。

状态区域只在控制者、暂停结果或失败原因变化时播报。普通状态使用礼貌播报；控制权未知使用一次明确提示。连续光标移动、滚动和点击波纹不逐个朗读。减少动态效果时关闭呼吸、扩散与插值，以静态目标框和文字替代。

渲染与资源预算

目标是在 60 Hz 设备上保持流畅；光标和反馈更新在单个动画帧集中提交，叠加层脚本开销目标不超过每帧 4 ms。指针移动不触发布局测量；几何变化时统一测量与缓存。滤镜重绘限制在受控区域，减少大范围模糊。

操作提示保留最多 6 个短时视觉节点。离开当前会话后动画与计时器必须为零。前后台切换不自动续作；恢复可见后先同步权威状态。以上为待验收的性能目标，需在目标设备与最终宿主中测量。
