## 一、规格 §12 已知问题（9 条）

### D-01 ｜ P0 ｜ 自动沉淀的"智能提炼"环节未真正生效

**需求文档描述**（§12 P0-1）：自动沉淀目前只把内容落进流水层，不产出结构化长期记忆；产品承诺的"越用越懂你"缺少了最关键的一环——长期层几乎只能靠反思升格和手动添加填充。

**复现步骤**
1. 新建任务，发送一条含长期偏好 + 硬性规则的指令（约 150 字，超过 240 字量闸之上，需确保超量）：
   > 我习惯先看结论再看推导过程，回答里不希望出现表情符号和大段客套话。另外项目规范：以后所有提交代码之前必须先跑通完整测试套件，不允许跳过失败的测试。这两条长期有效，请务必记住。
2. 等待本轮结束。
3. 查 `MEMORY.md` / `USER.md` / `2026-09-29.md` 的字节变化与 `audit.jsonl`。

**实际结果**
- 长期层**确实长出了内容**：`MEMORY.md` 60→200 B、`USER.md` 63→172 B，格式为结构化条目（`[R]` 类型标记 + 日期）。
- 但 `audit.jsonl` 显示写入方为 `actor: "tool"`（智能体主动调工具），**自动管道本身只产出 `日志追加`（流水层）**。
- `reflections/` 仍为 0 项，`index.json.entries` 仍为 0。

**证据**
- `audit.jsonl` 末两条：`{"actor":"tool","type":"memory_write","target":"…\\MEMORY.md","summary":"写入长期记忆 1 条 [R] importance=5","detail":{"count":1,"type":"R","importance":5}}`
- `MEMORY.md` 字节 60→200；`USER.md` 63→172；`2026-09-29.md` 4496→4977
- `audit.jsonl` 另两条同期记录均为 `actor:"host"`（面板删除、外部改写感知），**无任何一条由自动沉淀产生长期记忆写入**（完整流水见 `evidence/observed/audit.jsonl`）

> 备注：规格表述"长期层几乎只能靠反思升格和手动添加填充"与实测有出入——实际还存在第三条路径：**智能体自己调工具写**。真正的缺口是"自动"那一段接线。

### D-02 ｜ P0 ｜ 反思永远返回"无需升格"，反思状态不刷新

**需求文档描述**（§12 P0-2）：点击反思后永远显示"无需升格"，即使日志里明明有重复内容；反思退化为纯规则匹配，"重要路径"完全失效。

**复现步骤**
1. 正常使用若干轮对话（本次累计 17 轮反思）。
2. 打开 设置 → 记忆与进化 → 概览 → 近期动态。
3. 另将同一句话分别写入 `2026-09-28.md` 与 `2026-09-29.md`（构造跨天重复），再开新会话。
4. 观察 `index.json.entries`、`MEMORY.md`、`.reflection-state.json`。

**实际结果**

- 跨天重复内容**被新会话正确注入**（模型确认看到了那句偏好），但**未触发升格**。
- `.reflection-state.json` 的 `lastAt` 停在 `1790644216391`（≈09:10），此后多轮对话**未刷新**。
- `reflections/` 恒为 0 项。

**证据**

### D-03 ｜ P1 ｜ "重要度 ≥4 直接升格"通路不可达（部分推翻）

**需求文档描述**（§12 P1-3）：明确标记为关键的内容，事后没有进入长期记忆；缺少"关键约束自动升级"的快速通道。

**复现步骤**
1. 按 D-01 步骤让智能体写入一条硬性规则。
2. 开新会话，让模型逐字转储注入的预置内容。
3. 查看注入段落结构与 `audit.jsonl` 的 `detail.importance`。

**实际结果**
- **可写入**：条目带 `importance=5`，且**注入时被单独强调**——注入快照多出第 5 段 `[硬性规则 — 必须遵守]`，该条目在 `[长期记忆 MEMORY.md — 必须遵守]` 段内同时出现一次（重复注入）。
- 因此：**若"重要路径"指工具写入 → 可达，规格描述需修正**；**若指反思驱动的升格 → 仍不可达**（见 D-02）。

**证据**
- `audit.jsonl`：`"detail":{"count":1,"type":"R","importance":5}`
- 模型逐字转储的注入全文（5 段，含 `[硬性规则 — 必须遵守]`）——全文见 `evidence/observed/injection-dump.txt`

### D-05 ｜ P2 ｜ 记忆条目计数与索引口径三处不一致

**需求文档描述**（§12 P2-5）：跨文件搬运同一条记忆时的识别口径有偏差，可能出现重复计数或漏计。

**复现步骤**
1. 记忆库 → 输入框添加一条「用户偏好：代码注释一律使用中文。」→ 确认。
2. 对比 `index.json` 与卡片显示。
3. 再由智能体工具写入一条长期记忆，对比 `index.json` 是否变化。
4. 在"添加"时观察自动判定的类型。

**实际结果**
- 面板手动添加 → `index.json.entries` **增加 1 条**（含 `id/type/file/line/keywords`）。

- 类型自动判定偏差：内容为「用户偏好：…」却被判为 **F(事实)**，而非 P(偏好)。

**证据**
- `index.json` 添加前后对比：`entries: []` → 1 条 → 删除后回 `[]`
- 截图 `143-A2-added.png`（列表行显示 `F | 用户偏好：代码注释一律使用中文。 | 2026-09-29`）

### D-06 ｜ P2 ｜ SOUL.md / AGENTS.md 写入后不进入注入快照

**需求文档描述**（§12 P2-7）：智能体读取工具不支持读 SOUL.md / AGENTS.md，智能体无法直接读取协作风格与工作手册，影响语气与规范对齐。
（另见 §4.1：人格层"作为快照的一部分"）

**复现步骤**
1. 向 `SOUL.md` 写入 `【风格标记-ST5E18】` + 风格要求；向 `AGENTS.md` 写入 `【手册标记-ATEB50】` + 流程要求。
2. 新建任务，发送统一探针（要求原样列出收到的预置内容），不暴露标记。
3. **重启应用**后重复第 2 步。
4. 查设置页卡片字符数；全盘检索标记。

**实际结果**
- 设置页卡片**实时显示** `SOUL.md 38 字符`、`AGENTS.md 54 字符` → 应用读得到。
- 但**注入快照中无对应段落**，模型一律回答"协作风格：无""工作手册：无"，标记零出现。
- **重启后复测仍无效** → 排除启动缓存因素。
- 注入 schema 实测 section 名为 `memory:logs` / `memory:user-memory` / `memory:user`，**无 soul/agents**。

**证据**
- 会话文件中注入快照的机器级结构（`next-step[].content[].source`）：

- 对照实验矩阵（各轮只改一个文件，探针逐字相同）：

  | R1 | `SOUL.md` | 98 B / 38 字符 | ❌ 不注入 |
  | R1b | 同 R1，重启后重测 | — | ❌ 仍不注入（排除缓存） |
  | R2 | `AGENTS.md` | 128 B / 54 字符 | ❌ 不注入 |
  | R3 | `USER.md` | 63 B | ✅ 注入（同一探针下答出"铁蛋/炼铁工艺员"） |
  | R4 | `MEMORY.md` | 59 B | ✅ 注入（答出"炉顶改造/ZQ-9911"） |
- 截图：`evidence/shots/126-memory-cards-state.png`（卡片实时显示 `SOUL.md 38 字符`、`AGENTS.md 54 字符`）

### D-13 ｜ P2 ｜ 注入快照的段落顺序与规格不符

**需求文档描述**（§6.1）：注入内容结构按顺序为 1. 用户画像摘要 → 2. 最近反思 → 3. 长期记忆摘要 → 4. 最近 N 天工作日志摘要；截断优先级为 用户画像 > 长期记忆(critical) > 最近反思 > 工作日志。

**复现步骤**
1. 新建任务，要求模型**逐字转录**收到的记忆预置内容。
2. 对照规格顺序。

**实际结果**
- 实测顺序为：`[记忆定位]` → `[最近工作日志(尾部)]` → `[长期记忆 MEMORY.md]` → `[用户画像 USER.md]` →（条件性）`[硬性规则]`。
- 与规格声明的顺序**不同**（工作日志在最前，用户画像在最后）。
- "最近反思"段不存在（见 D-04），故优先级链无法完整验证。
- 🟡 段数为**条件性**：无内容则不渲染（`reflections` 缺失时无该段；无 critical 条目时无 `[硬性规则]` 段）。

**证据**
- 模型逐字转储的注入全文（逐段可核对），见 `evidence/observed/injection-dump.txt`
