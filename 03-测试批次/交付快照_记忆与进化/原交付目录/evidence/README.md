## ⚠️ 数据来源声明（务必先读）

**本目录中所有记忆内容均为测试数据，不含任何真实用户数据。**

测试分两个阶段，两类数据的性质完全不同：

| 目录 | 谁写的 | 里面是什么 | 能用来证明什么 |
| --- | --- | --- | --- |
| `fixtures/` | **测试者人工/脚本直接改磁盘** | 人格层文件与伪造的"昨天"日志 | 只能当**测试输入**，不是产品输出 |
| `observed/` | **产品自己写出** | 审计流水、记忆文件、索引、注入转储 | 产品的**真实行为**（格式、来源、是否注入/升格） |
| `shots/` | 截图 | 界面状态 | 界面事实 |

**关键区分**：`observed/` 里 `MEMORY.md` / `USER.md` 的**内容文本是测试者编的**（"铁蛋"、"炼铁工艺员"、"炉顶改造"、"ZQ-9911"、"沟通偏好"、"硬性规则"），但**"产品把内容写进去了、写成这种格式、写进去之后有没有进注入、有没有升格"是产品的真实行为**。

**所有缺陷结论都建立在行为上，不依赖这些文本的真假。** 例如：

- D-06（SOUL/AGENTS 不注入）：判定依据是"**换成任何内容都不注入**"，与写了什么无关
- D-02（反思不升格）：判定依据是"**17 轮真实对话的反思全为『无需升格』**"，与夹具无关
- D-15（重复日期标题）：判定依据是"**两次真实写入产生了两个同名日期标题**"，是结构问题

## 从 `injection-dump.txt` 可直接核对的三件事

1. **实际 5 段结构**：`[记忆定位]` → `[最近工作日志(尾部)]` → `[长期记忆 MEMORY.md — 必须遵守]` → `[用户画像 USER.md]` → `[硬性规则 — 必须遵守]`
   - 规格 §6.1 声明顺序为「用户画像 → 最近反思 → 长期记忆 → 工作日志」→ **D-13**
   - **无"最近反思"段** → **D-04**
   - **无 SOUL.md / AGENTS.md 段** → **D-06**
2. **critical 条目重复出现两次**（`[长期记忆]` 段内 + `[硬性规则]` 段）→ **D-17**
3. **日志段首行残缺**：`!-- tpt-session:... -->` 缺开头 `<` → **D-16**
