# 记忆与进化：设计、观察与修正

## 预期能力

设计原文划分人格（SOUL/AGENTS，手动）、用户长期记忆（USER/MEMORY，可自动生成并编辑）、每日工作日志与反思；涉及提取、晋升、蒸馏、召回和敏感过滤。设计第 11 节明确移除了项目隔离方案，不能把早期设计概念当成最终要求。设计自身也列有已知问题。

## 哪些事实可以合并，哪些必须保留时间范围

| 主题 | 合并后的阅读结论 | 范围 / 不应推导 |
|---|---|---|
| 记忆落盘 | 指示记住后 USER/MEMORY 增长，审计有 actor=tool | 证明工具写入；不足以证明自动沉淀链路完成 |
| 注入块 | 早期先观察 3 块，后在有 critical 规则时观察 5 块 | 原 05 文档 G3 修正；不是固定只有三段 |
| 召回 | 原 05 文档 G4 实测从 MEMORY.md:4 返回内容 | 空 index.json 不能推出召回失效；召回扫描文件 |
| 面板 / 索引 | UI 添加与工具写入的索引表现不同；换包后面板计数与文件自洽，但索引仍空 | 不要把早期计数异常笼统延续到后续包 |
| 反思目录 | 早期“目录不存在”后来修正为存在但空 | 原先仅列文件造成误判；不能继续复用不存在的结论 |
| 反思进度 | 换包回归 lastAt 已推进，仍无反思文件/晋升观察 | 原报告仍判定核心链路未修复；时间戳推进和内容产出分开 |
| 人格文件 | 后续批次 SOUL/AGENTS 是 0 字节 | 不能用空文件复核“有内容却未注入”；早期内容测试独立保留 |
| 删除 | 早期原生确认阻塞，人工处理后添加/删除可走通；换包回归未再测删除 | 自动化阻塞与产品能力分开，未测不能算修复或仍失败 |
| 类型 | 默认 F 与 P/F 分类有疑点 | 可能是表单默认选择；语义分类错误没有充分确认 |

## 可以向团队展示什么

可以展示带来源的典型链路：人工构造记忆输入 → 工具写入文件 → 后续注入/召回观察。这能支持该历史场景的行为说明，不能宣称整套自动记忆与进化已经闭环。原回归报告中的反思/晋升和重要性等问题应和已通过的落盘/召回分开呈现。

交付包中的领域文本和个人信息是测试夹具；部分日志由测试者构造，注入 dump 为模型复述。读原始证据时先看 [证据说明](../%E4%BA%A4%E4%BB%98%E5%BF%AB%E7%85%A7_%E8%AE%B0%E5%BF%86%E4%B8%8E%E8%BF%9B%E5%8C%96/%E5%8E%9F%E4%BA%A4%E4%BB%98%E7%9B%AE%E5%BD%95/evidence/README.md)，再判断它证明的是输入、产物还是过程。
