# 沙箱与权限：两层设置和验证边界

本专题对应 2026-09-30、app.asar 253,660,790 字节（mtime 2026-09-29 21:50:02）、exe 文件版本 0.1.3.0。方法包括真实 UI、受限子进程和磁盘/ACL 检查，没有在整理时再次执行。

## 先分清两组档位

| 层 | 档位 | 资料中的含义 |
|---|---|---|
| 用户权限选择 | 仅可查看 / 工作区内修改 / 完全权限 / Auto review | 对应 read-only / workspace-write / danger-full-access / auto |
| 沙箱实现 | acl / elevated | 当前 ACL 路径与独立低权限本地用户路径；后者涉及安装及管理员授权 |

原报告在设置中未找到实现档位切换/安装入口，包内却有相关代码与说明。代码存在只支持“实现资料存在”，不能说明用户能正常进入 elevated 路径。

## 已验证的行为与暴露的问题

| 方面 | 历史观察 | 对质量说明的含义 |
|---|---|---|
| 基本写边界 | 只读拒绝内外写；工作区内修改在可用夹具中允许内部写、拒绝外部写；切回后即时生效 | 有具体正反例支持，仍限定在这些路径与调用 |
| 内置写工具 | 受约束，不仅命令行受约束 | 区分文件工具与受限进程两个入口 |
| 普通目录可用性 | p1/p2 两个目录 grantWrite 报 Win32 5；任务目录对照可运行 | 实际权限/ACL 是条件，不能推为所有 D/E 盘失败或所有 C 盘成功 |
| 诊断链路 | 产品运行环境找不到 icacls，诊断中止；所有者提示与实测矛盾 | 诊断失败和沙箱拒绝分开，不能宣称修复途径已走通 |
| Auto review | 提示明确不使用沙箱；安装目录写入测试获放行 | 该次审查未拦住对应写入，不能推导所有请求都无审查 |
| .git 与硬链接 | .git/HEAD 可改；夹具硬链接外部文件受影响 | 即使普通越界被拦，也不能宣称全面隔离无漏洞 |
| 常驻 ACL 与已有文件 | 有残留标记及非继承 DACL 文件写入问题 | 需要阅读具体 ACL/路径证据，不能只看 UI 成功提示 |
| 读取、网络、进程枚举 | ACL 路径不限制，文案有说明 | 不是本轮记录中的违规；写隔离不等于信息读取隔离 |

## 原文中需要收窄的结论

用户体感原文用盘符总结目录可用性，并称“没找到能硬闯的漏洞”。本整理保留原文，但不将这些措辞作为全局结论：资料直接支持的是两个测试目录的 ACL 前置条件与对照结果，同时原文记载硬链接、.git 和常驻 ACL 问题。更准确的说明是“基本写边界在指定夹具上通过，仍有可用性与边界问题”。

缺陷总表有 12 个编号，其中 S-08 被原表列为非缺陷，S-09 为观察、S-10 为观察状态。不能把 12 个编号统一计为 12 个已确认缺陷。定级与判定沿用原报告来源，并非整理时重新评审。
