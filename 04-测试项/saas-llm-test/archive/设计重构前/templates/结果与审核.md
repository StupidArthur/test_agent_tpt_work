# 结果与审核模板

## 单个实例

```text
实例 ID：测试项/目标/模型/档位/场景/样本或窗口
归属测试项：可多项，但逐项断言
attempt：第几次；原 attempt 路径（补测时）
前置：是否满足；缺什么
动作：请求路径、协议、方法、实参证据引用
观测：HTTP 状态、错误、正文/工具/usage、时间点和终态
断言：名称 | 预期 | 实际值 | 满足/不满足/未观测 | 证据路径
状态：通过 / 失败 / 不确定 / 未验证
失败归因：协议/内容/服务额度/网络/执行器候选；证据不足就写未知
指标：sample n、统计口径、SLO 分项（若适用）
证据：相对路径、SHA-256、归属实例
恢复/残留：已做动作及实际回读；未做项与原因
```

缺失值写 null，并给原因；“不确定”不能改写成观测到产品失败。预期取自执行前冻结的用例/服务约定；任何改动给版本和理由。

## 报告结构

1. **范围与环境**：目标、协议、包/代码版本、模型/思考档、能力声明、凭据模式、网络、配额、测试窗口。
2. **完整性**：36 项的本轮适用范围、展开实例数、实际尝试数、通过/失败/不确定/未验证；单列请求 attempts 和用户轮次；共享证据如何归属。
3. **通用 API 与 TPT 契约**：逐项结论，必需能力是否全部验证；软件 UI/端到端未纳入。
4. **性能**：原始样本、n、均值/p50/p95、失败分布、计量完整率；测量完成与 SLO 达标分开。
5. **容量**：负载与 SLO、逐档用户/在途/请求/轮次/时间、持续复核、开放到达、客户端瓶颈、已测范围与未知最大值。
6. **差异**：独立编号、实际/预期、影响、证据、复核状态；候选问题待双方审核。
7. **未验证与补测**：缺条件、影响哪些结论、具体补测前置。不要用“阻塞很多”代替编号清单。
8. **恢复与交付**：负载进程/在途已停止证据、残留、文件索引/哈希校验结果、执行器离线验证记录。

## 审核自查

- [ ] 当前任务队列全部有状态，条件子项没有被总状态掩盖。
- [ ] 每个通过的必需断言有实际值和证据。
- [ ] 证据存在且 SHA-256 一致；无 key/Authorization 原值。
- [ ] 每个失败 attempt 进入计数，没有被重试覆盖。
- [ ] usage 缺失没有写 0，chunks/s 没有改称 tok/s。
- [ ] SSE 拼接与终态分别核对，增量问题没有被最终值覆盖。
- [ ] 用户数、请求数、轮次数分开；工具第二轮失败计整轮失败。
- [ ] 容量有冻结 SLO/负载、窗口和客户端资源依据。
- [ ] 本地模拟验证与真实网关结果分开，未声称软件端到端通过。
- [ ] 原始差异保留，候选问题未自动写入产品知识。
