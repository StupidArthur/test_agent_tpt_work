# 04 执行器与交付约定

这是后续 Agent 的实现要求，不是已实现的工具说明。本轮不提供新版执行代码。

## 最小代码层次

保持轻量，标准库或团队已可用依赖即可，不建设额外服务平台。

| 层 | 职责 |
|---|---|
| HTTP / SSE | 鉴权、路径、连接、超时、取消、帧解析、原始证据、时间点 |
| 协议与场景 | Chat/Responses 请求和事件归一化，文本、历史、工具、图片往返 |
| 调度与报告 | 实例展开、性能采样、用户闭环/到达调度、统计、SLO、台账与报告 |

用例只声明场景、参数与断言，复用以上函数。原始观测、断言与统计分离，方便复核解析错误。函数必须保留源码和调用记录，不能只有一次性终端代码。

## 行为要求

- 可列用例、按模块/编号/目标执行；明确显示参数展开后的实例数和预计请求数。容量另列档位和最短/最长时间估算。
- 按模板取配置，key 用环境变量。支持配置真实路径，不假定 URL 一定带 `/v1`。
- 记录每个 attempt，包括失败；默认不自动重试。连接、读空闲、整个请求、整个阶段的期限分别明确。取消后关闭客户端资源，但不凭关闭连接宣称服务器计算/计费已停止。
- SSE 解析能承受真实网络分片；错误 JSON 不静默忽略，事件终态与内容增量一致性独立验证。
- usage 缺失为 null；保留来源字段。不把 chunk 当 token，不以字符估算 token 后混入服务计量。
- 按实例持续写结果；中断可恢复未完成队列。每次补测保留原 attempt，不覆盖历史结果；同一输出目录不能静默覆盖。
- 性能暖机单列，正式样本数量固定或按明确窗口；容量正式起点一致、单用户顺序执行、排队/排空口径明确。
- 证据仅移除凭据，保留完整请求参数、正文/工具参数和关键事件。密钥不进入 URL、异常信息、配置快照和报告。
- 报告生成与校验离线进行，不为出报告再发请求。校验器只证明记录完整，不代替业务断言审核。

## 编码后必须先做的离线验证

用本地可控 HTTP/SSE 服务验证这些观测风险，明确它们是执行器验证而非网关结果：

1. role/空事件先到、推理先到、正文后到：三个时间点确实不同。
2. CRLF、多行 data、注释、中文跨网络分片、多个帧共用一块：解析不丢字/串帧。
3. 工具参数分片、多个 call/item、最终参数不一致：对应 ID 正确，能发现矛盾。
4. HTTP 200 的流内错误、无终态 EOF、非法 JSON、HTTP 401/429/5xx、慢读超时：失败记入总数。
5. usage 缺失/非法：指标为缺失，样本不从错误率消失。
6. 一批部分成功、部分失败：attempted、成功率、状态分布与证据条数一致。
7. 用户串行/工具多请求/思考间隔、开放到达调度：轮次与请求数量不混淆，排队等待可见。
8. 小样本/最高档通过/非单调/客户端受限：报告不会生成未经支持的“最大用户数”。

## 每轮交付目录

在本次探索性测试任务下创建：

```text
README.md                  本轮目标、队列和恢复指令
环境与负载.md / 配置快照.json  无密钥；版本、协议、SLO、模型与限制
code/                      本轮实现源码及依赖说明
结果/                      每个实例的状态与逐项断言
证据/                      请求、响应/SSE、usage 与采样记录
证据索引.jsonl             归属实例、相对路径、SHA-256
运行日志/                  调度/调用/进度、终止与恢复
报告.md                    范围、统计、差异、性能、用户容量、未验证项
```

模板见 [结果与审核](../templates/结果与审核.md)。请求证据可以被多个测试项引用，不复制正文；索引需列全部归属。报告明确：测试项数、展开实例数、请求 attempts、用户轮次数、条件未验证数，这些不能合成一个“case 全通过”数。

## 交付审核

**记录审核**：队列编号无缺失；每个通过项有实际断言值；证据哈希和引用有效；参数与版本可还原；恢复与残留明确。

**业务审核**：抽查原始请求/帧与断言；判断问题来自协议、模型、配置/额度还是观测工具；不能把 null 当失败产品事实。差异保留待双方审核。

**容量审核**：确认负载、凭据模式、SLO 固定；包含失败与排队；客户端没有瓶颈；有持续复核；报告范围不超过已测范围。
