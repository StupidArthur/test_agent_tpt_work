# 核心指标定义

统一单调时钟、秒、固定正式窗口；暖机分开。未知值为 null，不补 0。每张表注明模型/协议/负载、样本数、窗口和统计对象。不同配置不混算。

## 成功、失败与质量

成功必须分层，禁止用模型指令遵循问题直接降低“网关服务容量”。

|层级|定义|主用途|
|---|---|---|
|Protocol Success Rate|HTTP/传输正常、协议可解析、终态合法；不要求业务内容正确|协议兼容与故障诊断|
|Gateway Service Success Rate|协议成功，且文本场景取得非空有效正文、工具场景取得合法 tool name/ID/可解析参数；空正文、异常截断、传输/协议失败均不成功。仅“措辞未严格匹配 marker、OK 带句号、模型未完全遵循内容指令”等不自动算网关失败|网关服务容量、普通请求可用性|
|Agent Task Success Rate|完整 Agent 任务的所有必需请求、工具往返和最终业务断言均通过|TPT Work Agent 用户体验容量|
|Model/Task Quality|模型是否遵循指定格式、是否主动调用要求工具、答案业务质量等|质量解释与诊断；除 Agent task 明确把它作为成功条件外，不用于网关服务容量|

模型不调用指定工具是 Agent Task Success 失败，但不自动判 Protocol/Gateway Service 失败。短文本 marker 的严格字符匹配可以保留为质量探针；若返回了正常非空答案但只是格式/措辞不完全一致，应进入 Model/Task Quality，而不是把网关容量从高并发档直接压低。

## 核心指标

|指标|计算口径|
|---|---|
|Protocol Success Rate|协议成功数 / 全部正式请求尝试数|
|Gateway Service Success Rate|网关服务成功数 / 全部正式请求尝试数；普通请求容量的成功率使用本口径|
|Agent Task Success Rate|完整 Agent 成功任务数 / 全部正式任务尝试数；Agent 容量使用本口径|
|TTFT|请求发起至本场景第一个真正有效内容。预先选择 first text、first reasoning 或 first tool；推理只有在确实作为该场景有效反馈时可选。不得用 HTTP 首字节、首 SSE、role、heartbeat、空 delta 替代|
|E2E Latency|请求从发起至完整完成或失败；Agent task 从任务发起至完整成功或失败，含全部请求与工具等待。开放到达还包含计划到达至实际发起的排队等待|
|Output tokens/s|优先表示首个有效输出之后的服务输出速率：实际 output tokens / (completion_time - first_valid_output_time)。只在分母有效且服务 token 计量语义明确时计算；若 output_tokens 含 reasoning，必须标为“服务输出 tokens/s”，不得解释成可见正文打字速度或纯模型解码速度|
|E2E effective output tokens/s|实际 output tokens / 请求 E2E 秒。仅作为端到端效率辅助指标，包含输入处理、排队、网络、推理和 TTFT，不与上项混用|
|Completed output tokens/s|正式窗口内有效完成请求的实际 output token 总和 / 正式窗口墙钟秒；这是系统级 token 吞吐，不是单请求生成速度|
|Requests/s|正式窗口完成的请求尝试数 / 窗口秒；失败也计完成尝试，另给成功 Requests/s|
|Agent turns/s|正式窗口完成的完整 Agent turn 尝试数 / 窗口秒；另给成功 turns/s。一个 turn 可以包含多个 LLM 请求|
|Error Rate / Distribution|失败尝试 / 全部尝试；按 HTTP、传输、超时、协议、空/无效内容、Agent任务质量分类。主类别互斥，附加标签可重叠|

正文禁止只写“TPS”。必须明确是 Output tokens/s、Completed output tokens/s、Requests/s 或 Agent turns/s。

没有首个有效输出时间或服务 token 计量时，Output tokens/s 写 null 并说明原因，不使用 chunks/s、字符数或输出预算伪造。usage 缺失样本不参加 token 速率计算；失败样本不能从成功率分母中移除。

输出计量必须注明服务字段以及是否包含 reasoning。含推理的 output tokens 不等同于可见正文 token。需要评价用户看到的持续输出流畅度时，可在诊断附件中使用正文 delta 时间轴，但不要将其升级成额外核心 KPI。

E2E 主口径包含全部实际尝试至成功/失败的耗时，同时保留成功子集诊断。TTFT 对取得有效内容的样本统计，并并列缺失数/比例；缺失不记零、不隐藏在 p95 中。Agent 首反馈从任务起点计，与每请求 TTFT 分开。

p50/p95 使用 nearest-rank：排序后取 ceil(p×n) 第项（1 起算），保存 n 和统计输入；小样本 p95 仅描述当前样本，不代表长期尾部保证。扫描通过是样本验证，不是“真实长期成功率≥99%”的统计保证；持续窗口保留样本不确定性说明。

## 固定体验映射

|通用指标|用户体验含义|
|---|---|
|TTFT|发送后多久感觉系统开始有效回应|
|E2E|一个问题或工作多久完成|
|Output tokens/s|首个有效输出后，长回答继续生成的速度；计量含 reasoning 时只解释为服务输出速率|
|Completed output tokens/s|高负载下服务整体输出能力|
|Requests/s|网关能处理的请求吞吐，不直接等于用户数|
|Agent turns/s|单位时间能完成多少完整 Agent 工作|
|Gateway Service Success Rate|普通请求真正可用的概率|
|Agent Task Success Rate|用户交给 Agent 的完整任务成功概率|
|Error Rate / Distribution|高峰是否出现失败、重试或不可用，以及失败类型|
|Concurrency → Latency|同时使用人数增加后等待如何恶化|

## 长上下文

按固定短/典型/长输入分别报告 TTFT、E2E p50/p95、Gateway Service Success Rate；退化比例=该档延迟/短档延迟，另报增加秒数。提示与答案要求一致，输入 token 使用实测值，输出长度差异注明。

cache 字段只作为性能变化的解释信息；无字段不宣称冷缓存。首字节、首事件、细粒度 delta 间隔进入诊断附件。
