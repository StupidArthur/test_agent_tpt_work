# 核心指标定义

统一单调时钟、秒、固定正式窗口；暖机分开。未知值为 null，不补 0。每张表注明模型/协议/负载、样本数、窗口和统计对象。不同配置不混算。

## 成功、失败与耗时

分三层保留：①协议成功（HTTP/解析/终态合法）；②有效请求成功（①且取得本场景需要的有效正文或有效工具调用）；③Agent 任务成功（所有请求、要求的工具往返和最终业务断言通过）。文本空正文不能因 200/completed/DONE 判②；工具首轮可没有正文，但必须取得合法工具名、关联 ID 和可解析参数。模型不调用指定工具是③失败，不自动判①失败。

|指标|计算口径|
|---|---|
|Success Rate|本层成功数 / 本层全部实际尝试数；正文主表请求使用②，Agent 使用③；①进附件|
|TTFT|请求发起至本场景第一个真正有效内容。预先选择 first text、first reasoning 或 first tool；推理只有在确实作为该场景有效反馈时可选。工具需可识别为有效调用，原始增量时间与完成校验均留存。不得用 HTTP 字节、首 SSE、role、heartbeat、空 delta 替代|
|E2E Latency|请求发起至完整完成或失败；任务从任务发起至完整成功或失败，含全部请求、工具等待；开放到达还包含计划到达至实际发起的等待|
|Output tokens/s|每个有效成功请求的实际 output tokens / 请求 E2E 秒；报 p50/p95 与计量覆盖率，不能用输出预算替代实际 token|
|Completed output tokens/s|有效完成请求的实际 output token 总和 / 正式窗口墙钟秒，标注排空归属；与上项不同|
|Requests/s|正式窗口完成的请求尝试数 / 窗口秒，失败也计为完成尝试；另给有效成功 Requests/s，避免失败快而吞吐显得好|
|Agent turns/s|完整 Agent turn 的完成尝试数 / 窗口秒；另给成功 turns/s。此方案一 turn 是一个完整标准任务，可含多个 LLM 请求，不能拿 requests/s 直接替代|
|Error Rate / Distribution|失败尝试 / 全部尝试；按 HTTP、传输、超时、协议、空/无效内容及任务质量分类，保留原错误；主类别互斥，附加标签可重叠|

正文禁止只写“TPS”。没有真实 token timing 时上述输出速率不称“纯模型解码速度”。usage 缺失样本不参加 token 速率计算，不能默默剔除失败来计算成功率。

输出计量注明服务字段及其是否包含 reasoning；含推理的 output tokens 不等同于可见正文 token，不能直接据此断言正文生成更流畅。流畅性有疑问时查看诊断时间轴，避免将计费计量当作用户看见的输出速度。

E2E 主口径包含全部实际尝试至成功/失败的耗时，同时保留成功子集诊断。TTFT 对取得有效内容的样本统计，并并列缺失数/比例；缺失不记零、不隐藏在 p95 中。Agent 首反馈从任务起点计，与每请求 TTFT 分开。

p50/p95 使用 nearest-rank：排序后取 ceil(p×n) 第项（1 起算），保存 n 和统计输入；小样本 p95 仅为该样本描述，不代表长期尾部。扫描通过是样本验证，不是“真实成功率≥99%”的统计保证；持续窗口留置信区间或样本不确定性说明。

## 固定体验映射

|通用指标|用户体验含义|
|---|---|
|TTFT|发送后多久感觉系统开始有效回应|
|E2E|一个问题或工作多久完成|
|Output tokens/s|长回答持续生成是否流畅；E2E 平均速率不能证明增量平滑|
|Requests/s|网关能处理的请求吞吐，不直接等于用户数|
|Agent turns/s|单位时间能完成多少完整 Agent 工作|
|Success Rate|用户直接遇到失败的概率|
|Error Rate / Distribution|高峰是否失败、重试或不可用，以及失败类型|
|Concurrency → Latency|使用人数增加后等待如何恶化|

## 长上下文

按固定短/典型/长输入分别报告 TTFT、E2E p50/p95、成功率；退化比例=该档延迟/短档延迟，另报增加秒数。提示/答案要求一致，输入 token 实测，输出长度差异注明。cache 字段仅作解释，无字段不宣称冷缓存；首字节与细粒度间隔进附件。
