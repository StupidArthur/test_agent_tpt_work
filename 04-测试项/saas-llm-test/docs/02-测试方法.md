# 测量方法

先读 [方案](01-需求与范围.md)，按 [核心入口](../cases/README.md) 选择队列，不按“执行器能测什么”自动展开。

## 控制变量与样本

生产实际模型、reasoning、协议、网络、凭据模式优先。冻结 prompt、input/output 画像、输出上限、超时、history、工具等待和成功判据。普通短请求默认30次；长回答及每个上下文档默认10次；Agent 基线默认30完整任务。暖机单列；这些是项目样本默认值，执行前可按预算调整并写明，不因测完不达标再改。

每请求/任务保存开始、首有效内容、完整/失败结束的单调时间及原始内容。定义见 [指标](06-指标定义.md)。首字节、首事件和各 delta 时点只解释现象。缺有效输出不能用终态填 TTFT。

## 有效结果验收

短文本：固定唯一标记或答案；长文本：固定题目、最低完整内容与正常终态；上下文：中部/尾部标记使用正确且长度未越窗口；Agent：合法工具关联、结果回填和最终业务断言。保留期望与实际，不只记录执行器 ok。

协议成功、有效请求成功、任务成功独立统计；incomplete 是可识别的截断，不是完整长回答成功。usage、HTTP 200、DONE不能证明用户拿到答案。失败保留在尝试分母，空答案/模型质量与 HTTP/传输分类分开。

## 复用与诊断

同一正式窗口可供多个断言复用，登记全部 case 归属，避免重复发相同请求。短/典型/长上下文固定回答要求，控制顺序偏差，实际 token 与输出差异都注明；cache只解释，不强制冷/热矩阵。持续性由容量关键边界窗口承担，不另跑重复 PERF-08。

[容量方法](03-指标与容量.md) 统一闭环、开放到达和恢复。异常先核对对象、请求、响应与统计，再有限修正驱动；原 attempt保留，复测独立编号。诊断触发见 [条件入口](../cases/07-诊断与条件测试.md)。
