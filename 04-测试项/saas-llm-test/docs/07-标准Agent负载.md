# TPT Work 标准 Agent workload v1

用途：用稳定的产品实际上下文与工具链评价 Agent 等待、任务完成率和活跃用户容量。短 OK 请求不能代替此负载。本文件保存定义，不保存某轮通过率。

## 固定来源画像

|字段|v1 定义/来源特征|
|---|---|
|预设|安装包 `standard`；来源版本和 serializer 哈希在执行任务冻结|
|模型 / reasoning|flash / low；服务实际模型 ID 按目录映射记录，不把显示名当 wire ID|
|协议|Responses，使用产品 `@tpt-work/llm-tpt` serializer 的兼容消息/工具定义|
|典型每请求 input tokens|约22.5K～23.1K；包括真实 system、工具与历史，不用短 prompt 冒充|
|典型每请求 output tokens|约0.35K～1.1K；这是采样画像，不是每次必须产生的长度或预算上限|
|每任务 LLM 请求|典型2次：工具调用请求、工具结果回填后的最终回答；偏离数量保留实际值|
|工具调用|要求1次 pwsh 计算；实际调用名/ID/参数需合法且与回填关联|
|工具等待|来源约0.9～1.2秒；回放用冻结固定值或固定种子分布，独立记录|
|历史规模|使用采样中完整 system/user/工具定义，初始请求约22.5K token量级；第二请求增加 assistant 工具调用和 tool result。每任务重置同一基准，不继承前一虚拟用户任务；增长历史另作上下文场景|

## 固定业务与成功断言

六个月收入1000/2000/3000/4000/5000/6000，成本700/1400/2100/2800/3500/4200；要求使用代码工具计算，最终返回月度表格、趋势及两条建议，正文至少300字符。核对收入21000、成本14700、利润6300、利润率30%及本轮唯一标记。

回放不执行模型任意 Shell 命令；收到合法调用后模拟来源工具等待，回填独立核对的固定计算结果。工具调用缺失、结果关联错、最终数字/格式错均是任务质量失败；网关协议与有效请求成功另统计。该负载不能代表外部慢工具或所有 Agent 类型。

任务开始至首有效 reasoning/tool/text 的反馈口径在执行前冻结，解释该反馈为何对 Agent 有意义；任务 E2E包含两请求及等待。输出上限要足以取得正常终态和完整答案，固定后记录，不能把采样范围当上限或把空答案当成功。

## 版本与来源

来源：[预设 Agent 采样任务入口](../../../探索性测试/2026-10-07-预设Agent容量评估/README.md)、[来源报告与方法](../../../探索性测试/2026-10-07-预设Agent容量评估/报告.md)。10个 UI/session 采样及 SHA 保持在原任务 `负载采样/`，serializer/preset 在 `适配器快照/`；本目录不复制原始 session。

每次任务引用具体采样和 SHA，保存重建 body 哈希、输入计量、工具结果夹具与负载版本。更换模型/档位、系统工具、业务断言、工具等待或历史策略时创建新画像版本，结果独立分组；不要静默改变 v1。现有一般容量执行器并未自动内置此负载，驱动来源见上述探索任务，执行前登记适配和代码版本。
