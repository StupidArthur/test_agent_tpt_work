# 本测试项的接手规则

先读本目录 `README.md` 和 `执行交接.md`，再按当前模块查用例与方法，不必全量读历史套件。

## 范围

- 只评估网关 API 服务。禁止把软件 UI 操作、应用设置、安装导入、登录流程加入本测试项。
- 当前阶段是需求与方法设计；没有收到执行任务时，不实现新测试程序，不请求线上网关，不跑负载。
- 后续执行必须区分 Chat API 和 TPT Work 原生 Responses API；契约通过不等于软件端到端通过。
- 模型和思考档来自当前网关目录与服务约定，不能沿用历史列表或假定各家的 `low` 等价。

## 实现与记录

- 按 `docs/04-执行器与交付约定.md` 实现和验收。旧版位于 `archive/v1`，保持原始字节；不在旧版目录开展新任务。
- 每个实例留请求实参、响应/事件、断言实际值、失败原因和证据哈希。不把失败样本丢出统计；不把缺失 usage 写成 0。
- 流式首事件、首推理、首正文、首工具事件分别计时。不能把 role/空事件算成正文首字。
- 容量结论必须引用工作负载、SLO、样本量与稳定复核；并发请求数不能改称用户数。
- 没有隔离故障环境时，不向服务注入破坏、不臆造故障已测。记录所缺条件和影响，继续其他项。

本目录原套件的 AGENTS.md 仅约束保留的旧版历史材料，不作为新版设计或任务入口。
