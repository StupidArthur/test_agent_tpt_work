## 执行实例如何展开

- 每个目标/协议单独建环境记录。主协议为 Responses；Chat 只在网关声明支持且需要评估时展开。
- 功能先按每个当前服务模型做短可用性检查，再执行该模型所声明/业务所需的能力项。未购买或不可用模型单列，记录真实返回，不反复压测。
- TPT-06 遍历该模型声明的思考档；性能按 PERF-06 做档位对照。容量按主力模型、典型档位和场景展开，不默认给所有模型跑相同压力。
- 每个项列“前置、动作、断言、证据”；建议样本数属于设计参数，执行前冻结。默认功能正向项至少 1 次，负向项每种独立错误 1 次；不确定/差异再按补测规则有限复核。
- 同一场景证据可供多个断言复用，归属编号必须完整。性能与容量使用独立正式采样窗口。

## 条件与状态

必需能力失败要明确记录；未声明可选能力记未验证/不纳入本轮能力范围。隔离条件缺失也是未验证，不拿成功请求代替故障路径。

负向项的通过是“错误被正确拒绝/呈现”，不是“服务不出错”。性能项的完成测量与 SLO 达标分别记录。容量最高档通过只证明已测下界。

用例不会要求打开软件、点击 UI 或修改 TPT Work 设置。
