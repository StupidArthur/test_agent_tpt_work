# 容量与稳定性 case

核心方法与判据统一见 [容量与用户模型](../docs/03-指标与容量.md)；编号保留用于关联证据，不代表六项都要另跑一套实验。

|编号|定位|动作与判定|证据|
|---|---|---|---|
|CAP-01|诊断请求压力|受控固定请求burst，多独立波次；核对真实在途与正文/终态成功，分HTTP/传输/超时。结果不能填活跃用户表|波次、发起/结束、实际连接与在途、响应、资源|
|CAP-02|核心普通用户曲线|用户顺序完整短文本→think time，递增U；每档同时评≥99%与3/5/10秒 E2E p95，TTFT缺失单列|user/turn/request、正式窗口、输入输出与吞吐|
|CAP-03|核心标准Agent曲线|按[标准负载](../docs/07-标准Agent负载.md)调用→回填→最终答案；轮内顺序、完成后think time。请求成功与任务成功分别评|工具ID/参数/等待、两请求关联、最终断言、任务耗时|
|CAP-04|边界持续验证|只复核各阈值关键通过/首失败档，重合档共享窗口；默认每档两窗，每窗≥10分钟且≥100尝试，逐分钟观察|独立窗口全样本、资源、边界与限制|
|CAP-05|结论验证方法|候选吞吐附近低/目标/高开放到达；至少2分钟且30计划到达；全部对账，调度等待计用户等待，检查积压|计划/实际到达、未发起、队列、资源|
|CAP-06|实验完整性|停止发起、排空/期限关闭，至少10健康turn，核对基线容差与残留；未恢复如实报|停止/排空、恢复样本、最终曲线与限制|

每档保存成功率、TTFT p95、E2E p95、Requests/s及适用 Agent turns/s。样本不足不判服务失败，最高安全档通过只给下界。三条体验线都确认边界或达到安全上限再收尾；3秒失败不能直接终止10秒曲线。客户端故障、安全/费用上限仍优先停止加压。

持续验证前只报“初筛候选”；证据足够才填已验证同时活跃用户。普通/Agent分别给N3/F3、N5/F5、N10/F10，规划总用户=N×5且明确为规划约定。容量不得由请求协程数、连接池200排队1600任务或历史短答案吞吐直接推导。

CAP-04每窗独立判通过/不达标/实验无效，至少两有效窗才确认档位；客户端受限等无效窗不算网关失败边界。CAP-06保留每次恢复检查异常。中断重跑新建attempt，配置/SHA/时长/样本/排空不匹配不得复用；正式窗口安排暂停同网关其他调用并记录credential_id。执行约定见 [证据规范](../docs/04-执行器与交付约定.md)。
