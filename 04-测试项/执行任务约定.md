# 从测试项分派到执行任务

测试项定义长期范围，探索性测试任务定义本轮执行队列、机器、准备和交付。管理者设计/分配/验收，执行 Agent 测试并补齐函数。本机尽量不执行整轮 UI 测试。

## 1. 历史覆盖不能静默删减

- 历史实测动作和断言对应到本轮检查项，注明历史已覆盖/部分覆盖/新增未测。
- 合并编号不能漏掉原断言；不要只对照缺陷编号而遗漏通过的路径。
- 发现历史内容未映射，补到本任务覆盖表，保留为待执行/待分配的明确编号，不自行删除。
- 无入口、未实现、缺依赖只影响本轮状态，不等于从测试项删除。提出删除需写原项、理由、证据和影响，由用户明确确认；没有确认继续保留。
- 历史定级/结果与本轮结果分列，改变结论不覆盖原 attempt。

## 2. 任务入口与机器准备

每个任务 README 必须给出：负责 PC、完整编号队列、测试项链接、适用 AGENTS/技能/工具入口、夹具/前置/恢复、结果根路径和交付要求。

各 PC 独立核验：包版本/hash、CDP 实例、账号/模型、项目/cwd、权限、数据目录、运行时/依赖、工具库版本、操作授权与原生确认能力。环境记录不得复制另一台机器的实际值，路径不硬编码到历史盘符。

一个 PC 的同一应用由一个 Agent 操作；机器上已有人操作该实例时先协调，不抢 UI 锁或结束对方进程。不同 PC 的夹具名/运行编号包含机器身份，不用旧同名资产凑通过。

## 3. 所有操作必须通过工具体系

渐进入口为 [软件 UI 操作工具](../tools/ui-operations/README.md)。已有业务函数必须复用；`--plan` 没有新编号时，按 `--find`/模块/`--describe` 查找，不能把缺映射当产品不可测。

缺动作、等待、取值、夹具或恢复能力，在任务 `code/business` 或 `code/automation` 中实现可复用函数。复用主库 ctx/recorder，登记任务 catalog；通过 `call.mjs --task` 调用并保留源码/契约/调用/快照。文件与系统取证也登记函数，不能另开一次性脚本绕过记录。

每项记“用了哪个函数、取得了哪些断言值”。找不到函数先核对候选是否选错；确认缺失后补充，不能以“工具不足”直接阻塞。函数未实测、签名未知、返回值无法支撑断言都不算覆盖。

执行 Agent 不直接修改共享主库或全局规则；将函数留在任务目录，管理者验收后并入 `tools/ui-operations` 并补主库映射。其他 PC 后续取得审核过的同一版本再复用。

## 4. 逐项执行与恢复

先准备并核对样本，再通过真实产品入口触发行为，等待明确结束，读取实际值并比较。外部准备写盘不等于产品成功写盘；模型拒答不等于 OS 沙箱拒绝；开关改了不等于效果生效。

按共享场景推进整批，不在 checkpoint 停下询问。真正缺少本机/身份/原生/UAC条件时，记录尝试、受限步骤和补测条件，继续下一项；不能强行改配置文件模拟入口成功。

只动本轮自建夹具和明确备份的测试状态。恢复设置、文件和相关元数据/ACL，逐项独立回读；恢复失败与审计增量保留为残留。通过项默认不截图。

## 5. 结果只进本轮任务目录

```text
README.md / 任务队列.md
环境记录.json / 运行上下文.json / 夹具清单.json
结果/                         每个编号与子检查点的实际值/状态
证据/ + 证据索引.jsonl          归属、相对路径、SHA-256
运行日志/                     进度、动作/读取与业务调用
code/ + 新增函数清单.json       任务函数及契约/实际调用
审核/                         主库与任务代码快照
历史覆盖与工具覆盖.md           历史内容、新检查项、函数和缺口
恢复记录.md / 报告.md
```

按照 [记录契约](../skills/exploratory-testing/references/records.md) 登记。任务内可用现成格式，不要求为了此目录树重建执行框架。首次运行前冻结用例/工具版本和编号，续跑保留原 attempt。

报告分别给出：已登记、实际尝试、必需断言已观测、通过/差异/未验证、记录校验、恢复。两个 PC 的结果不混作一轮实测；交付提供分支/commit（适用时），由管理者合并和复核。候选结果未获审核不进入产品知识。
