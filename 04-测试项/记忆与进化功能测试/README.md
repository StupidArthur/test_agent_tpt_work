# 记忆与进化功能测试

整合早期分层记忆测试、设计对照、缺陷报告、换包回归和交付快照，形成统一测试项。本次只整理，未操作软件或复测，历史问题不自动延续到当前版本。

## 按需阅读

1. [测试设计](测试设计.md)：记忆层次、写入/注入/召回与自动进化，18 个检查项和判据。
2. [历史记录与证据](历史记录与证据.md)：历次观察、D-01～D-17 对应、后续修正和原始证据入口。
3. [来源清单](来源清单.json)：文件位置、SHA-256、来源性质及检查项归属。

开始实际执行再读本轮任务、[测试技能](../../skills/exploratory-testing/SKILL.md)、[UI 工具](../../tools/ui-operations/README.md)。本测试项不是本轮执行任务，不能直接把全部历史项称作当前已分配 case。

## 两个维度分别看

| 维度 | 要区分什么 |
|---|---|
| 数据层 | 人格/手册 SOUL/AGENTS、用户画像 USER、长期记忆 MEMORY、每日日志、反思/元数据/审计 |
| 处理链路 | 面板编辑、模型工具写入、外部改写、自动沉淀、反思、晋升、蒸馏、注入与召回 |

模型调用工具写下了一条内容，不等于自动沉淀已工作。记忆进入新会话，也不等于已经发生反思晋升。

## 历史资料的重点

写入、后续注入和文件扫描召回有历史观察；自动反思/晋升链路仍有未完成或问题记录。换包回归中 lastAt 推进、面板计数变化，应与旧轮“停住/计数为零”分开。

交付快照是同一报告与证据的副本，不是一轮新增测试；部分输入与日志由测试者人工构造，注入 dump 是模型复述。这些来源差异会影响结论强度。
