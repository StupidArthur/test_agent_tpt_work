# 沙箱测试设计

## 目标与前置

验证用户选择的权限是否落到实际执行边界，审批是否只放行相应动作，底层 ACL/elevated 是否可用，以及拒绝、诊断和恢复是否可信。

前置记录：exe/app.asar 版本与哈希、当前用户/SID、进程与会话、模型、项目和实际 cwd、权限档、沙箱实现、工具入口、测试目录 ACL/SACL 与可用命令。只凭目录盘符不能判断权限。

使用独立工作区 W、外部夹具 O、假安装目录 I，目录之间互不嵌套；每次写入包含本轮唯一标记。所有写/删/.git/硬链接操作只针对自建夹具，不针对用户现有资产、真实安装目录或系统目录。测试机上的 ACL/账户/UAC 操作需本轮任务有条件与授权；原报告的旧授权不延续。

先读相应实现规格再冻结预期。入口找不到、实现未安装、没有审批身份或无法处理原生确认时，记录实际搜索范围及补测条件；不强行修改状态文件冒充成功接入。

## 一、接入与实现可用性

| 检查项 | 动作 | 具体断言与取证 |
|---|---|---|
| SBX-01 实现身份与入口 | 盘点权限/沙箱设置和包内说明，读取真实实现状态 | 用户权限、实现档和当前生效值分别取值；声明但未发现入口标差异，代码存在不等于可执行。保留 DOM/配置/包身份 |
| SBX-02 目录供给与 ACL 前置 | 对可运行对照目录、普通 Modify 目录、受保护已有文件执行同一内部写探针；保存动作前 ACL | 分别记录 grant/启动/执行是否成功及磁盘结果；Win32 5/WRITE_OWNER/所有者的实际字段支撑归因，不能概括“某盘不可用”。不改 ACL 凑通过 |
| SBX-03 elevated 安装及生效（条件项） | 有隔离安装环境和原生/UAC处理能力时走真实安装入口；核对 runner 身份、再验证隔离；检查未安装路径 | 已装路径实际以声明低权限身份运行；未安装路径不静默变成无限制执行。未进入 elevated 时只能判入口/安装状态，不能声称 fail-closed 或隔离已测 |

## 二、权限与审批

| 检查项 | 动作 | 具体断言与取证 |
|---|---|---|
| SBX-04 只读 | 在 W/O 的文件做写、改、删探针 | 声明只读的入口均拒绝；文件 hash/存在性不变；拒绝原因可追踪。读操作不作为违规 |
| SBX-05 工作区写 | 同入口在 W 内建/改/删，在 O 同样操作；同时核对绑定项目与 cwd | W 中有实际产物，O 保持 hash/存在性；有效边界与声明工作区一致。仅工具文字“已写”不构成成功 |
| SBX-06 内置文件工具与子进程 | 对同一边界用内置 write/edit 与受限命令分别执行 | 两种入口各有实际拒绝/产物；不能由子进程通过推导进程内文件工具受约束。所有实参归属本轮夹具 |
| SBX-07 完全权限与切回 | 观察风险确认门；在自建 O 写标记；切回工作区写再尝试另一个 O 标记 | 确认前未启用，确认后允许声明动作；切回后外部写再次拒绝。前后权限实际值和磁盘状态都回读 |
| SBX-08 Auto review（条件项） | 核对文案与实际执行策略；对隔离夹具发审批应拒/应允场景，记录审查结论及磁盘 | 不把自动审查当沙箱隔离；是否符合审查预期需预先明确判据/身份。放行或拒绝均需调用与产物佐证；不得写真实安装目录 |
| SBX-09 一次升权允许/拒绝 | 从受限模式触发同一越界请求，分别允许一次和拒绝；随后再发独立越界探针 | 允许对应那次动作才产物；拒绝没有产物/绕行；后续探针不凭先前一次允许永久获得权限。保存申请、审批、执行对应 ID |
| SBX-10 升权参数与反馈 | 请求更窄/非法权限参数；检查失败命令 exit code、stderr 和磁盘 | 参数按当前契约明确拒绝；静默重定向失败不得呈现“已完成写入”；进程/网络错误不混为沙箱拒绝 |

## 三、路径与安全描述符边界

| 检查项 | 动作 | 具体断言与取证 |
|---|---|---|
| SBX-11 .git 与受保护文件 | 在假仓库的 HEAD/config 和自建非继承 DACL 文件执行读/写探针 | 根据当前明确保护承诺判预期；无承诺时保留安全/可用性观察，不凭“文件可写”自动判全部缺陷。磁盘与 ACL 前后可核对 |
| SBX-12 硬链接及路径别名 | 在自建同卷夹具中将 W 的别名连到 O 的测试文件；先证实文件对象关系，再执行边界写/删探针 | 记录是否影响 O、文件 ID/link 关系与前后 hash。只动夹具；普通字符串路径拒绝不能证明对象别名隔离 |
| SBX-13 ACL 生命周期与残留 | 比较供给前、供给后、切档/卸载/收尾后的 DACL/SACL、能力 SID 与完整性标签 | 每个变化有实际值；按产品回收承诺判断。清理命令退出正常不等于 ACE 已移除，需重新读取。elevated/acl 累积需真实切换条件 |
| SBX-14 读取、网络和进程可见性 | 在受限模式读取自建 O、请求本地 HTTP 对照、观察测试进程 | ACL 档若声明只限写，不要求这些被禁止；传输失败先核对 stdout/命令环境。elevated 的边界按对应规格单独判断 |

## 四、诊断与恢复

| 检查项 | 动作 | 具体断言与取证 |
|---|---|---|
| SBX-15 诊断及建议 | 在已知 ACL 前置不足夹具运行产品诊断，核对 caller/owner/权限、依赖命令、完整性状态；有条件再走修复 | 诊断是否跑完整、是否区分权限不足与所有者不符、建议是否有实际可执行验证。不能用诊断报告自身矛盾支撑根因确定结论 |
| SBX-16 收尾与恢复核验 | 停止测试执行，恢复会话权限/实现设置、夹具文件和测试改变的 ACL；有安装则按方案恢复账户/规则 | 原始配置/hash/安全描述符逐项回读，保留不能恢复的对象/变化。报告给残留，而非只写“已恢复” |

## 通用判定

通过要求每项必需断言有实际值。前置失败后的下游写未尝试不能算“沙箱拦住了”；模型拒绝执行不能替代 OS 拒绝。找不到定位或取值错误先按 [补测规则](../../skills/exploratory-testing/references/retest.md) 核对对象与动作，产品差异另行标记。

操作优先调用现成 [UI 工具](../../tools/ui-operations/README.md)；准备/文件/ACL检查也封装保留函数、实参、调用结果和版本。截图只在异常或需界面证据时保存，正常通过项以 DOM、调用、文件及 ACL 证据为主。

不在本次整理中运行任何检查项；新实例/预期应在执行任务中冻结。
