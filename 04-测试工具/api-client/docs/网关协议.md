# TPT Work 本地宿主接口协议参考

来源：对 `TPT Work 0.1.4-nightly.202610121943` 安装包的静态解析与本机实测（`@deepseek-ai/dsh-api-gateway`、`@deepseek-ai/dsh-client-connection`、`@deepseek-ai/dsh-desktop-host`、`@deepseek-ai/dsh-api-*` 等包）。字段随版本可能变化，以运行实例实际返回为准。

## 1. 服务与端口

- 应用内置一个 **dsh 桌面宿主本地服务**：`--host 127.0.0.1 --port ${TPT_DESKTOP_PORT:-21029}`。正在运行的普通实例就会监听它。
- 该服务就是"接口"；UI 本身也连它，所以**对同一实例的接口调用会即时反映到它的 UI**。
- 旧的 `--test --port=18471` 测试网关与 `GET /__verbs` 清单在 0.1.4 **已退场**（全包仅 `/lib/main.js` 注释提及"该面已退场"；实测 `/__verbs` 返回 404）。端点清单改为从各包 `typert.*.js` 静态导出。

## 2. 鉴权

- **cookie 会话**：`GET /?token=<启动 token>` 由宿主设置 `dsh-auth-*`（HttpOnly、签名）cookie；之后请求带该 cookie。
- 启动 token = 环境变量 `TPT_DESKTOP_LAUNCH_TOKEN`，缺省为每进程随机；壳旗标 `--token` 可覆盖。
- **无 cookie 时 `GET /api` 返回 401**；带 cookie 后 404/200 取决于具体路由。
- 不是 `Authorization: Bearer`。WebSocket 升级同样用该 cookie。
- 本工具的做法：从实例的 CDP 读它自己的 cookie（不接触 token）。

## 3. 一元调用

```
POST /api/<endpoint>
Content-Type: application/json
Cookie: dsh-auth-...

{"type":"client-request","rpcId":"<唯一>","method":"<endpoint>","payload":{"args":{...}}}
```

返回：

```
{"type":"server-response","rpcId":"<同>","result":{"ok":true,"value":...}}
{"type":"server-response","rpcId":"<同>","result":{"ok":false,"error":{"code":"...","message":"...","details":{...}}}}
```

- 业务错误常以 **HTTP 200** 返回，必须看 `result.ok`。
- 未知路由返回 404 `not found`；已注册但参数不合法返回 `result.error.code = "gateway/input-invalid"` 或 `"gateway/arguments-invalid"`。
- 参数校验：严格模式下，参数名/结构必须与 descriptor 完全匹配；多余字段报 `arguments do not match the descriptor`。

## 4. 身份参数（agentId）

需要 `agent: Agent` 的端点（`commands/execute`、`commands/list`、`userQuestions/answer`、`terminal/*` 等），在 wire 上字段名是 **`agentId`**，**值就是 `sessionId`**。

- 例：`commands/execute {agentId:"session-…", line:"/permission read-only", submittedAttachments:[]}` → `{kind:'success',text:'preset read-only'}`。
- 传 `agent` 会报 `missing "agentId"; unexpected "agent"`。
- 这类参数是 lookup 身份，不是普通对象；用字符串 id 传即可。

## 5. 流式与审批（非一元）

- 路由：WebSocket `ws://127.0.0.1:<port>/api/remote.mux`（带 cookie）。
- 客户端 → 宿主文本帧：`{type:'open',streamId,endpoint,payload}` / `{type:'item',streamId,value}` / `{type:'end',streamId}` / `{type:'cancel',streamId}`。
- 宿主 → 客户端文本帧：`{type:'item',streamId,value}` / `{type:'end',streamId}` / `{type:'error',streamId,error:{code,message,details}}`。
- 转发事件流：`endpoint:"$events"`，`payload:{args:{}}`。首帧 `value = {type:'ready',clientId,host:{home}}`；随后 `value = {type:'emit',event,args}`（通知）或 `value = {type:'waterfall',event,eventId,agentId,request}`（需要应答的瀑布）。
- **审批应答**：对 `event='approval/request'` 的 waterfall，一元回送

```
POST /api/$events/result
{"type":"client-request","rpcId":...,"method":"$events/result",
 "payload":{"args":{"clientId":"<ready 的 clientId>","eventId":"<waterfall 的 eventId>",
                    "outcome":{"kind":"result","value":"allowed-once"}}}}
```

`outcome.value ∈ {allowed-once, rejected, cancelled, unavailable}`（`ApprovalOutcome`）；也可 `{"kind":"next"}` 放行给下一个监听者、`{"kind":"rejected","error":{name,message}}` 表示监听者异常。

- **可靠性**：外部原始 `$events` 订阅对连接时已挂起的审批会补投；连接期间新产生的审批补投不完全稳定 → 用"重连订阅 + 处理积压"。

## 6. 常用端点与请求结构（节选）

| 端点 | args | 说明 |
|---|---|---|
| `session/list` | `{_request:{}}` | 会话摘要列表 |
| `session/create` | `{request:{workspaceId?,cwd?,sessionId?,agentPreset?}}` | 建会话，返回 `{sessionId,agentPreset}` |
| `session/prompt` | `{request:{requestId,sessionId,mode:'queue'\|'steer',content:[{type:'text',text}],clientTimeZone?}}` | 发消息，返回 `{accepted:true}` |
| `session/projections` | `{request:{sessionId}}` | 摘要：`title`、`turnOutline[{turn,seq,prompt,response}]`、`tptTurnOutcome{turn,kind,code}`、`tokenUsage`、`permissions.currentValue` 等 |
| `session/page` | `{request:{address:{kind:'session',sessionId},throughSeq,beforeSeq?,maxMessages?,turnWindow?}}` | 原始事件历史（`throughSeq` 取 projections 的 `asOfSeq`） |
| `session/cancel` | `{request:{sessionId}}` | 取消当前回合 |
| `commands/list` | `{agentId}` | 可用命令 |
| `commands/execute` | `{agentId,line,submittedAttachments:[]}` | 执行命令（如 `/permission <preset>`） |
| `workspace/create` | `{request:{path}}` | 建项目（返回 `{workspace:{workspaceId,path,title,...},created}`） |
| `workspace/delete` | `{request:{workspaceId}}` | 删项目（返回 `{deleted:true}`） |
| `agentPresets/list` | `{}` | 预设列表 |
| `llm/listProviders` | `{}` | 模型提供方 |
| `permissionPresets/catalog` | `{}` | 权限档位目录 |
| `settings/describe` / `settings/update` | `{}` / `{ns,patch,expectedRevision?}` | 设置读写 |
| `pluginInventory/list` | `{}` | 插件清单 |

## 7. 状态与副作用

- 会话/项目落在**数据根**：默认 `%USERPROFILE%\.tpt-work\dsh`（`sessions/`、`storages/`、`projects/`）。`--home` / `--user-data-dir` 可改；不同数据根的实例互不可见。
- `session/create {cwd}` 会把会话 workingDirectory 设为该目录；归类到项目可用 `workspace/insertSessionBefore`。
- 写入类端点在真实实例上会持久化；无对应"撤销"接口时按产品语义处理（如 `workspace/delete` 只移出列表，不删目录）。
