先在本轮环境填实际 `cdp_endpoint`、`account_name`、`memory_root`。不要复制 PC88 的目录或记忆初值到另一台机器。

## 先找操作，再读参数

~~~powershell
node 04-测试工具/ui-operations/call.mjs --find "记忆 添加" --module memory --limit 3
node 04-测试工具/ui-operations/call.mjs --describe memory.addEntry
node 04-测试工具/ui-operations/call.mjs --plan MEM-02
~~~

| 函数 | 可证明的实际值 | 准备与限制 |
|---|---|---|
| `memory.inspectSurfaces` | 设置弹窗限定范围的文字、控件、设置行 | 打开并关闭面板；不扫描侧栏证明面板状态 |
| `memory.probePanel` | 概览/记忆库/日志、列表行、高级设置、编辑弹窗 | `action=tabs/rows/library/advanced/edit`；edit 的 index 仅打开编辑器，不保存；不提供 delete-first |
| `memory.readOverview` | 概览和高级参数的原始标签、值、checkbox 状态 | 读取配置不证明注入、沉淀、反思等行为生效 |
| `memory.readFiles` | 本机目录树、真实内容、字节数、SHA-256、存在性 | 根目录取环境 memory_root 或显式 path；files 必须为根内相对路径，不跟随目录链接 |
| `memory.addEntry` | 添加后目标内容对应的列表行及面板文字 | content 非空；写前备份 MEMORY.md/index.json；调用后另用 readFiles 证明落盘 |
| `memory.editLayerFile` | 编辑器身份和旧内容、保存后文件实际内容及 SHA-256 | 必填 file、content、beforeSha256；file 为 SOUL.md/AGENTS.md/USER.md/MEMORY.md。旧哈希须先独立读到，不能用请求内容算出来 |

## 写入和恢复的顺序

1. `fixtures.backupFile` 备份本机目标文件和 index.json，保存返回的 backup/sha256；记录可能新建文件的初始存在性。
2. 调用添加/编辑函数。编辑时确认 file 对应本轮对象，传实际当前文件的 SHA-256。
3. 调用 readFiles，比较独立 expected 与 actual。`returned`、弹窗关闭、文字包含标记各自不能单独证明完整成功。
4. 用 `fixtures.restoreFile` 恢复本轮备份，再读文件核对初始哈希。保留真实 audit 增量；如果出现本轮新建文件，先登记归属和哈希，再按任务恢复规则处理。

MEM-01/02/05/16 的 `--plan` 仅登记已提供的部分操作，不代表四条测试项的所有断言已覆盖。分层注入、自动沉淀、价值过滤、反思、晋升、预算边界仍需各自的独立场景和实际证据。

原生删除确认、任务版任意路径恢复、任务版 setAdvanced 不在本次主库接收范围。高级开关可查现有 settings 函数，但保存失败须保留实际反馈，不能直接改配置文件补成 UI 成功。
