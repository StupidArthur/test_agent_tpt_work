# 操作函数体系当前评估

评估日期：2026-10-07。相关依据见 [全面回归验收](../../../05-探索性测试/2026-10-07-全面回归验收/验收报告.md)。

## 当前定位

对140条回归用例涉及的主要操作，现成函数库已基本能够作为 Agent 的主要操作体系。后续操作优先通过现成业务函数完成；确实缺少时允许新增任务函数，留存代码、契约与调用证据，任务收尾再审核并入主库。

## 已有依据

- 原回归实际记录481次业务调用，使用125个不同函数，覆盖对话、技能、专家、附件、设置等操作。
- 验收发现的定位、读取问题已修正；当前任务权限函数已补齐并现场验证。该次验收登记173个函数，152条用例映射。
- 已有按需工具发现、单函数参数契约、顺序批量调用、动作/读取记录、代码快照和恢复机制。

函数登记、映射覆盖和格式校验不能代替业务行为验证，也不能证明软件全部功能已覆盖。

2026-10-07 后续 [PC88 分支审核](../../../05-探索性测试/2026-10-07-PC88分支审核/README.md) 接收6个修正后在本机实际试用的记忆函数，主库累计179个函数、156个操作计划；新增4个 MEM 计划均标记 partial。新增范围为面板/参数/文件读取和面板添加/分层编辑，不代表自动记忆、反思、晋升、删除确认等全覆盖。

## 效率判断

后续交付回收增加经过本机验证的 `fixtures.removeCreatedFile`，主库累计180个函数。插件展开/恢复及会话搜索已本机试用；具体结论与未完成项见[交付审核](../../../05-探索性测试/2026-10-07-PCG与PC88交付回收/审核报告.md)。121个任务函数同名覆盖不等于121个行为全部重新验证。

渐进查找和稳定操作批量调用具备减少阅读与调用开销的条件，但目前没有完成新旧流程的耗时对照，不能宣称已经量化证明高效率。模型响应、产品执行、页面等待和证据写盘仍影响总耗时。

下一轮利用现有任务记录观察首次找对函数的比例、临时新增函数数量和每批耗时，不要求另建复杂统计体系。

## 已知边界

- 覆盖结论限于已测试范围，不能保证软件所有功能都只靠现成函数完成。
- 仍缺按准确URL关闭测试浏览器页面并核验的主库函数。
- 原生快捷键与帮助入口外部窗口行为缺完整观测，不能仅根据DOM无变化认定产品缺陷。
- 任务中新增函数必须留存并登记，审核后补入库；原任务代码和历史证据保留。

## 存放位置

| 路径 | 用途 |
