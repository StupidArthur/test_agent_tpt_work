## 按目标逐层缩小范围

工具发现按“目标对象 → 操作场景 → 候选函数 → 单个契约”展开。目标索引只列对象；对象页只列操作意图与场景；场景页列相关函数、适用边界和相似能力区别；`--describe` 才提供参数及补充契约。源码只在异常定位或开发时读取。

有 case 编号直接 `--plan <编号>`；已知准确函数名直接 `--describe <函数名>`，不必重复走导航。取得对象、参数来源、实际断言取值与恢复方法后就开始执行。

```powershell
node 04-测试工具/ui-operations/call.mjs --browse
node 04-测试工具/ui-operations/call.mjs --browse settings
node 04-测试工具/ui-operations/call.mjs --browse settings.plugins
node 04-测试工具/ui-operations/call.mjs --describe settings.setPluginExpanded
```

## 关键词检索与分类互补

`--find "业务词" --module settings --limit 3` 可直接找少量候选；选定场景后使用 `--route settings.plugins` 缩小范围。默认返回 5 条，limit 范围 1–20。检索按空格拆词，再按命中词数和字段权重排序，没有模型或向量调用，不能保证业务适用性。命中含义不清时返回场景比较用途。

`--list` 保留为完整登记表查询，不作为通常阅读入口。任务新增函数用 `--find "关键词" --task <任务目录>` 或单条 `--describe`；共享场景分类只收录已登记的共享函数，不隐藏任务函数的检索入口。

## 分类数据与维护

- `business/catalog.json`：实现位置、导出、描述、版本和参数 schema。
- `business/discovery.json`：目标对象、场景 ID、操作意图、选用指导、明确的候选函数名单及补充契约。
- `automation/discovery.mjs`：逐层导航与关键词检索；只读取分类数据。
- `maintenance/build-tool-docs.mjs`：生成目标索引、对象页和场景页；不覆盖人工维护的工具 README。

场景按用户要做的事情组织，可以跨相邻步骤组合，不依赖原始 feature_path 的零散标题。冒烟辅助单独列出，避免和业务函数混选。新增共享函数必须有场景归属；生成器检查未分类函数、不存在的引用及重复场景 ID，失败时不生成文档。修改分类后运行：

```powershell
node 04-测试工具/ui-operations/maintenance/build-tool-docs.mjs
```

每个场景应保持少量候选；变重时按目标和适用条件拆分。找不到能力先核对邻近场景和任务函数，再按 [扩展与边界](扩展与边界.md) 判断是真缺能力还是引导缺失。函数返回成功、分类覆盖完整都不代表业务用例通过。
