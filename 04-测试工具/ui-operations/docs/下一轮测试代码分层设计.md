# TPT Work UI 工具代码架构（旧文件名兼容）

本文件保留旧名 `下一轮测试代码分层设计.md`，以免已有链接失效；**这里现在只说明当前 TPT Work 工具库的实现结构**，不再作为所有 Agent 任务必须复制的“下一轮模板”。跨产品的设计方法、函数开发、验证与审核请分别阅读 [测试代码开发技能](../../../03-测试技能/test-automation-development/SKILL.md)及其 [通用分层参考](../../../03-测试技能/test-automation-development/references/代码分层设计.md)。

## 当前实际代码结构

```text
04-测试工具/ui-operations/
├── call.mjs                  # 函数发现、契约查询与调用入口
├── automation/               # TPT Work 的 CDP、定位、读取、事件记录等操作支撑
├── business/                 # 按产品功能命名的业务函数
│   ├── catalog.json          # 函数签名、路径和参数契约（主登记）
│   └── discovery.json        # 检索用同义词、模块顺序与选用提示
├── coverage/                 # 既有用例到操作函数的候选映射
├── docs/                     # 工具特定的调用、参数与扩展说明
├── fixtures/                 # 共享测试夹具
├── sources/                  # 代码来源与历史交付
├── maintenance/              # 代码验证、文档生成与历史迁移脚本
├── package.json
└── verification.json         # 上次结构检查结果，并非全面实机认证
```

业务操作由 `business/` 内函数承载，`automation/` 负责连接、定位、操作和实际读取；`call.mjs` 统一查找及执行，Agent 或上层任务根据用例对真实观察单独判断。不要将 `status=returned` 当作用例通过。

早期文档中以 `用例/cases.json`、`business/03-测试技能/` 或 `05-探索性测试/历史归档/根目录散落证据/` 为任务内必建目录的示意**不是现行模板或目录约定**。新任务以 [任务模板](../../../05-探索性测试/_模板-通用测试任务/README.md) 为准；仅在实际需要新增函数时按当前 [扩展约定](扩展与边界.md) 创建任务 `code/` 内容，不逐 case 建同类脚本。

## 选择和调用的实际入口

- 已有用例编号：`node 04-测试工具/ui-operations/call.mjs --plan <case编号>`。
- 未知函数名：`--find "业务关键词" --limit 3` 或 `--modules`，再用 `--describe <函数名>` 查当前真实契约。
- 函数调用、批次、事件及恢复日志按 [调用与记录](调用与记录.md) 执行；函数实现在 `business/catalog.json` 登记，不以本页旧示例签名作为实际接口。
- 当前验证命令：`node 04-测试工具/ui-operations/maintenance/verify.mjs`。它能检查语法、加载与映射等结构，**不代表真实业务全部通过**；变更相关操作仍需按授权实机核对。
- 需要新增或修改函数：先按 [测试代码开发技能](../../../03-测试技能/test-automation-development/SKILL.md) 识别真正缺口，再按 [本库扩展规范](扩展与边界.md) 使用 `async (ctx,args)`、事件记录、catalog 和任务代码留存；审核后才入共享库。

本库使用 Electron CDP + Playwright 连接 TPT Work 的具体方式参见 [产品接入技能](../../../03-测试技能/tpt-work-access/SKILL.md)。其他产品使用的技术栈可能不同，不能将上述目录和签名写成通用技能要求。
