[返回对话工具分类](modules/conversation.md)

新增组合版本 `project-workflow-0.1` **仅静态检查，未现场验收**。用户正在使用软件，本轮未连接CDP、未运行原生探测、未打开表单或创建资产。

## 按目标只读一个场景

| 目标 | 场景 | 函数 |
|---|---|---|
| 选择已有项目 | [已有项目](scenarios/conversation.project.md) | readProjectOptions / newTask |
| 当前对话首次打开本地目录 | [首次打开](scenarios/conversation.project.open.md) | conversation.openProject |
| 创建新项目 | [创建](scenarios/conversation.project.create.md) | conversation.createProject |
| 缺少当前按钮、表单或会话信息 | 所选场景中的读取候选 | conversation.readProjectSurface |

只对选中函数运行 `--describe`。组合内部复用 nativeWindow.readState/describe/act，不要求执行者逐条拼接原生消息。未知类型拒绝动作，实际路径回读失败保留现场。

## 输入来源与动作

两种写入都要求本轮实际 `processId`、`expectedProcessStartTimeUtc`、`expectedPageUrl`、`expectedSession`，已存在且授权的完整Windows `folderPath`、独立预期 `expectedProjectLabel`。`timeoutMs` 可选100～60000毫秒。当前会话没有可读取的唯一身份时拒绝执行，记录缺口，不自动新建会话。

`projectControlName` 是当前项目按钮的准确可访问名称。`entry` 为 `{role,name}`，role仅button或menuitem，来自登记读取，不能用示例猜标签。首次打开的entry指项目菜单中实际“打开本地目录”入口；若当前版本以DOM表单中转而非直接唤起系统选择器，本版本会超时并留证，须按实测扩展，不能声称兼容。

创建另需 `projectName`、真实可访问 `nameFieldLabel`、`folderControl`、`submitControl`（后两项同entry结构）和 `projectAbsenceEvidenceRef`。调用前用readProjectOptions登记同名项目不存在，独立审核引用；函数不把字符串引用当作已验证的不存在证明。entry指直接可见新建项目入口。名称输入和路径回填分别真实回读，再单次点击创建；通过当前项目菜单精确选项保留名称/HTML。

返回initial、final、projectMenu（创建时）、事件引用和观察阶段。首次打开读取当前对话项目按钮；创建读取唯一项目菜单项。`businessVerified:false` 与 `persistenceVerified:false`：调用成功不代替测试断言，菜单名不证明路径归属或重启持久化。

## 失败与恢复

拒绝已有DOM表单、菜单、系统选择器；不操作这些用户对象。失败不自动取消、再点提交或删除资产，检查已登记事件和当前现场后，仅恢复本轮窗口/表单。提交超时可能已经创建项目，先读取项目列表，再决定恢复，禁止自动重复创建。

项目移除和磁盘清理未纳入这些函数；首次打开会改变当前对话项目，创建会增加项目资产。验收前先确定恢复入口及授权，保留原项目身份和目录初值。不同版本标签/结构差异需要保留首次错误，不以改预期换通过。
