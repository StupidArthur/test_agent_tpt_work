# 调用、取值和恢复

[返回工具入口](../README.md) · [功能索引](功能索引.md)

## 调用一个函数

先 `--describe`，把本轮真实参数写到任务目录的 UTF-8 JSON。例如技能开关参数：

```json
{"displayName":"本轮技能展示名","internalName":"本轮技能内部名","value":false}
```

```powershell
node 04-测试工具/ui-driver/call.mjs skills.setSkillEnabled --task "05-探索性测试/本轮任务" --args-base task --args-file "参数.json"
```

必填字段、枚举、是否允许额外字段由 schema 检查；`${...}` 参数模板必须替换。展示名与内部名一起绑定，session 和项目路径也必须来自本轮真实观测。


## 控制上下文与模型轮次

常规 Agent 调用加 `--output compact`：保留 call_id、错误、事件编号及主要实际值；raw 不重复输出，长文本和长列表显示明确标记的预览。完整返回仍原样保存到 return.json，摘要提供 fullReturnPath。需要完整正文、集合或 raw 做断言时，只读取该次返回的必要字段；不得从截断预览判定完整性或严格回复。默认 full 保持兼容。

已知对象与参数的相邻步骤用 --batch 顺序执行；按 case/共享场景写参数文件，避免每次点击、创建参数、读返回都单独请求模型。审批、导航后的新对象或参数依赖前一步结果时再回到模型决策。证据审计与交付使用已有审计入口，一次生成结果，不反复遍历快照和计算哈希。

明确工具错误先定位根因，不以增加 timeout 反复执行相同失败。每个场景结束保存简短 checkpoint：已完成编号、当前对象身份、必要初值/恢复位置、下一步；不把全部证据正文重新装入后续上下文。

## 合并一组稳定操作

参数文件可以写为：

```json
[
  {"name":"conversation.readTaskPermissionOptions","args":{}},
  {"name":"conversation.readTaskState","args":{}}
]
```

```powershell
node 04-测试工具/ui-driver/call.mjs --batch --task "05-探索性测试/本轮任务" --args-base task --args-file "批次.json"
```

批次顺序执行；遇函数错误停止本批。只有后续对象与参数都已确定时才合并。如果导航后要发现新控件，或下一步参数依赖前一步返回值，分成两次调用。批次不会自动替换上一函数返回值。

相对参数路径按显式 `--args-base task|cwd` 解析；省略时保持cwd兼容行为，绝对路径不变。缺文件不会从另一个基准兜底，错误显示解析位置。

同一应用不并行操作。tool 返回运行中 session/cell 时，先等待结束。UI 锁存在时确认持有者是否仍运行，不能直接删除锁抢占。

## 从返回值形成结论

统一外层返回是 `call_id/status/observations`，具体函数结果位于其中，事件记录又可能在内层 `observations`。查看真实返回结构，不猜字段路径。

1. `status=returned` 只表示函数未抛错。
2. 读取事件含 `event_id/value/raw`；根据 case 判据比较 `value`，必要时审查 `raw` 和对象身份。
3. 把本轮 `call_id`、实际 `event_id` 和原值写入 case 结果；不引用历史编号，不用省略文本替代实际值。
4. 读取失败保留错误/未观测，不转换成 false。目标表面确实可读且对象不存在，才能记录真实 false/0/空列表。

例如验证技能入口是否新建会话，用 `skills.useSkillDirect` 的 `sessionBefore/sessionAfter`；`skills.useSkill` 自己准备新任务，不能证明入口会新建。

## 恢复和追溯

设置验证初值→改动→效果→重开回读→恢复。自动恢复的函数用同次返回的初值、变化值和恢复值；不要误把恢复值当变化值。

文件变更先 `fixtures.backupFile`，最后 `fixtures.restoreFile` 并读哈希。服务停止使用本次启动返回的 state；URL、日志路径也由返回值绑定。只停用本轮样本并保留待审，不删除用户资产。恢复失败和残留明确记录。

每次调用自动保留：

“只读函数”指产品业务状态只读，仍会向任务目录写证据、快照和日志，并短暂创建库目录的 `.ui.lock/owner.json`。它不等于文件系统零写入；任务路径可选获准的可写位置，不能用最终Git无差异替代执行期间写入事实。

| 位置（本轮任务内） | 内容 |
|---|---|
| `审核/函数调用/<call_id>/` | 实参与完整返回 |
| `运行日志/业务调用.jsonl` | 函数版本、时间、环境、实参与返回哈希、代码快照引用 |
| `运行日志/business.jsonl` | 实际动作与读取事件 |
| `审核/代码快照/` | 调用时库和任务代码的 SHA-256 快照 |

case 结果和报告仍由 Agent 生成，库不会自动判定业务通过。通过默认无需截图；失败仅在图片有解释价值时截图。异常按 [补测规则](../../../03-测试技能/exploratory-testing/references/retest.md) 处理。

## 机械证据复核

收尾运行 `node 04-测试工具/ui-driver/maintenance/audit-task.mjs "05-探索性测试/本轮任务"`，一次核验调用ID、参数/返回/源码快照SHA、返回身份与事件引用，避免每轮临时编写成组脚本；相同快照只计算一次哈希。输出不含业务正文，不改任务或产品。非零退出先定位具体失配。

`integrityVerified:true` 只证明记录内部一致；工具保留 `businessVerified:false` 和 `currentRecoveryVerified:false`。业务预期、实际效果与当前恢复仍须独立核验，合成审计夹具不计作产品执行。

审计摘要提供 `callIndex` 以及前3项 `callReferences` 的call_id、函数名、实参/返回路径和SHA-256，可直接引用，不必再遍历证据目录、重算哈希或读取相同返回。`referencesTruncated:true` 表示摘要引用并非完整调用清单；需要其他调用时按本轮断言已有CALL引用定向读取callIndex。仍须判断真实actual与预期，摘要不自动给业务通过。
