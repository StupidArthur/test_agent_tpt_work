# 找不到工具时：补充与审核

[返回工具入口](../README.md) · [测试代码开发技能](../../../03-测试技能/test-automation-development/SKILL.md)

本页仅说明 **TPT Work UI 工具库**的函数签名、登记、调用及验证命令；通用代码分层、开发规范与评审方法由独立测试代码开发技能负责。

## 先确认是缺函数还是选错

按当前 case 执行 `--plan`；无编号时用 `--browse <对象>` 选择场景，或 `--find "业务词" --module <对象> --limit 3` 查少量候选，再对选中函数 `--describe`。任务新增函数另用 `--find "关键词" --task <任务目录>` 查找。核对它是否会额外新建会话、自动恢复、导航或读错对象。部分判据只需要换读取函数或正确绑定返回值，不需要另写点击脚本。

在新增函数清单中留下操作意图、查找词、候选及不用的原因。管理者发现主库已有能力时，不重复入库，修订检索词、契约或示例；确实缺能力才合并实现。

常见误选：设置内置插件用 `settings.listPluginCards/setPluginExpanded`，不是左侧插件市场卡片；展开参数传唯一插件名，不传多行卡片全文。设置导航要求环境填写准确 `account_name`。会话搜索命中数只能证明搜索结果，不能替代本轮session身份核验。

新增文件恢复可用 `fixtures.removeCreatedFile`：创建前先用 `fixtures.readFile` 记录不存在；删除时传该读取引用与当前内容SHA。只限允许根目录内本轮创建的单文件，核心记忆文件、链接路径和目录均拒绝。已有文件恢复仍用备份；该函数不是产品删除入口。

## 确实缺少时，写任务函数并保留

业务函数放 `05-探索性测试/<任务>/code/business/`；共享接入和控件定位放 `code/automation/`。业务函数签名 `async (ctx,args)`，复用主库接入与 `ctx.recorder.action/read`；保留真实动作、读取和异常。

在本任务 `code/business/catalog.json` 登记，例如：

```json
{
  "functions": [{
    "name": "task.readCustomPanel",
    "file": "code/business/custom.mjs",
    "export": "readCustomPanel",
    "parameters": {
      "type": "object",
      "properties": {},
      "required": [],
      "additionalProperties": false
    }
  }]
}
```

函数需要返回自身实际读取，不是预设成功值。上述登记只是结构示例，文件和导出实现存在后才能调用：

```powershell
node 04-测试工具/ui-driver/call.mjs --describe task.readCustomPanel --task "05-探索性测试/本轮任务"
node 04-测试工具/ui-driver/call.mjs task.readCustomPanel --task "05-探索性测试/本轮任务" --args-base task --args-file "参数.json"
```

名称不能覆盖主库，文件必须位于本任务 code 下。自动保留本任务代码快照。在 `新增函数清单.json` 写：case、缺口、函数路径、参数、真实调用证据、恢复办法。临时探针也必须留存，不能测完丢弃。

任务结束再审核跨机器参数、对象绑定、等待、断言读取、异常和恢复，决定如何并入主库；并入后保留任务来源。不会要求 Agent 为每条 case 都新增函数。

## 原生 Windows 窗口能力

页面 DOM 的弹窗函数不覆盖系统文件/文件夹选择器。缺能力时按 [原生 Windows 弹窗方案](../../../03-测试技能/tpt-work-access/references/原生Windows弹窗.md) 在任务中实现 UIA 发现与 Win32 操作层，再由业务函数组合；不要为每个业务场景重复窗口探测，也不要在所有动作前无条件扫描桌面。

探测需限定 PID、窗口归属和等待范围，区分已知窗口、未知窗口、未发现、通道失败与超时。操作必须动态核验句柄和控件意图；未知窗口仅取证并记阻塞。回读窗口关闭、页面回填和业务状态分别形成证据，消息调用成功不能替代业务断言。已有共享函数不足时留下候选与不适用原因，任务登记、真实验证和审核要求沿用上文。

当前库已重新实现 `nativeWindow.probe/list/describe/act`，见 [原生窗口分类](modules/nativeWindow.md)，真实验收结果留本轮任务。它不依赖CDP，不能由函数返回成功推出项目创建通过。历史笔记原源码未直接迁入；已识别结构之外的新能力仍按任务登记与审核流程处理。

## 当前验证范围与缺口

完整登记表是 [business/catalog.json](../business/catalog.json)，使用 `--describe` 单条查询。结构状态见 [verification.json](../verification.json)，现场验收见 [2026-10-07报告](../../../05-探索性测试/2026-10-07-全面回归验收/验收报告.md)。函数登记/映射覆盖不等于全部实测。

- 当前任务权限函数已补齐并实测。
- 仍缺按准确 URL 关闭测试浏览器页面并核验的主库函数。
- CDP 合成按键无响应不能排除原生快捷键机制；页面内没有变化不能排除帮助打开外部窗口。相关结论需要其他观测，不得直接认定缺陷。

修改库后运行 `node 04-测试工具/ui-driver/maintenance/verify.mjs`，再实测受影响动作。功能索引由 `node 04-测试工具/ui-driver/maintenance/build-tool-docs.mjs` 重建；生成文档不会操作产品。
