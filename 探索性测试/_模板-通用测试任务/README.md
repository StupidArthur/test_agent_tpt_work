# 测试任务入口｜通用模板

> 使用方式：复制本目录为 `探索性测试/YYYY-MM-DD-任务名/`，填写下方「本轮配置」和「测试用例.md」，其余执行规则、报告结构直接复用。不要为不同工作模式重新写一套 README。

## 1. 本轮配置（创建任务时只需填写这里）

| 项目 | 内容 |
| --- | --- |
| 任务名称 | 【填写】 |
| 工作模式 | 【用例试运行 / 常规测试 / 缺陷复测，三选一】 |
| 负责 PC / 执行者 | 【填写】 |
| 测试目标与范围 | 【填写】 |

## 2. 固定阅读入口

1. [根目录 AGENTS.md](../../AGENTS.md) → [执行任务约定](../../04-测试项/执行任务约定.md)。
2. [探索性测试技能](../../skills/exploratory-testing/SKILL.md) → [记录契约](../../skills/exploratory-testing/references/records.md)。
3. 操作前按需查 [UI 工具入口](../../tools/ui-operations/README.md)，异常时参考 [补测规则](../../skills/exploratory-testing/references/retest.md)。
4. 按本轮用例查对应正式测试项与历史证据；不要求预读全部历史材料或工具源码。

## 3. 工作模式（只使用本轮选定的一种）

- **常规测试**：按原始用例执行，记录产品行为、证据和差异；不因结果不符合预期而修改原断言。
- **用例试运行**：同时交付两类独立结论：①产品真实表现与候选问题；②用例的可执行性、断言有效性、可复现性及入库建议。产品失败不等于用例不合格，产品通过也不等于用例合格。用例问题只在 [用例评估.md](用例评估.md) 提修订建议，不覆盖原始用例。
- **缺陷复测**：注明原缺陷/原证据及修复版本；按复现步骤和受影响断言复测，区分“未复现”“已修复证据充分”“证据不足”，不要仅凭一次通过宣布彻底修复。

**所有模式共同适用**：按真实操作、真实读取、真实证据下结论；区分产品差异、用例问题、工具问题、环境问题及未验证。分析属于候选归因，最终定性和是否入库由用户或指定审核者决定。

## 4. 固定执行规则

- 首次执行前冻结用例版本、编号、预期断言和工具版本；新增/修订用例另存版本和原因，不覆盖原记录。执行顺序直接以 [测试用例.md](测试用例.md) 为准，不另建任务队列。
- 实际操作、读取、夹具准备及恢复按仓库工具约定进行；优先复用现有函数。确需新函数时按现有规则保留源码、登记、调用与证据，不自行改共享主库。
- 每条用例记录本轮 run/attempt、前置、输入、实际动作、预期与实际、每个必要断言、操作/读取引用、状态、证据及恢复。没有实际值不记通过；保留旧 attempt。
- 完成本轮分配的全部编号后核对恢复状态；缺条件时记明已尝试的准备、受限检查点和补测条件，继续其他项。遵守适用的授权与安全边界。
- 适用的环境记录、运行上下文、夹具清单、`结果/`、`证据/`、证据索引、调用日志和新增任务函数等在**执行时**按 [执行任务约定](../../04-测试项/执行任务约定.md) 生成，不为保持目录外观提前建空目录。
- 只在当前任务目录交付，不自行把候选观察、用例或函数合入正式目录。

## 5. 固定交付与审核

- [测试报告.md](测试报告.md)：所有模式都提交。产品真实结果、逐项状态/证据、候选问题和未验证范围。
- [用例评估.md](用例评估.md)：用例试运行**必交**；其他模式按需。记录用例设计问题、修订版本、入库建议及证据不足项。
- [恢复记录.md](恢复记录.md)：所有涉及修改状态的任务都提交；无修改也明确记“无状态修改”及核对依据。
- 交付实际分支/commit（适用时），审核状态默认为**待审核**。Agent 只能给出入库建议，用户/指定审核者决定定性及正式入库。
