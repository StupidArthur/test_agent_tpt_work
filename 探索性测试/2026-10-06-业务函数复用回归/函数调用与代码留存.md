# 本轮函数调用与代码留存契约

关联仓库`02-测试方法与技术参考/下一轮测试代码分层设计.md`。此契约补充原结果格式，不改变冻结case的业务断言。

## 调用顺序与目录

LLM按功能查`code/business/catalog.json`，读取适合函数契约，先复用；可组合已有函数。没有能力时再补写：软件接入、frame、定位、交互、读取、日志放`code/automation/`；对外可调用产品操作放`code/business/<一级功能>/<二级功能>.mjs`。临时发现脚本放`code/probes/<功能>/`并留来源，后续正式调用能力整理进对应模块。

不把每条case写成一个平铺脚本，也不要求新建case运行器。LLM安排tool call、根据case比较真实观察、登记判定、调用恢复。源码可用MJS/CJS；统一入口支持ESM导出或CJS导出对象。

## 函数登记

初始catalog没有实现；它不会提供虚假的可调用函数。另一台机器首次执行时按缺失能力补写分层函数并登记，后续调用优先复用。当前轮临时脚本尚未完整审核，不要求等待迁入，也不直接当已审核公共能力。本轮新增函数标待审核。每个条目示意：

```json
{
  "name": "skills.importSkill",
  "feature_path": ["技能", "导入"],
  "file": "code/business/skills/import.mjs",
  "export": "importSkill",
  "version": "本轮真实版本",
  "status": "本轮验证-待审核",
  "description": "导入本轮技能并读取实际反馈",
  "contract": "code/business/skills/导入函数契约.md",
  "parameters": {
    "type": "object",
    "required": ["packagePath", "internalName"],
    "additionalProperties": false,
    "properties": {"packagePath": {"type": "string"}, "internalName": {"type": "string"}}
  },
  "modules": ["code/automation/session.mjs", "code/automation/skills.mjs"]
}
```

条目必须指向实际函数，modules列全部本轮实际调用的支撑模块；不列整个node_modules。函数契约写前置状态、适用版本、参数、对象识别、终态、副作用、返回与恢复。函数签名为`async function importSkill(ctx, args)`，返回可JSON序列化的真实观察/来源，不返回case通过结论。

ctx提供taskRoot、environmentId/environment、runtime、runId、businessCallId、recorder；app/CDP连接由automation按环境记录获取和核验。避免顶层import时操作UI，实际操作发生在函数调用内。

## 薄调用入口

```powershell
node tools/call-business.mjs --list
node tools/call-business.mjs --describe skills.importSkill
node tools/call-business.mjs skills.importSkill --args-file 运行日志/输入/本次唯一参数.json
```

参数文件在任务目录，保留本次实际参数；不放密码、token或Webhook密钥。另一台机器按实际登录态接入，凭据由用户提供或现有本机授权配置读取，不照搬历史抓取中的key。入口检查任务启动状态、参数必填/未知项、实现位置和环境身份；参数类型/业务范围还应由函数落实。

入口只执行一次业务函数，不编排case。每次生成call_id，将参数、实现/支撑模块、调用入口、记录模块冻结到`审核/代码快照/<call_id>/`；保留实际返回/错误，记录模块调用前后哈希和函数版本，追加`运行日志/业务调用.jsonl`。后续代码升级使用新版本和attempt，不覆盖旧快照。

调用业务函数内使用ctx.recorder同步记真实操作/读取。自动包含business_call_id；相同调用可以支持多条case，结果都引用同一call_id和相关事件。函数可以组合稳定连续操作，页面变化后内部重新观察。

## 结果新增字段

每条原`结果/<case_id>.json`增加：

```json
{"business_call_refs": ["本轮真实CALL编号"]}
```

原actual、action_refs、read_refs、source、raw、恢复与哈希要求不变。软件UI动作及DOM读取应关联其business_call_id；离线夹具/文件读取可独立记录来源。函数返回不代表业务通过，LLM按case算子与预期比较，并保留组成原值。

函数只按case指定对象和范围读取；图像返回src/资源身份，拒绝返回对应错误反馈原文。动态expected在操作前从夹具/选中对象独立绑定，禁止用actual回填。操作或读取异常保留error并使相关断言actual=null，不吞异常后返回空串/false；真实不存在须先确认目标表面和对象身份。恢复快照覆盖本轮所有实际改动项，缺项不能宣称全部恢复。

evidence除原日志/关键截图外，还引用`运行日志/业务调用.jsonl`及实际SHA256；调用日志已经指向参数、返回和源码快照，`tools/check-code.cjs`校验其哈希。调用日志组结束再一次计算证据哈希，后续追加后统一更新受影响引用。

## 检查与审查

`node tools/progress.cjs`依次运行：

1. 原记录校验：环境、队列、断言、真实读日志、恢复、证据、判定一致性。
2. 新代码校验：业务调用存在、环境一致、UI事件关联、参数/返回/模块快照哈希、调用中源码未变。

checks不操作软件，也不成为测试运行器。代码索引声明完整性与函数实现正确性仍由双方审核，自动校验不能证明所有依赖已声明或LLM判定语义正确。

有实际调用时，代码校验同时从调用日志生成`审核/脚本索引.json`，不要求再手工抄写另一份索引。

收尾报告“复用函数/新增函数/修改函数”及对应证据。公共库提取待双方审核，本轮中间产物保留在本任务目录。
