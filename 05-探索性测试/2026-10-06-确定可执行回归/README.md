# 确定可执行回归：Agent 入口

本任务只做准备，由用户另行安排 Agent 执行。主 Agent 与 Luna 不执行本任务。结果待双方审核，不直接入产品知识。

可直接给执行 Agent 的指令：

> 从本任务 README 开始，按渐进阅读顺序接入真实 TPT Work。执行全部48条，按6个共享场景推进；每条必须有真实尝试、终态与证据，不登记阻塞/暂缓。已有证据充分则不重复操作，失败有限诊断后继续。最后提交完整结果、设置恢复和样本残留，等待双方审核。

## 渐进阅读

1. 先读本页与 [执行规则](执行规则.md)，明确范围与终态。
2. 读仓库根 `skills/exploratory-testing/SKILL.md`，掌握去重、共享场景、分组操作、取证和恢复。
3. 按需读 `02-测试方法与技术参考/测试接入与执行指南.md`；需要启动/重接时读同目录 `portable-agent-exe-ui-api-guide.md`。
4. 读 [场景与夹具](场景与夹具.md)；用 `用例/cases.json` 作为唯一执行清单，不重读全部原设计文档。
5. 每组开始前查看该组 case；历史执行依据在 `用例/历史可执行依据.json`，仅遇到定位/期望解释问题时读对应旧证据。

快速浏览见 [执行清单](用例/执行清单.md)。

## 目标

本任务含 48 条收窄后的回归用例，来源于上一探索任务已经实际走过的 UI 路径。无需市场安装、现场对端、第二身份、故障注入或原生窗口。测试正常和失败路径都必须得到实际终态；历史差异不作为本轮预填结果。

“确定可执行”指入口、夹具与验证办法已实测存在，不保证产品成功，也不能保证机器永不崩溃。禁止逐条标阻塞来结束任务；若包升级导致入口消失，做一次定位核查后记录本条失败（入口不可达），保留证据继续。若应用整体无法接入，先按指南有限恢复；仍不可恢复则记录任务级环境失败和未执行数，不能伪称用例已执行。

## 快速执行

按6个场景组顺序执行：基础对话 → 技能导入/查看 → 技能调用/启停 → 专家导入/查看 → 专家调用/副本/拒绝 → 设置效果。每组共享准备和证据，逐条保留判定。模型固定当前可用标准/low；现有项目以UI核对，历史为tpt-workspace。

保守计划为6组，每组记录耗时后再估剩余时间。不做泛化自由探索；新问题先记观察，不扩充队列。正常一次执行，失败最多一次有针对性的定位修正。不要重测已获得充分证据的检查点。

运行 `node tools/progress.cjs` 查看结果完整性。它不操作软件。初始48条均未执行；收尾必须48条有终态、证据与清理结果。格式和哈希通过不代表业务通过。
