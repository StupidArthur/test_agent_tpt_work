## 1. 任务目标与交付

### 当前开发状态与查找规则（用户补充，2026-10-05）

TPT Work 是开发中的产品。需求文档中的部分功能尚未出现在当前产品中，不能假定350条用例现在全部可执行。

- **用户体系功能完全没有实现。** 本轮暂缓`ACCOUNT-001`至`ACCOUNT-070`，不寻找注册、企业认证、多身份、空间隔离等入口，不准备真实账户或后台来强行验证。现有临时登录仅用于进入软件，不代表需求中的用户体系已经实现。
- **连接器本轮探索性测试无法测试。** 本轮暂缓连接器文档对应的`OTHER-012`至`OTHER-015`（MCP/IM、AAS）及其他依赖连接器的步骤。只记录限制，不尝试配置、鉴权、调用或补造环境；这不表示连接器完全未实现。
- 原350条用例及编号保留，74条为用户确认暂缓；其余276条进入探索队列，仍可能因开发状态或依赖而无法执行。暂缓不计通过，不记为本次实测失败。

对其他功能，先检查合理入口：当前导航、相关一级页面、可见菜单和目标frame；找不到时做一次重新观察或关联入口核对即可。**不要反复寻找、强制点击、猜测内部接口或绕过UI来证明功能存在。** 记录“目前没有发现入口”，附检查过的位置和证据，再继续下一功能。入口存在但操作表现出占位、未开放等事实时，可记“测下来没有实现”，同时写清动作和现象；仅没找到入口不能断言功能肯定不存在。明确错误或异常仍保留差异，分类留待双方审核。

此规则适用于所有主case及动态子检查。已知未实现或本轮不可测的功能无需再次查找。其他case依赖用户体系或连接器时，只测能独立验证的部分，未完成检查点注明依赖，不标整条通过。

完整遍历并执行[350条用例](用例/README.md)，以广度优先方式探索当前 TPT Work，逐条保存执行情况、实际产品特性、与文档的差异和审查证据。同时盘点全部左侧菜单、进入后的一级可点击功能，以及头像→设置下所有当前可见分类及功能。

## 3. 当前操作边界

- **默认方法：Electron调试端口 + Playwright连接CDP。** 当前历史端口为9234，使用前核对进程、端口归属、`/json/version`、`/json/list`及真实可见页面。不要只验证端口连通就宣称软件可用。
- 登录页和主界面可能同时存在；依据当前可见页面选择。嵌入模块枚举frames后定位，不把顶层找不到控件判成页面空白。
- 同一稳定页面上已发现、后续不会受前一步改变的控件，可在一次调用内顺序`await`操作。提交、导航、弹窗或异步状态变化后先等待并重新观察，再推进后续步骤。同一页面动作不并行执行。
- 本轮对话和生成类探索只使用当前已验证可用的**低级模型/低推理等级**，先读取当前名称并做短对照。不可购买或调用未购买的高级上游。要测试模型失败恢复，使用隔离测试环境的可控故障；没有该能力就登记阻塞，不能用真实高级模型制造故障。
- 选择项目只选**已有项目**；不添加项目、不删除记忆。避免左上角Home等已可能触发Windows原生窗口的入口。测试目录可放在已有测试项目中，但不得把创建磁盘夹具当成UI添加项目。
- 原生Windows弹窗不可通过DOM可靠操作。操作前发现会触发不可控弹窗就标阻塞；意外弹出时保存前后状态、停止该动作链并请求人工处理，不能隔窗继续点后台。可用真实HTML文件输入时使用`setInputFiles`；不能伪造拖拽成功，也不能调用内部JS绕过被测UI。
- 使用本轮隔离样本。禁止删除或覆盖现有用户资产、重置真实用户配置、向真实IM发送消息、提交真实企业审核、现场写值或执行全局负载测试。涉及删除/更新仅处理本轮明确归属且确认可控的样本；受限清理记录遗留，不强行完成。
- 测试账号、验证码、管理员、边缘节点、AAS、事件注入等依赖未提供时，逐条登记环境阻塞；不猜密码、不探测陌生节点、不直接改生产数据库。
- 保留已有实例；需启动网关时使用独立测试profile/home并核对单实例冲突。原指南有历史路径与配套仓库脚本，本目录不假定这些脚本存在。只结束本轮明确归属且PID已核验的进程。
- 密钥只用运行时获准输入或既有凭据，禁止写进用例、执行记录、截图和报告。截图包含秘密时先遮罩再存档；不要先落盘明文再说已经脱敏。

## 4. 执行方式：先广度，后增加深度

### 第一轮：入口覆盖

记录包版本、exe路径、app.asar哈希（可获取时）、时间、环境、账号类型、空间、项目、模型、权限及端口。建立[覆盖地图](覆盖地图.md)。逐个左侧菜单、一级功能和设置项走过入口与主要控件，确认哪些可用、缺数据、未实现或受限。

入口浏览只记“入口/页面可达”，不能把所属业务case标成通过。设置和其他开放探索case的子项用`OTHER-018/子项-001`一类标识（按实际父case编号），每项独立保存动作、结果与证据；子项不拿来凑350条主case数。

### 第二轮：按模块交错完成业务用例

以模块队列轮转：对话→Skill→Agent→账号→被控端→引用→其他。优先每模块低成本核心闭环，然后完成其余条目。不要在一个功能反复深挖而遗漏其他模块。优先级P0/P1是**本任务执行顺序建议**，不改写产品自己的版本优先级。

按case准备样本、保存初始状态、执行实际步骤、等待明确终态、核对每个检查点、独立回读结果。每个请求携带唯一case/attempt标记，核对回复和产物对应本轮，避免旧请求残留。不同模型组合的独立比较使用新会话；同会话恢复测试必须保留故障会话，并额外用干净会话作对照。

### 第三轮：异常、恢复和差异复核

失败先留证，再做最小对照。能安全复核时尽量只改变一个因素；重试不能覆盖第一次结果。一次复核成功不抹掉之前的失败或崩溃。没有故障注入、第二身份或权限时，不冒充完成深层验证。

执行350条中发现的新入口、新行为和用例外异常也登记。不要求把新发现全判bug；但不能因“超出用例”而不记录。用户要求持续执行时不要在一小批结束后停工；被中断、达到平台限制或用户明确暂停时保存队列与当前现场供续跑。

## 5. 逐条结果与差异分类

每条case使用[执行记录](执行记录/README.md)中同编号JSON，276条初始为未执行，74条按用户确认标为暂缓。追加`attempts`，一条尝试至少包括时间、环境ID、实际前置、测试输入、实际步骤、逐检查点结果、实际产品行为、证据、等待条件和结束状态。无新特性时也写明“未发现额外特性”，不要空着让审核者猜。

| 执行状态 | 使用条件 |
|---|---|
| 未执行 | 尚未尝试；不计覆盖。 |
| 暂缓-未实现 | 用户确认用户体系未实现；不是实测失败或通过，本轮不寻找入口。 |
| 暂缓-本轮不可测 | 用户确认连接器本轮不可测；不推定完全未实现，不强行补环境。 |
| 阻塞 | 已检查依赖，但无法执行或完成；填缺失条件、证据、可继续事项。 |
| 不适用 | 有证据表明本包范围或平台不适用；暂定分类，待双方审核；不是通过。 |
| 已执行-符合预期 | 所有目标检查点有直接证据；不能仅有toast、按钮或HTTP200。 |
| 已执行-存在差异 | 已观测到任一预期偏离；必须建差异，不等于确认bug。 |
| 已执行-结论不确定 | 有操作但证据不足或结果歧义；保留未完成检查点和补证计划。 |

每条差异区分：**实现差异、可能的设计演进、版本冲突、需求不清、环境限制、自动化问题、疑似缺陷**。可以有主分类与次分类；“更合理的实现”仍保留与需求不贴合的事实。

合理查找后无入口可用“阻塞”并在原因明确写“目前没有发现入口”；实测确认占位或未开放可记“已执行-存在差异”，描述“测下来没有实现”，分类为开发状态/实现差异，不能仅因此自动登记bug。只有部分动作可做时，逐检查点保留未验证状态。

判断依据依次写清用户明确期望、当前产品公开说明、有效版本需求、历史/待评审需求、一般合理预期。根据一般预期提出的问题也可列为疑似缺陷，但标明是测试推断。定位器错误、等待不足、iframe漏查和原生弹窗不可见先排除；环境故障与失败后恢复分别分析。

典型例子：未购买高级上游导致请求失败可以是环境预期；随后同一会话切回可用模型仍不能继续，是另一项恢复异常。删除进回收站与永久删除的文档不同，先标设计差异与影响，不凭一份待评审稿直接判产品错误。

差异与候选问题使用永久编号，不删撤回记录、不复用编号。保留原观察、复核和撤回原因。详见[差异与问题登记](差异与问题登记.md)、[产品特性记录](产品特性记录.md)。

## 6. 证据与变更管理

证据放`证据/<case_id>/<attempt_id>/`，文件名表达阶段。最少初态、动作序列、终态与检查点依据；可用截图、DOM文本、脱敏trace、请求响应、应用日志、独立文件内容及哈希。工具可见范围不足就记录不足，不生成模拟截图充当实测。

UI步骤经UI执行，API只做获准准备/交叉校验。若只在独立网关验证了同类接口，记“API已验证、UI阻塞”，不能把UI case标成通过。文件写入回读真实路径与内容；权限测试使用第二身份和服务端拒绝证据；被控端测试使用实际执行端或真实形态事件，静态动画不证明输入已停止。

每条证据在`证据/索引.jsonl`记录路径、case/attempt、时间、类型、能证明什么、脱敏状态及SHA256。创建/安装/更改配置记[变更清单](变更清单.md)，包括归属、原值、恢复动作及遗留。只清理明确本轮样本；不为清理触发禁止操作。

## 7. 进度、续跑与最终审核

运行 `node tools/progress.cjs`（在本任务目录）查看逐状态进度与结构问题。它只核对台账，不操作软件，也不判断业务正确性。无需重新运行生成脚本；生成脚本重建用例，会保留已有逐条结果。

每批结束更新进度、覆盖地图及变更清单。中断时交接当前页面、进程/端口归属、最后case、等待中的任务、故障会话和下一队列。恢复先读台账和现场，再继续未执行/阻塞/待复核项。

最终使用[总结与审核](总结与审核.md)填全量状态统计、模块验证深度、差异候选、已知限制及未完成项。由负责审核的Agent独立检查来源、结果证据、分类和补证，再由用户确认；涉及重大分歧共同决定。两方意见、时间、批准范围与入库位置都留档。未完成双方审核的内容继续保存在此目录，不搬入正式产品知识、缺陷库或测试规范。
