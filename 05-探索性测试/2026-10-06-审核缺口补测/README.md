# 审核缺口补测：Agent从这里开始

完成本任务 **59条case、108项断言**。这轮只补旧轮的证据与判据缺口，不重跑整份140条。旧轮结果和疑似问题不要改；完成后由root和用户审核，再合并两次结果。

## 按顺序读，按顺序做

1. 读本页和[补测操作规则](补测操作规则.md)：知道遇到失败怎么继续、哪些不能做。
2. 读[场景安排](场景安排.md)：按共享场景准备样本和执行，避免逐条重新导入。
3. 操作软件前，读仓库[接入指南](../../02-测试方法与技术参考/测试接入与执行指南.md)；启动/重连看[启动实操](../../02-测试方法与技术参考/portable-agent-exe-ui-api-guide.md)。读[探索技能](../../skills/exploratory-testing/SKILL.md)及[出错后怎么做](../../skills/exploratory-testing/references/retest.md)。使用本机实际安装路径、端口、已有项目和标准/low，不照抄旧机器路径。
4. 生成本轮唯一后缀样本。读[夹具准备](扩展场景与夹具.md)，运行 `python -X utf8 tools/prepare-fixtures.py --run <本轮唯一后缀>`。不要导入旧轮已安装对象来测试首次导入。
5. 读[补测清单](补测清单.md)：每条已经写出原问题、正确步骤和断言。`用例/cases.json`是59条执行队列，不能改它求通过。
   开始前运行 `node tools/check-task.cjs`，确认队列、来源和140条合并映射完整；这不代表软件测试通过。
6. 读[函数调用与代码留存](函数调用与代码留存.md)和[结果格式](结果格式.md)。软件操作通过business函数，接入/定位/读取放automation；已有能力先复用，缺的再补写。catalog初始为空，不代表已有可调用函数。
7. 执行并写本轮环境、上下文、日志及结果。运行 `node tools/progress.cjs` 检查记录和代码关联；**校验通过不代表业务全部通过**。

## 本轮交付

- `结果/<原case_id>.json`：59份最新结果，contract_version为`retest-1.0`；通过/失败/不确定，不能留下未执行。不确定允许，但须有实际尝试和精确原因。
- `结果/历史/<case_id>/<attempt_id>.json`：有重试时保留早先attempt；只在取得新执行结果后更新该case最新文件，原日志不覆盖。
- `运行日志/`：本轮实际动作/读取，限定目标frame、菜单、消息、控件或文件。每个actual关联read事件；null也记录尝试原因。
- 代码、调用及版本快照按函数留存契约保存；按需截图，通过默认不截图。
- `补测报告.md`：59条完成统计、差异候选、仍未验证的具体动作、恢复与残留。每条notes注明旧轮问题如何处理、新证据在哪里。

所有必跑项实际尝试完后结束，释放UI，不继续跑旧轮75条已认可用例，也不安装市场样本或探测缺对端连接器。恢复失败明确报告，不能写“无遗留”。

## 哪些结果会合并

59条原case ID保留，另外81条沿用原结果与审核证据。其中75条已认可通过；6条有直接证据的差异候选（含记忆/沉淀实机补充）无需重复。映射在[来源与合并映射.json](来源与合并映射.json)，具体合并方式见[合并说明](合并说明.md)。你只交付补测，不修改旧结果或生成最终通过结论。
