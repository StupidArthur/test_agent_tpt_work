# Test Agent 探索性测试规则（待审核草案）

来源：2026-10-05 TPT Work 探索阶段。这里沉淀可复用的测试方法；具体模型、端口、登录规则和产品数量以当轮环境及产品记录为准。

## 0. 探索产出先审核，再入正式知识库

所有探索产出先进入根目录“探索性测试”的对应批次，包括产品特性总结、疑似缺陷、方法论及操作指南补充。Agent 的复现和验证只是证据，不等于审核通过。未经用户或指定审核者批准，不将内容合并到正式产品资料或测试规范。记录审核者、日期、具体批准范围和入库位置；保留被驳回、撤回及部分通过的历史。

## 1. 先建立覆盖地图，再逐项增加深度

按导航、设置分类及进入后的一级入口建立待测队列。第一轮先遍历入口、主要控件与空状态；第二轮验证典型业务闭环；第三轮按风险检查失败、恢复和状态切换。一个模块出现问题时，保存证据并安排复核，不无限深挖而遗漏其它模块。

每项保留以下信息：入口、前置条件、已执行动作、证据、验证深度、当前结果、下一步。结果可标为通过、失败、候选异常、环境受限、未执行。没有数据可测、只查看菜单、跳过操作，都不能写成业务通过。

| 验证深度 | 可以支持的结论 |
|---|---|
| 入口可见 | 找得到入口 |
| 可进入或展开 | 页面或菜单能打开 |
| 操作有反馈 | 输入、筛选或导航得到预期反馈 |
| 业务闭环 | 操作结果正确，数据或回复与请求对应 |
| 恢复与持续使用 | 失败后可继续，重复操作不串扰 |

## 2. 同时测试正常路径和失败后的恢复

测试对象包括状态转换。对有外部依赖的功能，至少考虑“成功 → 失败 → 修正或降级 → 再次成功”。检查旧请求是否残留、后续操作是否可用、结果是否混入失败轮次。

本轮高级模型的上游未购买，调用失败符合环境条件；同一会话切回可用模型仍无法正常继续，则是另一项恢复问题。不能用“上游不可用”解释所有后续异常，也不能用新会话成功代替同会话恢复验证。

## 3. 用例外异常也进入测试证据链

凡是不符合明确说明、前后状态或合理用户预期的现象，都先记录候选异常。记录预期依据：用户确认、产品说明、既有成功对照，或待澄清的常规预期。用例未覆盖不是忽略异常的理由。

先记录触发序列和现场，再做最小对照：同一状态与干净状态、同一会话与新会话、同类正常入口与异常入口。尽量只改变一个因素。复核结果不一致时保留各次结果，不挑选一次结果作为最终结论。

候选可以转为确认、环境限制、预期行为或无法复现。撤回时保留原编号、撤回理由与证据，不删除历史或复用编号。本轮手输草稿与快捷提示对照表明项目切换保留未发送草稿可能是正常行为，不能继续按确定缺陷报告。

## 4. 先核对自动化观察范围，再判产品行为

UI 自动化失败与产品失败分别判断：

- 核对当前页面、frame、可见性、定位匹配数和遮挡。插件内容可能在 iframe 内；外层正文不含插件文字不能证明页面空白。
- 重名控件和隐藏副本需要限定容器，并核对唯一性；按钮中的图标 alt 文本也可能改变可访问名称。定位超时不直接登记为产品缺陷，不默认使用强制点击绕过。
- 页面内没有 dialog 不能证明没有原生 Windows 弹窗。出现遮挡或工具看不到的交互时，确认现场后再操作。
- 同一稳定界面上、已确认不会改变后续控件的操作可顺序批处理。提交、导航、打开弹窗或内容变化后，等待结果并重新观察，再决定下一组动作。

## 5. 等待业务状态，不用固定延时证明完成

优先等待可观察条件：加载标识消失、目标编辑器出现、按钮恢复、成功或错误终态、回复对应本轮标记。设置合理截止时间；超时记录为未完成或待查，保留当前状态。

固定等待一秒只能证明“一秒时看到什么”，不能证明功能最终失败。若重新进入页面、等待后仍报错，可增强复现证据；仍不能仅凭错误文本判定内部根因。

## 6. 管理测试状态和操作副作用

每轮明确账号、项目、会话、模型、权限、草稿与已有数据。保留一个已知可用的对照路径；故障会话不要作为后续可用性的唯一依据。需要判断恢复问题时保留故障会话，并用新会话辅助对照。

点击前按实际效果判断动作：浏览、临时输入、持久更改、对外提交或不可逆操作。卡片标题可能直接安装，不能因看起来像“详情入口”就假定只读。通过明确详情按钮进入；语义不清时先检查控件和提示。

维护本轮变更清单，记录创建、安装、配置及当前状态。误触后先记录影响，再按既有授权处理；恢复涉及不可逆删除且未获授权时，保留现场并说明待处理项。只清理归属明确的本轮数据。

## 7. 把证据、结论和产品知识分别维护

- 操作记录保存时间、版本/包身份、前置条件、动作序列、页面原文、等待条件、实际结果及必要截图。
- 缺陷记录保存预期依据、影响、复核结果、环境因素、未知项与当前状态；将现象和根因假设分开。
- 产品索引保存当前经过验证的行为，并链接原始证据；数量、默认值、登录与路由规则注明观察日期，变化时追加来源。
- API 或测试网关结果与真实 UI 结果各自保留：接口成功不能代替用户路径通过，页面显示成功也不能证明实际路由正确。

不记录具体密钥和不必要的个人数据。报告须说明哪些已验证、哪些仅浏览、哪些受环境或操作限制，避免把“全部入口已走过”写成“所有功能正常”。

## 8. 持续探索与停止交接

用户要求持续探索时，维护待测队列并持续执行，每批完成后推进下一项；进度汇报不表示结束。用户明确停止后立即停止产品操作，将已取得的证据收尾并暂停任务。

交接写清当前页面、待测项、候选异常、遗留测试数据和待授权清理动作。继续执行时先重新确认运行态，不能依赖上一次截图或历史默认值。

## TPT Work 本轮执行边界

本轮使用 Playwright 连接 Electron CDP，探索性对话使用标准模型 low；选择已有项目，避开本地文件/目录弹窗，不新建项目、不删除记忆。上述边界来自本轮用户要求，不自动扩展为其它产品的永久限制。
