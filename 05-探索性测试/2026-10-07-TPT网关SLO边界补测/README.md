# TPT 网关短请求 SLO 边界补测（待审）

来源：用户 2026-10-07 下发的补测需求单（见 `需求单.md`）。目标是把“可用并发边界”从上一轮 800 无报错 / 200～400 模糊区间，收敛到**指定 SLO 下可重复验证**的档位，并定位 1600 档 500/503 的根因归属，同时采集服务端实际并发。

## 范围与不变式

- 只评估网关 API（测试机 → 网关 → 上游）。不测 UI、登录、设置。
- 沿用上一轮：`flash`、`think_level=low`、Chat Completions 流式、同一提示、独立连接、无重试、批次排空后再升档。
- 短请求输出上限 128 token；长请求对照输出上限 512 token，输入约 2048 token。
- 每档之间等待 30 秒让服务端排队清空。
- 记录每档精确起止时间（UTC + 北京时间），用于事后对照服务端日志。

## SLO 判据（本轮统一）

| 等级 | 完整响应 P95 | 成功率 |
|---|---:|---:|
| 严格线 | < 5s | ≥ 99.5% |
| 宽松线 | < 10s | ≥ 99.5% |

同时记录 TTFT（首正文）P95/P99；短请求下 TTFT 与完整响应接近，不作主要判据。

## 本轮结果（待审）

- 请求总数 **15823**，09:52～10:30（UTC，即北京时间 17:52～18:30）分三批完成；失败 4322，失败集中 1600 档。
- **延迟边界**：严格线 P95<5s 收敛到 **(100, 125)**；宽松线 P95<10s 收敛到 **(240, 250)**。需求单原设 200～800 搜索区间位于真实边界之上，故本轮下探补档。
- **成功率口径**：每档都有个位数 `ClientConnectorError`（与并发不呈比例）。字面口径（含客户端连接失败）下 100～240 档有轮次 <99.5%，故无档全轮满足完整 SLO；剔除未取得 HTTP 状态的请求后，100～600 各档服务端成功率均为 100%，边界完全由延迟决定。
- **1600 档**：3 次均严重不完整（完整率 7%～19%），失败全为客户端连接类错误，**未复现**上一轮 nginx 500 / channel 503；500/503 根因仍未确认。
- **长请求对照**：长请求 100 档 P95（19.6～24.8s）已超过短请求 400 档（约 14.7s），短请求结论不可外推。
- **测试 C**：无服务端采集通道，仅交付时间窗口清单（报告第 7 节）。

状态：待审。不自动转成产品缺陷。结论强度不超过证据强度：边界为有限档位、每档 3 次的可重复观测，非服务端精确并发上限。
