# 补测需求单：TPT 网关短请求 SLO 边界收敛

> 用户于 2026-10-07 下发。原文保留，作为本轮执行依据。

## 一、总体目标

1. 找到在指定 SLO 下，**可重复验证的可用并发数**。
2. 定位 1600 档 HTTP 500 / 503 的**根因归属**（网关侧 vs 模型侧）。
3. 采集**服务端实际活跃请求数**，建立“客户端并发 → 服务端并发”的映射关系。

## 二、SLO 判据（本次测试统一使用）

| 等级 | 完整响应 P95 | 成功率 | 用途 |
|---|---:|---:|---|
| 严格线 | < 5s | ≥ 99.5% | 交互式场景可用边界 |
| 宽松线 | < 10s | ≥ 99.5% | 可接受场景可用边界 |

同时记录 TTFT（首正文延迟）P95 / P99，但本轮短请求下 TTFT 与完整响应接近，不作为主要判据。

## 三、测试项

### 测试 A：中间档位补测（核心）

- 档位：250、300、350、400、500、600
- 每档重复 3 次
- 每档请求数 = 并发数，全部并发启动
- 负载与上一轮一致（同提示、同模型、同 think_level=low、同 128 token 上限、流式）
- 记录：每档每次的完整成功数、失败数、平均/P50/P95/P99/最大延迟、批次总耗时

判定：
- 某档 3 次中 ≥2 次 P95 突破 5s → 严格线拐点候选
- 某档 3 次中 ≥2 次 P95 突破 10s → 宽松线拐点候选
- 拐点候选确定后，前后各补 1 档确认边界

### 测试 B：1600 档重复验证

- 档位 1600，重复 3 次
- 记录 HTTP 500 / 503 / 连接失败 / 完整成功分类
- 每次失败后等待 30 秒做一次单请求恢复检查，记录恢复时间

判定：3 次均出现 500/503 → 失败稳定，需定位根因；仅部分出现 → 可能偶发。

### 测试 C：服务端并发采集（关键）

同步采集：nginx access log（请求数、upstream 响应时间、upstream 状态码）、通道服务（活跃连接数、排队数、通道健康）。无法采集时至少记录每档起止时刻，供事后对照日志。

### 测试 D：长请求对照测（可选，强烈建议）

- 档位 50、100、200
- 负载：长输入（约 2048 token）+ 长输出（约 512 token），其余配置相同
- 每档重复 2 次

判定：若长请求下 100 档 P95 已远超短请求 400 档，说明短请求容量结论不可外推。

## 四、执行约束

1. 每档之间间隔 30 秒。
2. 失败请求不重试，如实记录。
3. 不修改网关任何配置。
4. 保留原始响应（SSE 压缩包 + 哈希）。
5. 记录每档精确起止时间戳（UTC + 北京时间）。

## 五、交付物

1. 补测报告（Markdown）：每档每轮数据表、严格/宽松拐点判定、1600 档 3 次失败分类对比、服务端采集结果或说明、长请求对照。
2. 原始数据文件：与上一轮 `wave-*.json` 同格式。
3. 时间窗口清单。
4. 失败详情，格式同 `failure-details.json`。

## 六、明确不做

- 不做 2501 档。
- 不做配置调优。
- 不给出“最大支持多少用户”的结论（只给 SLO 边界和并发数）。
