# TPT Work 冒烟测试入口

**交给PC-88执行：12条用例、30项断言、3次短模型请求。** 用例已获用户认可；本机尚未执行。PC-88作为独立短任务完成全部12条，再交付报告；本机和PC-G分别继续原任务。

PC-88拉取最新main，以实际仓库根目录为工作目录，读本页后开始；无需在第几个checkpoint再询问是否继续。没有登录态时由用户预先配置账号，本任务不从其他机器的历史日志提取密码。安装、登录或项目条件确实缺失时，报告具体缺失条件，不伪造执行结果。

用途：换包、重启或正式回归前，快速检查核心路径是否可用。全部必测项通过且恢复核验成功才记“冒烟通过”；失败或未验证都不能给绿灯。通过不代表完整功能回归已通过。

## 执行顺序

1. 仅使用PC-88本机的空闲实例。读[接入指南](../../02-测试方法与技术参考/测试接入与执行指南.md)，通过Electron CDP+Playwright操作；核验本机真实安装路径、端口、页面、包哈希和已有登录态。已有项目名/路径不必与其他机器相同，不在本轮重新测试登录机制。
2. 读[探索技能](../../skills/exploratory-testing/SKILL.md)及[出错后怎么做](../../skills/exploratory-testing/references/retest.md)。选择已有项目、标准/low，不添加项目，不删除记忆，不操作原生不可控窗口。
3. 运行 `python -X utf8 tools/prepare-fixtures.py --run <本次唯一ASCII后缀>`。样本和独立预期在`夹具/本轮/<后缀>/`；执行前确认对应技能/专家内部身份未安装。记录样本哈希。
   `smoke-draft-check-20261006`只是编写时生成并校验的样本，没有导入软件；实际执行另用唯一后缀。
4. 按[用例](用例.md)执行，机器可读契约在`用例/cases.json`。同一场景共享日志；导航后重新观察。使用已审核可用的业务函数，缺能力再补写，保存实际使用代码。不要照搬旧轮整组驱动脚本。
5. 按仓库[记录契约](../../skills/exploratory-testing/references/records.md)记录每条actual、动作、读引用、环境、结果和恢复。结果放本目录按本次run分开的运行目录，不能覆盖其他轮。
   使用PC-88独有run，例如`pc88-20261006-smoke01`。运行目录、环境记录、夹具索引都写machine_id=PC-88；不用本机或PC-G的绝对路径、PID、运行上下文及读事件。

## 怎么判

- 每个必要断言成立：通过；已实际操作且可靠值不符：失败；读不到或前置没成功：未验证，并写缺哪一步。
- 一条失败不阻止独立场景继续；依赖该失败的下游不假装执行成功。环境不可恢复时记录剩余未验证，报告停止原因。
- SM-12收尾始终尽力执行，前面失败也要核验实际已发生的改动；无法恢复时明确列残留，不能因依赖失败跳过清理。
- 读取助手本轮最终回复，不能从用户请求或旧消息找标记。技能/专家请求不包含目标回复标记，预期由生成的样本提供。
- 调用项验证选中身份及实际行为效果，不把这些证据称为完整上下文注入证明。
- 通过默认不截图，保留真实值及日志；异常截图按解释价值采集。失败日志保留，最多一次有依据的定位修正。

## 范围

覆盖：接入、新任务与项目、标准/low对话、附件、技能导入/搜索/开关/使用、专家导入/使用、设置与快捷键入口、主题效果及恢复。

不纳入：高级模型、市场、连接器对端、数据资产、用户体系、长时执行、坏包边界、故障注入。记忆/沉淀已有保存失败候选，不在这份短集里重复展开；这些问题仍在原审核中保留。

## 交付

`运行/<run>/`保留环境与样本索引、12条结果、操作/读取日志、代码版本和`报告.md`。报告分别列通过/失败/未验证、整体冒烟结论及残留。本次样本只停用/保留待审，不删除用户资产；结果仍待双方审核。

本批全部实际尝试并完成恢复后即可结束。报告给出准确路径和12条逐项状态，供root验收；不继续执行另两台机器的任务，也不自行扩大为140条回归。
