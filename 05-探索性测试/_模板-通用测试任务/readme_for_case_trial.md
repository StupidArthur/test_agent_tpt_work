## 本模式的双重目标（同时完成，互不冲突）

1. **产品测试**：严格执行原始用例，独立记录产品真实行为、预期差异、未观测断言及证据；用例预期不自动视为产品正确规范。
2. **用例验证**：判断每条用例的目标明确性、前置完整性、操作可执行性、断言有效性、可复现性、恢复完整性，以及已有工具能否真实支撑关键操作和读取。

执行前冻结 `测试用例.md` 的原始版本和编号。发现用例不合理、断言不清、样本缺失或工具问题时，**保留原始用例、失败现场及尝试**，另记候选归因与修订建议；如需验证修订方案，另存修订版本并留对应补测 attempt，不将修订后通过回填原用例。

产品不符合原始预期**不自动**代表用例不合格；产品全部符合预期也**不自动**代表用例能入库。产品缺陷、用例问题、环境/工具问题均只给出有证据的初步分类，最终由用户或指定审核者判断。

## 交付

- 执行后创建 `测试报告.md`：产品真实表现、各断言与证据、候选异常/缺陷、未验证项。
- 执行后创建 `用例评估.md`：逐条列用例问题、证据、修订建议及**建议入库 / 修订后建议入库 / 暂不建议入库 / 证据不足**。
- 记录恢复情况；入库审核结果默认待审核，**未经批准不写入 `02-测试项/`**。

## 执行入口与完成标准

先读 [通用测试技能](../../03-测试技能/exploratory-testing/SKILL.md)；测试 TPT Work 且需要启动、连接或确认 UI/API 通道时再读 [TPT Work 接入技能](../../03-测试技能/tpt-work-access/SKILL.md)，已接入则按本轮通道直接查工具或执行代码。根 [AGENTS.md](../../AGENTS.md) 的客观判定、工具复用和审核边界适用；记录字段不清时查 [记录契约](../../03-测试技能/exploratory-testing/references/records.md)，发生异常时查 [补测方法](../../03-测试技能/exploratory-testing/references/retest.md)。

完成本轮队列、逐条记录判据与实际值并核验恢复后交付。缺条件的项写明限制与补测条件，继续其他项；报告区分实际尝试、断言已观测与未验证，注明残留和待审核状态。产物留本任务目录。
