# DeepSeek 直连并发限额验证

本任务由用户要求验证 deepseek-flash 官方 2500 并发上限及超限报错。只测 DeepSeek 官方 API，不测 TPT 网关或软件 UI。

## 方法与边界

- 目标：既有配置 `deepseek-flash-low`，凭据只在内存读取，不输出。
- 使用 aiohttp 异步客户端，独立连接池，正常消费流式响应，不故意慢读、不重试、不更换身份绕过限流。
- 已启动队列：10、100、500、2501 请求，各轮全部结束后再发下一轮。共最多 3111 次，每次最大输出 1024 token，单请求总超时 180 秒。
- 按官方峰时输出单价 $1.2/百万 token，全部输出达到上限时输出费用约 $3.83，另加短提示输入费用；实际费用以 usage 与账单为准。
- `client_pending_peak` 包括连接准备，不能视为服务端并发。`http200_unfinished_peak` 是客户端已收到 200、尚未读完响应的重叠数，也不能精准代替服务端内部计数。429 原文提供服务端当时计数/限额时单独记录。
- HTTP 200 与 SSE `[DONE]` 分别检查；请求/连接超时按客户端限制记，不算服务端 429。

## 交付

`wave-*.json` 保存每次请求时间、HTTP 状态、usage、错误原文和响应哈希；`responses/` 保存原始响应。`evidence-index.json` 登记文件哈希。报告保持待审，不自动升级为产品缺陷。

官方依据：[并发限速](https://api-docs.deepseek.com/zh-cn/quick_start/rate_limit/)、[价格](https://api-docs.deepseek.com/quick_start/pricing/)，2026-10-07 查阅。公开文档说明账号级默认 2500，超限 HTTP 429。

## 本轮重要限制

500 请求轮已出现余额关联限流：错误提示当时限额为 225。最后一轮在检查前已自动发出，待其排空后停止，不追加冲击。当前账号不满足验证默认 2500 的前置条件。
