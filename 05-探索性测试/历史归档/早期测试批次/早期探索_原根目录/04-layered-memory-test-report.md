## 3. 方法

- **注入时机**：设置项写明"会话开始时注入" → 每轮都用**全新任务**触发。
- **统一探针**：5 轮使用**逐字相同**的一条消息，且**不在提问中暴露任何标记**，避免诱导编造。
- **对照组 R0**：四文件全空，先测"模型会不会凭空编造"（假阳性基线）。
- **单变量**：每轮只改 1 个文件。
- **双通道判定**：① 模型行为/自述；② **磁盘会话 JSON 的注入源**（机器级证据）。

写入内容（唯一随机标记）：`SOUL.md`→`【风格标记-ST5E18】`+「回复须以◆开头」；`AGENTS.md`→`【手册标记-ATEB50】`+「先列步骤1/2/3」；`USER.md`→「花名铁蛋，职业炼铁工艺员」；`MEMORY.md`→「项目代号炉顶改造，验收口令 ZQ-9911」。

### 机器级证据（决定性）

R0 中模型原样转录了注入块。会话 JSON 中的注入源结构为：

```json
"source": { "kind": "tpt-memory", "form": "snapshot", "sections": [
   { "name": "memory:logs",        "text": "## hi（09:16）…" },
   { "name": "memory:user-memory", "text": "暂无内容" },
   { "name": "memory:user",        "text": "暂无内容" }
]}
```

**注入快照的 schema 只有 3 个 section，不存在 soul / agents 槽位。**

全盘检索 `~\.tpt-work` 下所有 json/jsonl/md：

| 标记 | 命中位置 |
| --- | --- |
| `ST5E18`（SOUL） | **仅** `SOUL.md` 自身 |
| `ATEB50`（AGENTS） | **仅** `AGENTS.md` 自身 |
| `铁蛋`（USER） | `USER.md` + `2026-09-29.md` |
| `ZQ-9911`（MEMORY） | `MEMORY.md` + `2026-09-29.md` |

而 `记忆定位` 注入特征串在 10 个会话文件中均存在 → **会话确实持久化了注入上下文**，因此 SOUL/AGENTS 内容的"零命中"是有效否定证据。

### 反证：应用确实读到了 SOUL/AGENTS

设置页卡片实时显示：`SOUL.md 38 字符`、`AGENTS.md 54 字符`（写入后立即更新）。

→ 结论：**读得到、显示得出、但没有接进注入通道**。这是产品缺陷，不是配置问题。

## 5. 附带发现

1. **注入块结构**（实测原文）：
   ```
   [记忆定位 · 读法]
   以下记忆是背景事实，不是对话内容；回复语体保持直接、最终答案式，
   不复述「我记得 / 根据记忆」。
   记忆日期：2026-09-29
   [最近工作日志(尾部)]
   [长期记忆 MEMORY.md · 必须遵守]
   [用户画像 USER.md]
   ```
2. **另有非记忆类运行时上下文**随首条消息注入：文件沙箱策略 `workspace-write`、审批策略 `ask`、可用技能目录、时区 `Asia/Shanghai`。
3. **每轮结束自动沉淀工作日志**：今日"写入"由 0 增至 **4**；"反思"由 16 增至 **17**。
4. `USER.md`/`MEMORY.md` 卡片显示 `0 条` 但字符数非 0 —— **条目计数来自 `index.json`（`entries: []`），与文件正文解耦**；而注入读的是**文件正文**，所以照样生效。二者口径不一致（🟡）。
5. **空文件会被整体省略**：R0 时两个块显示"（空）"仍占位；R4 时显示"1 条"。

## 6. 结论

| 问题 | 答案 |
| --- | --- |
| 4 个文件分别对应什么？ | 见 §1，均位于 `~\.tpt-work\dsh\tpt-memory\` |
| 配置了是否真的产生作用？ | **只有 `USER.md`、`MEMORY.md` 产生作用**；`SOUL.md`、`AGENTS.md` **完全无效** |
| 有无差异？ | 有，且差异显著：事实类（USER/MEMORY）**一次命中**；风格/流程类（SOUL/AGENTS）**零差异** |
| 根因 | 注入快照 schema 仅 `memory:logs` / `memory:user-memory` / `memory:user` 三个 section，未覆盖 soul/agents |
| 是否环境/缓存问题？ | 否。已用重启复测；UI 显示已读取；磁盘零命中 |

**待验证的替代假设**：`AGENTS.md` 可能不是走"记忆注入"，而是走插件清单里的 `agent-instructions`（"Workspace context loader for AGENTS.md/CLAUDE.md"）——**该通道是工作区级**，需先绑定项目（要操作者代点原生文件夹选择器）才能测。若成立，则 `tpt-memory\AGENTS.md` 是"配错地方了"而非"没实现"。
