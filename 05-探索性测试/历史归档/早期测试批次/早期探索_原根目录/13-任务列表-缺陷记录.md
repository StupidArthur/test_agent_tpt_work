## BUG-1 · 「分享任务」点了完全无反应（死按钮）

**定级：P2**（功能不可用 · 误导性入口 · 不阻断主流程）

### 需求文档描述

`app.asar` 内嵌的产品设计规格中，会话行 `⋯` 菜单的条目清单为：

> 「**Pin、Rename、Fork、Archive** 本身就是 `sidebar.workspaces.session.menu.item` 列表的条目（pin 与 archive 同时也是 `sidebar.workspaces.session.row.action` 的条目）」

→ **规格清单里没有「分享任务」这一项。** 它是 TPT 侧栏自行增加的条目（TPT 改版产物），且无配套规格。

### 复现步骤

1. 侧栏「任务」tab → 悬停任意会话行
2. 行尾出现 2 个按钮，点右侧 `⋯`（`aria-label="会话"<标题>"的操作"`）
3. 菜单弹出 5 项：`重命名 / 在资源管理器中打开 / 标记为未读 / 分享任务 / 归档`
4. 点 `分享任务`
5. 重复 3 次

辅助定位：因 `⋯` 是无文字图标按钮，新增 `cdp.mjs clickaria <aria片段>` 精确点击，排除"点偏"因素。

### 实际结果

点击**确实被接收**（菜单关闭），但除菜单关闭外**零效果**：

| 观察通道 | 结果 |
| --- | --- |
| DOM 变更（MutationObserver 全程监听 addedNodes） | **无任何新增节点** |
| console.error / console.warn（挂钩监听） | **无输出** |
| fetch / XMLHttpRequest / WebSocket（挂钩监听） | **无任何请求** |
| 剪贴板（`Get-Clipboard`） | **未变化**（前后同为 45 字符、非 URL） |
| CDP targets（`/json/list`） | **无新窗口/页面** |
| 应用内弹窗 / toast | **无** |

对照：同菜单其它项均有明确反应 —— `重命名` 弹模态框、`标记为未读` 出绿点、`归档` 行使消失。

### 影响与建议

- **影响**：用户点「分享任务」得不到任何反馈 —— 既没成功提示也没失败提示，会误认为"点了但没生效"，反复点击。属于**哑入口**。
- **建议**：
  1. 若功能未实现 → **隐藏该项**（与规格清单对齐：Pin/Rename/Fork/Archive）或置为 disabled 并给出原因；
  2. 若已实现 → 至少给出成功/失败提示（toast），失败时说明原因。
- **保留的不确定性**（诚实标注）：本结论覆盖**渲染进程**三个通道（DOM / console / 网络）与剪贴板、窗口。**不排除主进程侧存在静默 IPC 副作用**（CDP 未挂钩 IPC）。但"用户完全看不到任何反馈"这一点是确定的。

## BUG-2 · 归档成功后缺少「撤销 / 筛选已归档会话」提示（**待复现**）

**定级：P2（待定）**

### 需求文档描述

`app.asar` 内嵌规格原文：

> 「**归档成功后的提示提供"撤销"动作，并在归档行仍被隐藏时附带"筛选已归档会话"动作**，后者直接把筛选切到全部对话（显示已归档）；停止并归档显示同样的提示但措辞不同，撤销只恢复 Session，不会让被停止的工作继续。」

同段还写明视图选项为**三选一**：

> 「视图选项以一组显式三选一控制显隐：**隐藏已归档**（默认项）/ **全部对话（显示已归档）** / **仅显示已归档**」
> 「仅显示已归档视图用自己的文案（**暂无已归档会话**），并附**查看其他会话**文字按钮」

### 复现步骤（待执行）

1. 侧栏「任务」tab → 悬停某会话行 → `⋯` → `归档`
2. 点击后**立即**连拍：0s / 0.3s / 1s / 2s / 3s（用 `install-hook.js` 的 MutationObserver 兜底抓 toast，即使一闪而过也能捕获）

### 已完成的部分观察

- 归档**无二次确认框**，直接生效（⚠️ 但这条**符合规格**：规格明写"对静止的 Session，Archive 不经过确认对话框直接提交"，**不作为缺陷**）
- 点击后 2 秒截图**未见任何 toast**（`283-arch-t0.png` / `284-arch-t1.png`）
- **不足以定性**：第 1 次未连拍、可能已自动消失；第 2 次归档**未点中**（行数未变）

### 待查的关联项

- 「视图选项」三选一的**入口尚未找到**：侧栏「排序方式」菜单实测只有 `排序方式` 标题 + `最近更新` / `手动排序` 两项，**无筛选项**
- 出处 `dsh.workspace.view.v5.archivedFilter` 的取值 `default`（另有 `show` / `only` 两态）**无 UI 可改** → 需确认是否有入口

### 已确认可用的归档回收路径（非缺陷）

- **账号菜单 → 「已归档会话」** → 模态框（搜索框 + 列表 + `取消归档`）
- 证据：`285-archived-page.png`

## BUG-3 · 「标记为未读」圆点消失/重现规律不明（**待复现**）

**定级：P3（待定）**

### 需求文档描述

`app.asar` 内嵌规格原文：

> 「『New task completed』未读标记是**本地查看状态**：完成时间 > 上次查看时间这一事实永远不会到达宿主」
> 「台账真身在 `@tpt-work/sidebar` 那份持久化的 `unread` 字段里」

→ 即：**未读 = 一次性事件**，打开会话应清除；且**台账是唯一真值源**。

### 实际观察（含我的操作史，需重测以排除我自己的干扰）

1. `⋯` → `标记为未读` → 行尾出现绿点 + 文本 `未读：空闲`，落盘 `tpt.sidebar.regions.unread` 增加该 id ✅
2. 再点一次 `标记为未读` → **不清除**（菜单项文字也**不变成**「标记为已读」）
3. 点该行（打开会话）→ **圆点清除** ✅
4. 之后**圆点又出现**，但此刻落盘台账 `unread` 与界面**仍然一致** → 无法归因
5. 全程**落盘台账与界面圆点始终一致**（未发现"两个真值源"矛盾）

### 待复现步骤

1. 标记未读 → 等 5s / 30s 各查一次（中途不点任何东西）
2. 展开全部会话、切换 tab、折叠分组后各查一次
3. 重启应用后查一次（验证 `unread` 是否持久化存活）
4. 每次同时记录：界面圆点 + `localStorage["tpt.sidebar.regions"].unread`

### 初步判断

**倾向不是缺陷**（台账与界面一致）。第 4 步的现象我怀疑是自己误点造成的，**不写成缺陷**。
