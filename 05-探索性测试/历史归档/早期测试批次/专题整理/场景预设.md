# 场景预设：对照结果与选型边界

场景预设决定 Agent 的工作方式；权限与模型需要另行记录。这里合并的是历史对照，不是对所有题目和版本的性能排名。

## 同一目录求和题的五模式观察

| 模式 | 原记录结果 | 时间 / token / 步骤 | 可以得出的结论 |
|---|---|---|---|
| standard | 正确 | 26 秒 / 65.5K / 5 | 当时以 pwsh 完成 |
| ptc | 正确 | 16 秒 / 53.7K / 3 | 生效后以 run_code 完成；第一次设置未实际生效需单列 |
| minimal | 失败 | 约 2 分 25 秒；18 次 PTY shell 失败 | 该环境工具不可用；涉及 runtime 重命名 EPERM，不能扩大为所有 minimal 安装失败 |
| cordis | 正确 | 30 秒 / 61.3K / 4 | 完成求和；没有验证其插件创建能力 |
| factory（自定义） | 正确 | 22 秒 / 51.6K / 3 | 格式符合本次观察；不是通用内置模式 |

来源：[五模式实测](../%E6%97%A9%E6%9C%9F%E6%8E%A2%E7%B4%A2_%E5%8E%9F%E6%A0%B9%E7%9B%AE%E5%BD%95/09-%E5%9C%BA%E6%99%AF%E9%A2%84%E8%AE%BE-5%E6%A8%A1%E5%BC%8F%E5%AE%9E%E6%B5%8B%E5%AF%B9%E6%AF%94.md)。数字按原记录保存，不据此估算未来耗时或成本。

## 定向题如何改变结论

定向测试为 2026-09-29 15:07—15:19，使用 deepseek-v4.1-flash、workspace-write。配置检查题使用人工创建的 8 个文件（schema 与 7 个输入），预置 5 个异常：PTC 与 standard 均检出 5/5。PTC 为 124K、86 秒、6 步；standard 为 175K、56 秒、9 步，后者还生成可复用 Python 产物。PTC 在这题 token 更少，但耗时更长；不能宣传它普遍更快。

原文“省约 41%”的表述与从 standard 的 175K 减到 124K 的基数不同；本整理只列原始数字，不沿用该降幅。单题检出全部预置异常不等于整个产品覆盖率 100%。

factory 与 standard 的工业情境输出都拒绝编造数值阈值；factory 在结构上更突出安全提示、事实、分支和禁止动作。这是文本响应对照，未执行工业控制，也未证明 factory 在所有安全情境更可靠。

来源：[定向用例验证](../%E6%97%A9%E6%9C%9F%E6%8E%A2%E7%B4%A2_%E5%8E%9F%E6%A0%B9%E7%9B%AE%E5%BD%95/11-%E5%9C%BA%E6%99%AF%E9%A2%84%E8%AE%BE-%E5%AE%9A%E5%90%91%E7%94%A8%E4%BE%8B%E9%AA%8C%E8%AF%81.md)。

## 后续选择与补测依据

可以将 PTC 的批量代码处理与 standard 的工具链作为候选方式，针对自己的任务复测时间、token、产物可复用性。当前资料不足以评价 PTC 并行、cordis 插件创建或 minimal 修复后的表现。切换预设后必须核对实际生效状态；首次 PTC 未生效是已有的测试过程事实。
