## 一之补 · ⭐ 用户体感结论（本篇最重要的观点）

> 这是从**使用者**角度给出的判断，与技术结论（第三、四节）互为印证。详解见 `03-关于用户体感功能的测试及结论.md`。

### 结论：**一半可以，一半不可以 —— 分界线是"项目文件夹放在哪个盘"**

| 你的项目文件夹在哪 | 继承到的权限 | 结果 |
| --- | --- | --- |
| **用户目录下**（`C:\Users\你\…`） | 继承给该用户**完全控制** | ✅ **正常可用** |
| **数据盘上新建的**（`D:\`、`E:\`…） | 只继承到"可修改"，**不含**所需的高权限 | ❌ **一条命令都跑不了**（S-02） |

**这不是推测**：本次测试用的 `D:\tpt-workspace\0929\p1` 与 `p2` **两个都失败**；而产品自己放任务的 `C:\Users\…\.tpt-work\tasks\` **一切正常** —— 差别就在这一条。

### 分维度打分

| 维度 | 评价 |
| --- | --- |
| **作为"隔离机制"** | ✅ **实现是对的** —— 该拦的拦住、该放的放开、切换即时生效、风险确认框齐全、自带文件工具也受管，**未发现能硬闯的漏洞** |
| **作为"用户能用的功能"** | ❌ **不合格** —— 最常见的建文件夹方式（数据盘）直接不可用；自带诊断也救不了，还给出**错误**建议（S-02 / S-03 / S-04） |
| **作为"安全承诺"** | ⚠️ **有误导** —— `Auto review` 名字像"更安全"，实际**关掉限制**，且其审查实测**未拦住往程序安装目录写文件**（S-11） |
| **数据安全** | ⚠️ **有真实破坏路径** —— `.git` 可被改写（S-05）；硬链接会把项目外文件一起放开（S-07，**实测真删掉了项目外一个文件**） |

### 一句话（可直接对外引用）

> **"隔离逻辑本身没毛病，但它有一个静默的前置条件"** —— 项目文件夹的权限必须够，而**用户不知道、产品不提示、出错了还修不了**。这属于**"能跑通但不健壮"**：一旦踩中，就从"正常"直接掉到"完全不可用"。

### 给使用者的三句话

1. 默认用「**工作区内修改**」即可 —— **但项目要放在 `C:\Users\你的用户名\` 下面**，别放在数据盘（`D:\`、`E:\`）。
2. **「Auto review」不要当"更安全的档"用** —— 它是把限制整个关掉。
3. 如果 AI **一条命令都跑不了** → 先想到就是这个原因：**换到用户目录下的文件夹**，或请人给该文件夹加"完全控制"权限。

## 二、被测对象是什么（先说清，避免误判）

产品是 **TPT Work（DeepSeek DSH 内核）**，**不是 Codex**。它有**两根正交的轴**：

| 轴 | 取值 | 测试时值 |
| --- | --- | --- |
| **权限档位（4 档，用户可见）** | `仅可查看` / `工作区内修改` / `完全权限` / `Auto review (EXP)` | `工作区内修改` |
| **沙箱实现档位（2 档）** | **`acl`**（默认，复用上游 ACL 受限令牌）/ **`elevated`**（TPT 自有提权档：独立低权本地用户） | **`acl`** |

- 权限档位 → 逐调用模式 `read-only` / `workspace-write` / `danger-full-access`
- `acl` 档机制：`WRITE_RESTRICTED` 受限令牌 ∩ 能力 SID ACE + **Low 完整性标签**；**只限"写"**（读/网络/进程可见性不限）
- `elevated` 档需**一次 UAC setup** 安装沙箱用户，未装则 fail-closed
- 落盘：`%USERPROFILE%\.tpt-work\sandbox\home\mode.json` → `{"mode":"acl"}`

### 3.1 头号缺陷 S-02 的根因（一句话）

沙箱要把 **Low 完整性标签写进 SACL**，因而需要 **`WRITE_OWNER`**；而"目录所有者"身份**只隐式给 `READ_CONTROL` + `WRITE_DAC`**，目录默认 DACL 又只有 `Authenticated Users:(I)(M)`（Modify，不含 `WRITE_OWNER`）→ `SetNamedSecurityInfoW` 失败 → 整个工作区的受限命令不可用。
**对照**：产品自己的任务目录 `~\.tpt-work\tasks\` 给 `yuzechao:(F)` → 沙箱正常。**同一功能在两类目录下表现完全不同。**

## 八、给研发的优先修复建议

1. **S-02**：供给前预检 `WRITE_OWNER`；不满足时用 `WRITE_DAC`（我们已有）自动补一条 `(OI)(CI)F` 再写 SACL；并把报错替换成**可执行的用户指引**，而不是 `Win32 5`。
2. **S-03/S-04**：让诊断**不依赖 `icacls`**（用 Win32 API 读 DACL/SACL）；结论不要推断"所有者不是本人"。
3. **S-01**：恢复「受限执行」档位设置卡（含 `安装沙箱` / `卸载沙箱`），否则提权档形同虚设。
4. **S-11**：把 `Auto review` 的文案改为显式"**关闭沙箱**、以 LLM 逐调用审查替代"；对**程序安装目录 / 系统目录 / 其他项目**保留强制用户确认。
5. **S-05**：为工作区内的 `.git` 元数据加写保护。
6. **S-12**：提供**显式回收入口**；或在把目录纳入工作区前**告知用户"该目录安全描述符将被永久修改"**。
