# @deepseek-ai/dsh-client-ui-primitives

**这是 dsh 同名包 `@deepseek-ai/dsh-client-ui-primitives` 的 TPT 门面档（facade）：保留上游包名，`export *` 转出上游全部导出，再显式覆盖两枚品牌图形、加我方扩展名。** 本体住第 4 棵 vendor 树 [`vendor/dsh-ui-primitives`](../../../vendor/dsh-ui-primitives)（= 上游 `packages/client/ui-primitives` 的 `0.2.0-rc.1` **逐字原样**，包名 `@tpt-work/dsh-ui-primitives-vendor`）。决策依据：[`DEC-014`](../../../docs/02-architecture/DEC-014-self-authored-dsh-shared-ui-identities.md) 的 2026-09-27 块与 [`DEC-033`](../../../docs/02-architecture/DEC-033-desktop-carrier-and-patch-whitelist.md) 的篇首扩围块。

**2026-09-27 换形留痕**：本包此前是**自写等价品**（包名/导出名/props 1:1，样式与实现全是我方 shadcn / Tailwind v4 / `@base-ui/react`）。需求方当日拍板改走「上游逐字 + 差异只以 `@patch` 标记表达」，于是本包从「实现者」变成「门面档」；自写实现与 tw4 层退场，样式改由上游那份 `.module.css` 承担（类名哈希归消费方壳的 Vite）。门面里仍**自写**的只有：两枚品牌图形、83 个旧图标族名 + `SHIELD_OUTLINE_STROKE` 等扩展导出。

## 为什么按 dsh 的包名存在

dsh client 产物在模块层 `require('@deepseek-ai/dsh-client-ui-primitives')`；上游 bundle 与插件都在模块表里按 specifier 查这个名字。模块表**按名查表**，所以这个名字必须叫这个名字、必须能被解析到 —— 这条不变。

**别名口径（换形后新增，写错就绕过门面）**：工作区别名的**键不得**用上游名（用上游名当键，解析会直接落到 vendor 本体、绕过品牌覆盖与我方扩展名）；`npm:` 协议指向工作区成员 = 404。门面消费本体的方式是 `dependencies` 里的 `"@tpt-work/dsh-ui-primitives-vendor": "workspace:*"`。

**缺成员比缺包更坏**：缺包可诊断；缺成员时调用方拿到 `undefined`，当成 JSX 组件用就在渲染期崩。因此验收口径仍是 **dsh barrel 里的每个名字都必须存在**，缺一个都不算完成；反向的一半是**不许少**（我方的品牌覆盖必须真的盖住上游那两枚）。

## 承诺什么、不承诺什么

| 承诺 | 不承诺 |
| --- | --- |
| 上游 barrel 的每个导出名与种类（值 / 类型）都拿得到 —— missing 值 0 / 类型 0（判据 `check:ui-export-parity`） | 上游导出范围**之外**的内部件（`highlight` / `katex` / `render` / `ansi` / `FoldToggle` / `pointer-grace` / `use-copy-feedback` / `head-tail-cap` 等）不作为本包承诺；我方 83 个旧图标族名属于**扩展**，不保证上游后续版本也有同名 |
| 上游组件与 hook 的 props 名称、可选性、默认值、可见行为（本体逐字来自上游） | 视觉细节由上游那份 `.module.css` 与 `--dsw-*` 设计系统决定 —— 我方不再逐像素改写外观 |
| 品牌图形是**我方**的（门面显式覆盖 `FishLogo` / `BrandWordmark`，不给上游图形留活口） | 上游那两枚品牌件仍**留在 vendor 树里**（逐字原样是有意的），只是不再从门面出去 |
| `exports` 出口键与上游逐键一致（`.` / `./src/*` / `./package.json`），深路径真能解析 | 上游仓库自家测试门禁用到的内部路径不在此列 |

公开 markdown 只有五个门：`MarkdownText` / `MessageText` / `CodeBlock` / `JsonBlock` / `extractMarkdownPlainText`（+ 它们的类型）。**真语法高亮与 TeX 数学已按 dsh 同名同形落地**（两件逐字移植件，见下节）；仍在落差里的是**脚注**（`[^1]` 之类照旧成字面文本）与 **raw HTML**（一律当文本、永不进 DOM）——按 DEC-014-self-authored-dsh-shared-ui-identities 如实记为落差，不用假实现糊过去。

## 重 markdown 依赖只约束本包自写件（2026-09-27 按 D5 收窄）

**旧口径（已作废）**：本包曾逐字规定「dsh 的 barrel 静态 re-export markdown 五门、等于把 `shiki` / `@shikijs/langs` / `katex` / `mdast-util-*` / `micromark-*` / `anser` 全量背进 shell，TPT 不照抄这个缺陷」，并要求「任何重渲染依赖一律不得静态 import」。

**现口径**：需求方 2026-09-27 拍板 **markdown 走上游逐字、不做首屏体积优化**（原文「接受上游做法。不需要专门优化首屏性能」）。上游那条静态路径随本体进仓（实测：`markdown/highlight.js`、`markdown/katex.js`、`ansi.js`、`markdown/MarkdownText.js` 四件里 8 条静态命中），**按口径整体接受、不判红**。约束范围因此收窄到**本包自写件**：本包自己的同步导出里重依赖命中必须为 0 —— 我方那两道门（`src/markdown/highlight.ts` / `src/markdown/katex.tsx`，经 `src/atoms/dsh-rc1-code-highlighting.ts` / `dsh-rc1-math.ts` 按需 `import()` 取用，后者连 `katex/dist/katex.min.css` 一起按需取）仍是唯一入口，`src/index.ts` 的同步导出里这些 specifier 命中 = **0**。

- 我方**将来**新增的重渲染依赖仍只能这么进：藏在 `src/markdown/` 之后按需 `import()`，不得进 `src/index.ts` 的同步导出。
- 引擎/语法未就绪时，代码块回落纯文本、数学回落原样源码（不闪错误、不抖版式）；就绪后由订阅通知重渲染换成真结果。
- 这条约束由**仓内正式门禁** `scripts/check-ui-lazy-doors.ts`（根 `package.json` 的 `check:ui-lazy-doors`；用例在 `tests/quality/ui-primitives-gates.spec.ts`）强制，读数为三行：闭包内文件数（**分桶**：本包自写件 / 第 4 棵树）、`本包自写件重依赖命中`（**判据 = 0**）、`第 4 棵树重依赖命中`（**读数、不判红**）。它从 `dist/index.js` 出发算静态可达闭包，且**裸 specifier 真解析**（否则门面那条 `export * from '@tpt-work/dsh-ui-primitives-vendor'` 走不出 `dist/`，第 4 棵树整棵在闭包外 —— 那种绿是假绿，门禁现在自己判退 3）。它每次跑都当场打印**动态装载门表**与两个桶的读数，并**自带反向对照**：量完主闭包后必然拿门表里第一道门当入口再走一遍，那件在门后、自己静态引 `shiki`/`katex` ⇒ **必须报红**。门找不到、闭包只走出一件、第 4 棵树 0 件、或走了不报红，一律退 3（假绿），不当绿放行。

## 怎么用

```ts
import { Button, ReadBlock, relativeTime } from '@deepseek-ai/dsh-client-ui-primitives'
```

- 本包完全**自含**：不 import 任何 `@tpt-work/*` 原语（原子已折进 `src/atoms/`）；`@deepseek-ai/*` 这个名字只是为了被 dsh bundle 解析到。
- 只承诺 cordis-free / react-only：本包不 import cordis，不 import `apps/**`。
- React 19 写法（`React.JSX.Element`、无 `defaultProps`、`exactOptionalPropertyTypes` + `noUncheckedIndexedAccess`）。dsh 自身 pin React 18，本仓是 19 —— 已装的 dsh bundle 只把组件当值用，实测不受影响。

## 三个待定项的裁决

1. **`OnboardingSurface` / `Input` 不加 dsh 味标记类，保留 `data-slot`。** dsh 蓝本用的是 CSS Module 类名，构建后是哈希名，跨包不稳定、不构成契约；`data-slot` 是本仓既定约定。被装载的产物只把组件当**值**用，不选择这些类名。
2. **`MarkdownText` 的 `streaming` / `fileMentions` 门保留。** 已装产物真传 `fileMentions` / `streaming`。实现照抄 dsh 的**单一门**（`fileMentions: streaming ? undefined : fileMentions`）——增长中的消息没有最终文本，文件提及必须失效。
3. **`FishLogo` / `BrandWordmark` 不上改成公共原子。** 这两个图形只为满足 dsh 导出内容而存在，真正的消费者只有被装载的 dsh 产物；导出名（`FishLogo` / `FISH_LOGO_PATH` / `FISH_LOGO_VIEWBOX` / `BrandWordmark`）是上游 import 的名字，**不可改**。
4. **图形 = 2026-09-16 定稿的品牌标识（蓝底立体「T」）。** 原 dsh 鲸鱼/字标早已移除；`FishLogo` 直接渲染彩色 PNG（`/tpt-work-icon.png`，web 根静态资源），该文件是**全链路唯一的图形权威来源**——桌面图标（exe/托盘/安装器的 `icon.ico`、Linux 托盘 `icon.png`、macOS `icon.icns`）全部由它派生：`vendor/dsh-desktop/scripts/make-ico.mts`（PNG→ico+png）→ `make-icns.mts`（ico→icns），流程见 `process/brand-icon-single-source-chain`。旧 interim 剪影常量 `FISH_LOGO_PATH` / `FISH_LOGO_VIEWBOX` 仅剩 dsh 导出内容兼容（已无渲染消费方），**导出名不可改**。⚠ **首屏 Hero 上已经没有这个 path**：上游 `HeroShell` 的 SMIL 会在该常量与上游硬编码的鲸鱼路径之间插值（悬停即露上游图形），故 `conversation.hero.brand.mark` 自 2026-09-07 起由 `@tpt-work/brand` 占掉、回退动画件不再渲染 ⇒ 成因与判据见 `bug-fix/hero-brand-slot-hover-morph`。
