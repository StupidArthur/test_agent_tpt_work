# @tpt-work/llm-tpt

TPT 桌面端**默认模型服务席位**（宿主半 cordis 插件）。它为 TPT 应用提供**自有的一等 LLM provider**：
不经过 `pi-ai`，由本插件自己的 `LlmAdapter` 实现与模型网关（OpenAI Responses 风格，`tpt-work-router`）直接对话。

本包是**host-only 插件**——只有宿主侧的 node 半。**浏览器半是独立包 `@tpt-work/llm-tpt-onboarding`**
（模型目录卡片 / 首启密钥引导），不在本包内。两个包共享零依赖的身份常量权威来源 `src/refs.ts`。

> 定位一句话：替代 dsh 官方 `deepseek provider`，由 TPT 自己的适配器（Responses 请求拼接 + 模型发现 + 默认模型落位）出任默认模型席位。

## 1. 定位与职责

本插件是 `cordis` 插件（`name` / `inject` / `Config` / `apply` 四件套），挂载 id = `llm-tpt`。
它把「默认模型」这件事在 TPT 里变成**一个自有席位 `tpt-official`**：

| 职责 | 说明 |
|---|---|
| **自有 adapter（TptAdapter）** | `POST {baseURL}{responsesPath}` 的 Responses 请求体拼接 + SSE → `StreamChunk` 翻译（蓝本 = 旧包 `@tpt-work/llm-tpt` 的已验证实现，模块分解对齐 dsh 官方 `dsh-llm-deepseek`）。 |
| **自有模型目录获取** | `GET {baseURL}{modelsPath}`，解析网关富字段（`model_name` 多语名 / `is_default` / `input_modalities` / `max_model_len` / `supports_think` + `think_mode` + `think_levels`），成功且非空即**采纳落库**。 |
| **默认模型声明式 + 网关对齐** | 默认模型由装配 `agent-default-model` `{provider, model}` 固定（种子），`model` 支持写**稳定显示名**（`轻量` 等，id 亦可，`implementation/llm-tpt-default-model-name-pin`）；目录获取成功后默认由网关自报 `is_default` 对齐（装配不设 `defaultModelName` pin，2026-09-14 修订）。 |
| **思考能力归一化** | 异构模型的档位表 / 默认档 / 显示名归一化，权威来源在 `reasoning.ts`。 |

**身份常量（零依赖权威来源，`src/refs.ts`）**：

| 常量 | 值 | 含义 |
|---|---|---|
| `TPT_SETTINGS_NS` | `llm-tpt` | settings 命名空间（档案根即 provider 档案）。 |
| `TPT_PROVIDER_ROUTE` | `tpt-official` | 席位路由（2026-09-09 由 `tpt-gateway` 改名）。 |
| `TPT_API_KEY_REF` | `TPT_API_KEY` | 凭据引用：登录窗经 `tptIdentity/writeIdentity` 写入（2026-09-28 拍板取登录身份三件套同名；旧名 `TPT_GATEWAY_API_KEY` 让位），设置卡片仍可经 `credentials/set` 改写；请求时解析为 Bearer。 |

> **依赖服务由 `inject` 声明**：`['settings', 'llm', 'agentDefaultModel', 'credentials']` 四家 start 后才进 `apply`。任何失败**不抛未捕获错误、不影响其他 provider 装配**。

## 2. 模块分解

```
src/
├── index.ts       插件入口：apply / Config schema / 默认选择种子解析与削档修复的 boot 窗口 / 解析链 / 触发接线
├── refs.ts        身份常量（零依赖，浏览器半共用权威来源）
├── adapter.ts     TptAdapter：LlmAdapter 实现，纯传输（连接事实经 thunk 每操作读取）
├── serialize.ts   dsh 请求 → OpenAI Responses wire 请求体（请求拼接，不发请求）
├── sse.ts         SSE 帧切分（纯文本 → {event,data} 帧序列）
├── translate.ts   Responses 事件 → dsh StreamChunk 翻译（跨事件 index/缓冲状态）
├── types.ts       OpenAI Responses API wire 格式（仅类型，Wire* 前缀）
├── catalog.ts     模型目录获取（多 URL 故障转移 + 富字段解析）
├── reasoning.ts   思考档位归一化（能力 / 默认档 / 显示名 / 上游契约）
└── *.test.ts      各模块 vitest 单测
```

生产分层与 dsh 官方 `dsh-llm-deepseek` 高度对齐：**adapter 是纯传输**——连接事实（档案）经 thunk
每操作读取、Bearer 经每请求解析器解析；校验、分层与凭据策略归注册插件（`index.ts`）所有。

## 3. 档案 schema

适用 settings ns `llm-tpt`，`settingsPath` 为空（档案根即 provider 档案）。schema 权威来源 =
`index.ts` 的 `Config: z<TptProfile>`。配置条目与 `llm-pi-ai` 的 profile **全集对齐**（同名同形），
换自有 adapter 后配置层不缩水。装配 config 为基座，`installSection` 热更新（settings 用户层 + 基座 + schema 默认值合成）。

### 3.1 生效字段（adapter 真实消费）

| 字段 | 类型 / 默认 | 说明 |
|---|---|---|
| `apiKeyEnv` | `TPT_API_KEY` | 凭据引用（`credential-ref` 角色）。 |
| `displayName` | `TPT` | 提供方显示名。 |
| `api` | `openai-responses`（字面量 union） | 协议方言，当前只此一值。 |
| `baseURL` | —（无默认，看似可服务校验） | 网关地址，**支持多个**（换行/逗号/分号/空白分隔，书写顺序 = 尝试顺序）。 |
| `modelsPath` | `/models` | 模型发现 GET 路径段（缺前导 `/` 自动补）。 |
| `responsesPath` | `/responses` | 生成请求 POST 路径段（同上自动补）。 |
| `models` | `DEFAULT_MODELS`（内置静态目录） | 模型条目数组；**目录获取成功即整表替换**。 |
| `modelOverrides` | `{}` | 按模型 id 覆盖/补充 `models` 条目（override 字段优先；**集合字段空值继承基座**）。 |
| `defaultContextWindow` | `262144` | 模型未声明容量时回落。 |
| `defaultMaxTokens` | `32768` | 模型未声明容量时回落。 |
| `defaultInput` | `['text']` | 模型未声明模态时回落。 |
| `defaultModelName` | — | 默认模型**稳定名**（id 亦可，`implementation/llm-tpt-default-model-name-pin`），目录取后按名解析成网关当前 id。**装配当前不设**（真网关回 `model_name`+`is_default`，默认走网关对齐）；保留为可选能力。 |
| `headers` | `{}` | 自定义请求头（stream 与模型发现都附带；在 Bearer/attribution 之后追加，可覆盖）。 |
| `reasoning` | — | 档案级默认思考档（pi-ai 对齐旧字段，词表固定 7 档）。 |
| `thinkingPreference` | `[]` | 档案级默认档**有序偏好列表**（任意词表）。 |
| `streamIdleTimeoutMs` | `300000` | 流空闲看门狗（连续读不到字节即中止）。 |
| `retryPolicy` | — | 经 `providerRetryPolicy` 交给 dsh-llm-retry。 |
| `requestImagePixelBudget` | `4194304` | 图像输入像素预算。 |
| `requestImageMaxBytes` | `1048576` | 图像输入字节预算。 |
| `timeoutMs` | — | 请求超时（>0 才计时，覆盖到响应头为止）。 |

### 3.2 仅接受字段（schema 收下、当前实现不消费）

`compat`（profile 级与模型条目级）、`thinkingBudgets`、`cacheRetention`、`transport`、
`websocketConnectTimeoutMs`、`maxRequestImageBytes`、`providers`——为配置层兼容保留
（`api` 恒为 `openai-responses` 字面量，`transport`/websocket 走 fetch SSE、自定义 head 不消费本组键）。

### 3.3 模型条目字段

| 字段 | 说明 |
|---|---|
| `id` | **必填**，harness/wire 模型名。 |
| `name` | 静态单语名。 |
| `model_name` | 多语显示名（键=语种 id，如 zh/en）；显示侧按激活语种解析。 |
| `is_default` | 网关默认标记；目录取成功后驱动 `agent-default-model`。 |
| `description` | 用户可见简介（透传 listModels/resolveModel）。 |
| `contextWindow` / `maxTokens` | 容量：**采纳时直接取网关声明值**（上下文窗 = `context_window` → `max_model_len`；输出上限 = `max_output_tokens`），缺省才回落档案默认。 |
| `input` | 输入模态（text/image）；含 image 时 composer 出图片入口。 |
| `reasoningEfforts` | **档位表**：键=档位 id，值=发网关 `reasoning.effort` 的 wire 串，`null`=该档不携带 reasoning；**`false` = 声明该模型无思考能力**。 |
| `defaultReasoningEffort` | 模型级默认思考档（须是档位表里的键；`off` 合法=默认不思考）。 |
| `reasoningEffortNames` | 档位显示名（**不分语种**，统一英文）。 |
| `compat` | pi-ai 同名方言开关（当前不消费）。 |

### 3.4 内置静态默认目录 `DEFAULT_MODELS`

未显式声明 `models` 时出厂自带，`listModels` 恒非空、不依赖外部装配 seed。**它只服务目录获取前
的离线解析**（boot 期种子按稳定名落到 id、`listModels`/`resolveModel` 的兜底读数），获取成功后
整表替换成网关本次应答。**出厂只放「轻量」一条**（2026-09-29 需求方收敛口径）：

```ts
ds-flash   // name 轻量 / flash（zh/en），is_default，contextWindow 256000，maxTokens 32000，档位 { off:null, low:'low', medium:'medium', high:'high' }
```

网关当日 live `/v1/models` 另有 `qwen-flash`（高级 / pro，档位含 `xhigh`，自报 `text+image`）——
**不在本表**：它不随安装包分发，只在「获取模型」成功后随整表替换出现 ⇒ 未获取过目录的实例（含
无 key / key 配错 / 网关不可达）选择器里只有「轻量」，已采纳过的实例看的是自己那份用户层目录。

⚠ 旧值 `my-flash` 已下线：留着它会让干净席位的 boot 种子（装配 `agent-default-model.model: 轻量`）
解析成无效 id ⇒ 目录获取前每轮请求 502、界面那枚模型控件退化成裸 `tpt-official/my-flash`
（`implementation/llm-tpt-default-model-name-pin` 的 2026-09-29 修订节有成因与读数）。
**`input` 不写**：`qwen-flash` 的网关行自报 `modalities.input:[text,image]`，但该网关带 `input_image`
的请求仍一律 400（`bug-fix/llm-tpt-assistant-history-400`）⇒ 沿用「未真机验证不硬编码视觉能力」
的口径（`bug-fix/llm-tpt-image-capability-propagation`），模态由采纳时提供。**容量写**：网关行两键
都给（`context_window` 256000 / `max_output_tokens` 32000），本表按同值写——它只服务目录获取前的
离线解析，少了 `maxTokens` 那 768 个 token 的差会让干净席位发超网关声明的输出上限。

**刻意不写默认档**：默认思考档由分层策略解析出来（`ds-flash` 的 `{off,low,medium,high}` → `high`）——
证明零配置即成立；想改档写 `modelOverrides.<id>.defaultReasoningEffort`。

> ⚠ **长期持有档位/默认档写 `modelOverrides.<id>`**（`models` 是数组 ⇒ 点「获取模型」即整表替换，
> `implementation/tpt-default-llm-seat` 第九批），且每条 override **必须重复 `id`**（缺它整个 backend 装配失败）。改默认档例：
> `modelOverrides.ds-flash.defaultReasoningEffort: medium`。
> **空表不算剥档位**：`reasoningEfforts` 空对象 = 未声明、继承基座（浅合并会被 schemastery 自动填
> 的 `{}`/`[]` 抹掉基座真值——`implementation/tpt-default-llm-seat` B 分支的机制本体）；**剥档位用 `reasoningEfforts: false`**。

### 3.5 `assertServiceable`（serviceability 把关）

`baseURL` 至少解析出一个 URL、`models` 非空，否则抛错命名原因（装配解析的 validate 与写盘共用）。

## 4. 触发入口

本插件在 **四条路径** 上被触发（同时也是"什么时候干活"的答案）：

### 4.1 插件启动（cordis `apply`）

`apply` 一气呵成：

1. 注册 adapter：`ctx.llm.registerAdapter([TPT_PROVIDER_ROUTE], adapter)`。
2. 注册可配置 provider：`registerConfigurableProviders({ provider, displayName:'TPT', settingsNs, settingsPath:[] })`。
3. 注册模型发现：`ctx.llm.registerModelDiscovery(TPT_SETTINGS_NS, …)` —— 通用发现 wire
   （唯一 UI 调用方 = 设置页 TPT 卡「获取模型」按钮）= **「拉取并采纳」**，回复投影为 `LlmDiscoveredModel`。
4. `installSection` 安装 settings 段（基座为 `Config(config)`，热更新 setSource）。
5. `fire-and-forget` 启动 `bootstrap`（见 4.3）。

### 4.2 凭据更新事件（自动获取一次目录）

```ts
ctx.on('credentials/reference-updated', (ref) => { if (ref !== TPT_API_KEY_REF) return … })
```

- **触发点**：`TPT_API_KEY` 变化且 key 解析就绪 ⇒ 自动 `refreshCatalogShared({})` 一次。
- key 的两条写路径（首启引导弹窗 / 设置卡密钥框）都经 `credentials/set`，这里是**唯一触发点**。
- key 被清空（unset）**不触发**。
- fire-and-forget：`void` + 兜底 catch，失败 info 留痕，绝不未捕获 rejection。

### 4.3 boot 窗口的种子解析 / 削档修复（`bootstrap`）

`apply` 后不阻塞启动，后台在 `RETRY_DEADLINE_MS = 30s` 内以 `RETRY_INTERVAL_MS = 2s` 有界重试
`attempt()`，目标是等 `agent-default-model` 段注册完成后做：

1. **稳定名种子解析**：`resolveSeedSelection` —— 落盘选择是本席位、`model` 不是已知 id、
   但按稳定名命中生效目录 ⇒ 改写为该条目 id（离线解析，不依赖网关可达）。
2. **存量思考档位修复**：`repairStaleEffort` —— provider 是本席位、model 是目录已知 id、但落盘
   `reasoningEffort` 已不在该模型**当前**档位表 ⇒ 写回一条不带档位的选择。

瞬态错误（`SETTINGS_CONFLICT` / 消息含 `is not registered`）在本窗口内重试；永久失败静默放弃
（info 留痕，下次启动再来）。

### 4.4 用户/浏览器半主动获取（wire `llm/discoverModels`）

设置页 TPT 卡「获取模型」按钮经浏览器半（`llm-tpt-onboarding`）调 `llm/discoverModels`，
`provider='tpt-official'` 触发，进入 `refreshCatalogShared`。**目录获取的去重**（自动 vs 手动可能并发）：

- 无 `signal` 的调用共用同一在途 Promise（`refreshInFlight`）。
- 带 `signal` 的调用**不进**共享池（避免拿别人结果 / 被别人 abort 连坐成 ABORTED，各自取消各持有）。

### 4.5 每个会话请求（adapter 被调用）

对话/工具/图像等每次生成走 `TptAdapter.stream`（见 [解析管线](#5-解析管线)）。

## 5. 解析管线

### 5.1 请求拼接（`serialize.ts`，纯函数不发请求）

`serializeRequest` 把 dsh 请求翻译成 Responses body，**恒为流式**，可选字段缺省**不发键**（不发 null）：

| body 字段 | 来源 |
|---|---|
| `model` | `options.model`（本席位 harness 模型名 = wire 模型名）。 |
| `input` / `instructions` | `serializeMessages`：user 消息 → `{role:'user', content:[input_text/input_image]}`；assistant → `function_call` / `output_text` 项；tool-result → `function_call_output`；system 块拼进 `instructions`（`\n\n` 连接）。 |
| `stream` | `true`。 |
| `temperature` | `options.temperature`（有则发）。 |
| `max_output_tokens` | `options.maxTokens ?? defaults.defaultMaxTokens`。 |
| `tools` | dsh 工具 schema → Responses 扁平 `{type:'function', name, description, parameters}`。 |
| `reasoning.effort` | 选中思考档位的 wire 串（非空才发，见 5.2）。 |

- **工具参数始终是 RAW JSON 字符串**；图像在 user 消息里按 attachmentId 原位插成 `input_image` 数据 URL。
- `stop` 序列**显式反对**（抛 `UNSUPPORTED_OPTION`——Responses 网关联不了 stop list）。

### 5.2 思考档位 wire（`adapter.reasoningWire`）

选中档位在模型 `reasoningEfforts` 映射里有非空 wire 串才发 `reasoning.effort`；`null` 档位/
`false`/未命中 ⇒ 不携带 reasoning 字段。

### 5.3 图像输入（`adapter`）

消息含图像块 ⇒ 经 `attachments` 服务（dsh-base 挂载）`readImageRequest` 读取 → 数据 URL
（`data:<mediaType>;base64,…`），再进 `serialize`。attachments 服务缺失时抛 `UNSUPPORTED_CONTENT`（纯文本路径不受影响）。

### 5.4 SSE 帧切分（`sse.ts`，纯函数）

- `parseSseFrames(text)`：SSE 文本 → `{event,data}` 帧序列。`data:` 多行按 `\n` 拼接、`[DONE]` 哨兵、
  CRLF 宽容、其它字段行（`id:`/`retry:`/`comment:`）忽略。
- `splitFrames(buffer)`：把缓冲切成"已完整帧 + 剩余串"，**跨 chunk 断句安全**、一次多帧全切。
  > 修正蓝本的死锁：`findFrameEnd` 返回**含分隔空行**的长度，`rest` 因此会前进（蓝本返回不含空行、
  > rest 总以空行开头 ⇒ `indexOf('\n\n')` 命中 0 ⇒ 流里只有第一帧能被解析）。

### 5.5 事件翻译（`translate.ts`）

`ResponsesTranslator` 持有跨事件的 index/缓冲状态，把事件流翻译成 `StreamChunk`。`KNOWN` 事件九种：
`output_item.added/done`、`output_text.delta`、`reasoning_text.delta`、`reasoning_summary_text.delta`、
`function_call_arguments.delta`、`completed`、`failed`、`error`（未知事件/非 JSON 宽容丢弃）。

语义要点：

- **思考内容对位**：`reasoning_text.delta`（vLLM /v1/responses 实流拼写）与
  `reasoning_summary_text.delta`（OpenAI 摘要拼写）都落成 `block-start(reasoning) → reasoning-delta →
  block-end(reasoning)`；块开合由 `output_item.added/done`（`item.type==='reasoning'`）驱动，网关漏发时
  由增量自开、`completed` 前统一兜底闭合。闭合态全文回落链 = 缓冲文本 → `item.content`（vLLM
  `reasoning_text`）→ `item.summary`（OpenAI `summary_text`）。
- **契约强制**：`usage` 必须先于 `finish`；`finish` 后不再 emit（terminated 状态丢弃后续）。`index` 按首见顺序分配。
- **工具**：`function_call` 开 `tool-call` 块，参数增量走 `argumentsDelta`（RAW JSON），
  `finish` reason = `sawToolCall ? 'tool-calls' : 'stop'`。
- `failed` / `error` → `finish(kind:'error', failure:{message, code})`。

### 5.6 目录获取（`catalog.ts`）

`GET {baseURL}{modelsPath}`，response 三形状容错（裸数组 / `{data:[...]}` / `{models:[...]}`），逐行解析：

| 网关字段 | → 目录条目 |
|---|---|
| `id` | 必填，空/缺/非 string 的行丢弃。 |
| `model_name` | → `model_name`（只收值非空的 string）。 |
| `name` | → `name` 回落（`model_name.zh ?? name ?? id`）。 |
| `is_default` | → `is_default`。 |
| `context_window` | → `contextWindow`（网关声明的可用窗口；驼峰 `contextWindow` 优先，两者都缺才回落 vLLM 的 `max_model_len`）。 |
| `max_output_tokens` | → `maxTokens`（网关声明的每请求输出上限；驼峰 `maxTokens` 优先）。 |
| `modalities.input` / `input_modalities` | 与已知模态 `['text','image']` 求交；交集空 = 未声明（真网关给的是 `modalities.input`，旧形作回落）。 |
| `supports_think` + `think_levels` | → `reasoningEfforts`（`supports_think===true` 且数组非空才生成；`off → null`，其余档位 wire 串 = 档位串 1:1）。`think_mode`（toggle/level）不改变映射。 |

`projectDiscovered` 投影为 `LlmDiscoveredModel`（id + 当前语种显示名 + 容量；富字段不出宿主）。
成功且非空 ⇒ `refreshCatalog` 采纳落库（`settings.mutate` 只 `set ['models']` 一个键）⇒ `adoptGatewayDefault`
（见 [默认模型解析链](#6-默认模型解析链)）。

**显示名解析链（`displayNameFor`）**：`model_name[精确语种]` → `model_name[语种主子串]`（`zh-CN` → `zh`）→ `name` → `id`。
宿主侧语种 = settings `locale.preference`，缺省 `zh`（`resolveLocale`）。

### 5.7 保持最后的有效档案（keep-last-good）

`resolveProfile` 每次解析用户 settings 快照；新一轮快照非法（`Config` 解析抛错）时**留痕并回退上一份
好档案**（对齐 dsh `llm-deepseek` 的 `resolveAdapterOptions` 容错），绝不逐请求崩。

## 6. 默认模型解析链

### 6.1 目录获取后的解析链（`gatewayDefaultSelection`，`implementation/llm-tpt-catalog-fetch-and-multi-url` 两级 + `implementation/llm-tpt-default-model-name-pin` 名字链）

依序（命中即止，id 恒来自本次网关应答，不复活"未知 model id 502"漂移类）：

1. **现值有效不 churn**：现选择 model 在目录里按 id 或稳定名命中 ⇒ 保持（按名命中顺带改写落盘为该
   条目 id；按 id 命中且档位仍可服务即幂等不写）。档位失效时**即使模型没变也写**（削掉档位）。
2. **pin 按名**：`defaultModelName` 在目录里按名命中 ⇒ 该条目（网关回 `model_name` 富字段后的主路径）。
   ⚠ **装配当前不设此字段**（2026-09-14 修订：真网关回 `model_name`+`is_default`，默认直接走 4）；
   为可选能力，其他部署可经该字段启用。
3. **pin 两跳**：pin 在**声明基座目录**（apply 期对装配 config 一次性解析快照，`declaredModels`）按名命中、
   且该条目 id 仍在本次目录 ⇒ 该条目（真实网关只回裸 id 行、目录里没名字时的漂移修复主路径；同样仅当 pin 开启时参与）。
4. **`is_default` 行**（装配不设 pin 时的默认主路径（本网关）。
5. **兜底目录首行**。

只动 TPT 席位自己的选择（生效 provider 非本席位不碰）；解析目标与现值相同不写（幂等）；现选择的
`reasoningEffort` 若仍在新模型档位表内则保留。

### 6.2 匹配规则（`matchModelEntryByKey`，`implementation/llm-tpt-default-model-name-pin`）

`key` 精确等于 `id` → `name` → 任一 `model_name` 语种值；精确相等、行序首中，不做模糊/trim/大小写折叠；
id 恒优先于同串的名字；空 key 恒不中。

### 6.3 写入口径统一

落盘默认选择统一走 `ctx.agentDefaultModel.saveSelection`。存量落盘的 `reasoningEffort` 是当初
`saveSelection` 写出的 id 串（品牌类型无运行期校验），原值透传（一个类型断言）。

### 6.4 削档修复（`repairStaleEffort`）

为什么必须修：宿主在把请求交给 adapter **之前**校验档位（`dsh-llm` 的 `resolveCallWithInfo`），失效档位
抛 `UNSUPPORTED_REASONING_EFFORT` ⇒ 该模型每一轮请求都失败。不写档位是安全的（默认档由宿主按
`reasoning.defaultEffort` 物化，标 `adapterDefaults`，不会被当作用户手选落进 session header）。按**会话**
落盘的旧档位不在本函数处理范围内（出口 = 用户在 composer 重选一档）。

## 7. 多 URL 故障转移与错误处理

### 7.1 多 URL 语义（`catalog.ts` 文件头）

`baseURL` 可含多个 URL（换行/逗号/分号/空白分隔，**书写顺序 = 尝试顺序**）。一个 URL「能通」= 请求在它
身上完成（2xx 且可解析）：

- **转移**（该 URL 不可用 ⇒ 试下一个）：网络层失败（连接拒绝/DNS/超时）、`status ≥ 500`、`404`。
- **立即停**（与 URL 无关 ⇒ 不再换）：401/403 鉴权、400/422 请求本身错。
- 流式一旦开始消费响应体就不再转移（那条分支只剩空闲看门狗与网关异常两个错误出口）。

`parseBaseURLs` 负责拆解；URL + 路径拼接前都削一次尾斜杠、路径缺前导 `/` 自动补（`gatewayPath`），
防止拼出 `http://hostmodels` 坏 URL。

### 7.2 流（`TptAdapter.stream`）的错误出口

- **缺 key**：`MISSING_CREDENTIAL`（不触网）。
- **无 URL**：`PROVIDER_ERROR`（NO_GATEWAY_MESSAGE）。
- **请求超时**：`timeoutMs > 0` 时与调用方 abort 并行计时，覆盖到响应头为止，每 URL 独立一次。
- **流空闲看门狗**：连续 `streamIdleTimeoutMs` 读不到字节即 abort ⇒ `PROVIDER_ERROR`（caller abort 优先）。
- **未到终止帧**：SSE 没给 `error`/`completed` 时兜底 `finish(error)`。
- **全部 URL 耗尽**：`PROVIDER_ERROR`。
- **abort 接线贯穿整个尝试生命周期**：caller abort → 抛 `ABORTED`，无论成功/失败/换 URL/消费端早退都拆底层连接（防"停止生成"停不掉、早退泄漏连接）。
- 401/403 → `AUTH`；其余 4xx → `PROVIDER_ERROR`。

### 7.3 脱敏口径（`implementation/llm-tpt-catalog-fetch-and-multi-url` 需求方裁定）

**用户可见文案不含任何具体内容**——网关地址、HTTP 状态、配置项路径、席位 id、凭据引用名都不许出现在
界面上（上游把非 `AUTH` 的 `LlmError.message` 原样渲染进对话流，设置卡也直显）。文案常量：
`MISSING_KEY_MESSAGE` / `MISSING_KEY_FOR_DISCOVERY_MESSAGE` / `NO_GATEWAY_MESSAGE` /
`KEY_REJECTED_MESSAGE` / `REQUEST_REJECTED_MESSAGE` / `GATEWAY_UNREACHABLE_MESSAGE`。

**具体事实一律走 `TptDiagnosticLog`**（宿主注入 `ctx.logger`）：URL、HTTP 状态、响应体片段、空闲毫秒数
只进日志，绝不进 `message`。diag 内容不含密钥值（Bearer 只在请求头，从不进事实）。

## 8. 思考能力归一化（`reasoning.ts`，纯函数零 UI）

解决同一席位下异构模型思考方式的四件事：

1. **能力来自数据**：`reasoningEfforts`（键=档位 id，值=wire 串；`null`=该档不携带 reasoning、
   `false`=无思考能力）。本模块不认词表只认形状。
2. **默认档分层策略**（`resolveDefaultEffort`）：模型显式 `defaultReasoningEffort` > 档案
   `thinkingPreference` 偏好列表 > 档案 `reasoning` > 内置「最高非 off 档」兜底。
   `off` 这类"不携带 reasoning"的档**不参与兜底**（否则出厂默认就成了不思考）。
3. **显示名 = 网关原始词汇**（需求方 2026-09-29 拍板「不要映射，就用网关原始词汇」）：`reasoningEffortNames[档位]`
   （网关自报的显示名，给了就用）→ 档位串**原样**。网关写 `xhigh` 界面就是 `xhigh`、写 `turbo` 就是 `turbo`，
   不做首字母大写、不查内置标签表。**模型名**才走语种链（`catalog.displayNameFor`），两套口径别互相抄。
4. **上游契约三条硬约束**（`dsh-llm.normalizeModelInfo`）一次性满足：`efforts` 非空、`id` 不重、
   `defaultEffort` 必属 `efforts` —— 违反任一条是 `INVALID_MODEL_REASONING`，整个模型不可用（不是降级）。

**为什么必须回报 `defaultEffort`**：上游 composer 的档位面板在 `reasoning` 存在而 `defaultEffort` 缺席时
会**自己插一栏硬编码的 `Default`**（`dsh-client-ui-model-selection` 的 `provider-default` 项）。要 TPT 席位
不出现这一栏、又出厂即带默认思考，唯一不碰上游的方法就是把 `defaultEffort` 补全。展示顺序 = 「关闭」
档恒排最前，其余可服务档按强弱**升序**（`EFFORT_RANK`；未知档 rank=0 按声明序稳定）——单调递增、一眼可读。

**"模型没思考能力"的表达**：整块不回报 `reasoning`（`false` / 缺表 / 只有 `off` 表 ⇒ `undefined`，
界面就没有推理等级入口）。唯一例外：显式 `defaultReasoningEffort:'off'` 可以把"只有 off 的表"救回来
（隐藏 Default 栏 + 出厂不思考）。

## 10. 接线

### 10.1 与浏览器半（`@tpt-work/llm-tpt-onboarding`）

- 身份常量两处各有一份 `refs.ts`（宿主半零依赖权威来源，浏览器半复制单源——浏览器半只准 import 零依赖模块，
  宿主那颗被 schemastery 依赖链污染）。**同名同值**，界面写的键与请求读的键不可能分叉。
- 浏览器半经 `remote.settings` 读写 `llm-tpt` ns、经 `llm/discoverModels`（`settingsNs='llm-tpt'`、
  `provider='tpt-official'`）触发获取。

- id: agent-default-model          # 覆盖 base 已装的 agent-default-model（根级 - id: 改写继承行）
