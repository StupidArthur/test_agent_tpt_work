# TPT 网关短请求并发验证（待审）

用户要求从 100 并发开始测。沿用上一轮公网网关 flash / think_level=low，提示与单并发基线相同：`Reply with exactly OK. Do not explain.` 输出上限 128 token。

队列：100、200、400、800、1600、2501。每轮同步创建请求、独立连接，排空后再升档，无自动重试。首次 HTTP/流式/客户端异常后停止升档，仅一次单请求恢复检查。总请求最多 5602、最大输出约 71.7 万 token；单请求总超时 180 秒，连接 60 秒，读取空闲 90 秒。

完整成功检查 HTTP 200、DONE、finish_reason、无流内错误/读取异常；OK 后附句号不作为接口性能失败，正文差异另记。输出实际 token 与 usage 一并保留。

headers_sent_peak 包含请求传输和等待，不等于服务端内部并发；200 未读取完毕的重叠数量也不能作为模型并发。快速短回答可能在全部请求送达前已结束，计划档位不能当作达到的真实并发。报告分别列这些值。

响应时间为每个请求启动到读取结束，包含本机连接/调度等待。first_bytes_at 是首个响应体字节的到达时刻，不一定是首正文，不能称模型生成首 token 延迟。各请求原始/部分响应压缩留存，逐请求解压 SHA-256 与文件字节 SHA-256 分别登记。

环境与边界见 environment.json；逐请求证据见 wave-*.json、responses/；异常后恢复见 recovery-1.json。全部留在此任务待审，不自动转成产品缺陷。
