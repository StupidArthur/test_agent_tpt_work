# TPT 公网网关并发报错验证（待审）

用户要求按上一轮 DeepSeek 直连方式验证 TPT 网关什么时候报错。本轮使用既有 `flash-public-low` 测试凭据、模型 flash、think_level=low，Chat Completions 流式接口。只评估 API，不操作软件 UI。

## 队列与停止条件

1、10、25、50、100、200、400、800、1600、2501 请求逐轮并发启动。各轮完全收尾再升档。出现任意非 200、SSE 错误、未完整结束或客户端异常后停止升档，只做一次单请求恢复检查，不重试失败请求。

每次输出上限 1024 token，总请求上限 5688，单请求总超时 180 秒、连接 60 秒、读取空闲 90 秒。正常读取，不故意延迟消费响应。最大输出配额约 583 万 token；费用以网关自身计费为准，不能套用 DeepSeek 直连单价。本轮通常在首次异常档位提前结束。

## 判据与证据

- 完整成功：HTTP 200、SSE DONE、finish_reason、无流内错误、无读取异常。
- headers_sent_peak：请求头已发送但尚未结束的客户端重叠数量，含等待，不是网关/上游内部计数。
- http200_unfinished_peak：已收 200 但尚未读完的重叠数量，仍不是服务端准确计数。
- 初次失败档位只表示该批次出现错误；没有服务端计数/稳定重复验证时，不称精确并发上限。
- 明确区分 HTTP 拒绝、200 中途断流、SSE 错误及客户端连接/读取限制；上游原因仅在错误原文支持时归因。

`wave-*.json` 记录逐请求状态、时间、错误原文、usage、响应头和事件；`responses/*.sse.gz` 保存原始/部分响应，解压后的 SHA-256 见请求记录；`evidence-index.json` 登记压缩文件及代码哈希。`recovery-1.json` 保存恢复检查。报告留待双方审核。
