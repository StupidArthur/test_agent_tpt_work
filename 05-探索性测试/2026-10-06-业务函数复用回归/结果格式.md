# 结果格式

每条 `结果/<case_id>.json`：

```json
{
  "case_id": "G5-06",
  "contract_version": "2.0",
  "attempt_id": "本次唯一attempt编号",
  "environment_id": "本轮环境编号",
  "object_identity": {"original_agent_dir": "原实际安装绝对路径"},
  "inputs": ["本轮实际提交的目录/选项/请求；没有文本输入可为空数组"],
  "action_refs": ["本轮真实动作事件ID，可与同组case共享"],
  "status": "通过",
  "started_at": "真实ISO时间",
  "ended_at": "真实ISO时间",
  "actual_steps": ["实际步骤"],
  "assertions": [
    {"id": "G5-06-A1", "actual": {"before": "64位SHA256", "after": "64位SHA256"}, "read_refs": ["G4-original-agent-before", "G5-original-agent-after"]}
  ],
  "evidence": [{"path": "运行日志/G5.jsonl", "sha256": "该证据文件实际SHA256"}],
  "cleanup": {"status": "retained", "description": "本轮专家保留待审；设置已恢复", "read_refs": ["实际恢复核验事件ID"]},
  "notes": "本条其他断言必须同样逐项填写"
}
```

运行日志示例（示例不是执行结果）：

```json
{"event_id":"G4-original-agent-before","captured_at":"真实ISO时间","environment_id":"本轮环境编号","kind":"read","target":"原安装目录/agent.md的实际绝对路径","object_id":"该绝对路径","source":{"channel":"file","scope":"本轮原安装专家目录","locator":"该文件完整绝对路径"},"value":"文件读取计算出的64位SHA256"}
```

所有read_refs必须来自本轮日志，且结果actual与相应日志value一致。前后比较分别记录value，target相同，before时间早于after；副本路径比较必须是两个不同对象。标记路径字符串、时间和哈希示例不能原样填入正式结果。

`运行上下文.json` 保存本次期望绑定：project（UI确认的已有项目）、skill_name（本轮唯一技能内部名）、expert_resource（本轮专家引用实际名，通常agent-加内部名）、theme_initial/theme_changed、language_initial、font_initial/font_changed（数字）、permission_initial、scene_initial。初值必须引用准备阶段原始read事件；变更值由本次操作选择，不用改后actual倒填expected。报告列这些绑定的来源事件。

扩展绑定见[扩展场景与夹具](扩展场景与夹具.md)。夹具脚本的预期绑定与设置初值要分别注明来源，不能把夹具生成值称为产品读取值。完整JSON对象按固定键顺序记录，以避免序列化比较出现无意义差异。

`运行上下文.json`另含`binding_sources`，每个`$...`字段注明：初值用`{"kind":"read","event_id":"真实读取ID"}`；夹具预期用`{"kind":"fixture","path":"夹具/本轮/本次后缀/预期绑定.json"}`；点击前选定的修改值用`{"kind":"chosen","chosen_at":"真实ISO时间","reason":"本次预先选择依据"}`。不得从改后actual倒填expected。

## 环境与原始取值

准备阶段写`环境记录.json`：environment_id、captured_at、cdp_endpoint、project（已有项目身份和路径）、app_identity（真实exe或asar的path与SHA256）、account_alias、fixture_manifest（本轮生成夹具索引路径）、queue_sha256（本轮cases.json初始哈希）。不要记录密码、token或完整敏感配置。执行后校验队列未被修改。

每个read事件有object_id与source，channel为dom/file/http/derived，scope限定具体frame/菜单/卡片/任务/文件，locator为实际使用的定位器或完整路径。布尔聚合或派生值另外保存raw和derivation。例如“图片成功加载”要留`{complete:true,naturalWidth:8}`及`complete && naturalWidth > 0`；不能只有value=true。计数/列表保留对象身份，序列化比较使用固定键顺序。

actual=null仍须引用真实尝试中的观察事件，并写reason和failed_dependency（入口、上游case、超时或自动化取值限制）。这类断言记“未观测”，不能宣称业务已验证。对象已知不存在时取false/0/空列表，不用null隐藏失败。

## 可复用日志函数

Playwright脚本可调用`tools/record.cjs`，把操作、读取与日志写入同一次脚本；无需每条另起脚本。

```javascript
const {createRecorder} = require('./tools/record.cjs');
const log = createRecorder(taskRoot, {environment_id, group:'G3'});
// sampleSwitch是本轮观察后定位的真实控件，未使用expected造值。
const action = await log.action('本轮技能开关', 'click', null, () => sampleSwitch.click());
const read = await log.read('本轮技能开关', skillName,
  {channel:'dom', scope:'技能iframe/本轮卡片', locator:actualLocator},
  async () => {
    const raw = {aria_checked:await sampleSwitch.getAttribute('aria-checked')};
    return {value:raw.aria_checked==='true', raw, derivation:"aria_checked === 'true'"};
  });
// 断言actual=read.value，read_refs=[read.event_id]；动作引用action.event_id。
// 整组日志写完才调用log.evidence()计算哈希。
```

cleanup.status仅为restored/retained/failed/unchanged；说明实际核验和保留对象。恢复相关read_refs也必须入证据索引。共享日志后续追加会改变哈希，整组完成后一次计算并更新各case引用，不能反复手工抄哈希。

每份结果的evidence须包含其read_refs所在的日志文件及实际哈希，也可引用共享日志。日志组写完再计算哈希；后续追加后要更新受影响引用，不修改已经执行的读取值。比较型actual统一为before/after对象；普通比较actual为直接读值。

只允许通过/失败/不确定，逐条不允许阻塞/暂缓。状态：任何明确断言不成立为失败；没有失败但有null为不确定；全部成立才通过。缺日志或哈希不符是记录校验问题，不自动判产品失败。
