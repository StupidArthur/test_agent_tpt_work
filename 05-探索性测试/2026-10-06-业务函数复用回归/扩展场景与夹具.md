## 一次准备夹具

在本任务目录执行：

```powershell
python -X utf8 tools/prepare-fixtures.py --run 20261006-agent2
```

后缀换成本次唯一值。脚本仅生成本地文件与ZIP，不接入软件；同目录已存在时拒绝覆盖。它创建 `夹具/本轮/<run>/`，包含附件、单文件技能变体、技能ZIP、专家目录与哈希清单。`夹具/扩展/` 是只读模板，不直接导入。各case中的`夹具/扩展/...`在执行时解析为此本轮目录对应路径。

把生成的`预期绑定.json`字段合并进`运行上下文.json`，保留原G1–G6绑定；这些仅为夹具预期，**不能写成读取日志或actual**。脚本不修改运行上下文。技能技术name以fast-assert-开头并包含本轮后缀；覆盖专家与原longread专家内部name故意相同；mixed中的duplicate与root故意同名。

在UI选择的已有项目下建立一个本轮专用`.fast-assert-<run>`工作目录；核对绝对路径确实属于该项目，任务提示都给出此绝对路径。flow.txt内容为`FAST_FLOW_INPUT`，long.txt为`FAST_LONG_LINE_001`至`FAST_LONG_LINE_200`，code-on.js和code-off.js初始内容为`module.exports = 0;`，deliver.txt开始不存在。只改此目录与本轮导入资产。不要复用Luna的残留样本，不新增项目。

文件添加/技能导入/专家导入使用页面HTML input和Playwright `setInputFiles`，ZIP用生成的ZIP，专家用目录输入。无输入时实际查找一次并记录入口缺失，不点击不可控的原生选择器。

## 队列与复用

执行顺序为 **G1–G6 → G7 → G8 → G9 → G10 → G11 → G14 → G13 → G12**。每组仍按编号执行；G13依赖G9的cn-all，G10依赖G9导入的rich。G7可保留几个本轮草稿分别测试3/20/30附件，按case切回对应session id；不要为了每条重新上传全部附件。

- G8：先建立已完成本轮A，从B手动标未读再进入A验证清除，不依赖后台任务运行时长。工具详情复用本轮read/write任务。模型终态最多90秒，真实超时记录实际状态；竞态相关后台提醒/运行/停止已移出必跑。
- G9：批量准备变体，逐包导入时仍观察提交终态。英文回退只需切一次语言，完成后恢复。minimal在G9-09导入，G9-10复用，不重复导入导致同名冲突。缺必填字段若实际导入成功，拒绝断言为false并记新对象残留；不能伪造“已拒绝”。
- G10：一份rich目录覆盖文本/JSON/PNG/二进制。外部修改前核对**实际安装路径**、唯一内部name、备份字节与哈希；不改导入源包来冒充安装内容更新。有效修改测试后精确恢复，再做无效修改。恢复使用原字节，不重新拼写文件。
- G11：先导入各独立样本，longread共用覆盖/编辑/刷新；每次变更后恢复并回读，才能进入下一case。提示词和字段取自夹具，不将固定回复答案写进用户请求。确认前方案与确认后修改共用一个本轮编辑会话，明确限定字段，禁止修改既有专家。
- G14：root扫描用一次导入覆盖确认前/后检查。正式列表无法在弹窗时读取时，可读已观察的只读注册表或关闭弹窗独立回读；不能调用产品内部导入API绕过UI。candidate名称排序，混合状态规范为成功/跳过/失败，校验拒绝并入失败，同时留原文。
- G13：只在被测菜单/frame/卡片内取值，禁止全页正则把侧栏词汇当菜单选项。只读打开市场，不安装市场样本。搜索和排序操作后恢复。
- G12：先记录本组所改所有设置初值；本组结束核验同一字段集合快照。用量共用已完成任务。代码工具两次任务使用不同文件与新会话；不把Trace隐藏解释为工具未执行。记忆/沉淀只尝试开关保存，不运行或删除记忆；出现错误就记录，不反复点击。

全部导入技能结束停用，专家保留待审。可控草稿清空；本轮文件若允许清理则先保存必要证据，仅清理明确归属本轮的文件。恢复失败或无法控制的外部浏览器页如实列残留，不能写“无遗留”。

## 链接夹具与繁忙发送

```powershell
python -X utf8 tools/link_fixture.py --run 20261006-agent2 --log 运行日志/link-requests.jsonl
```

服务只监听127.0.0.1随机端口，启动输出base_url。保持该进程运行，分别使用`<base_url>/sidebar`和`<base_url>/external`，记录真实请求。任务请求生成一个指向完整URL的Markdown链接，不让模型访问它。先确认助手气泡内实际锚点href正确，再点击；没有锚点时只作一次明确格式补充，不循环生成。

应用内设置以实际侧栏和GET验证；默认浏览器以该URL的GET User-Agent和实际启动观察验证，不需要操控Chrome，也不点击Windows弹窗。不得直接从脚本请求目标URL来冒充软件点击。完成后Ctrl+C终止自己启动的服务，关闭本轮应用内页；外部页无法控制时记残留，不杀用户Chrome。

以下仅用于以后单独安排的可选时序专项，本轮不执行：繁忙测试在看到运行指示后立刻提交第二条消息，可用composer的Enter发送，不等待不存在的普通发送按钮。原始日志记首任务开始/终态、第二消息提交/第二次执行开始。排队与插话不能仅凭设置选中值通过；若时序观察缺失，记录null及缺失事件，不倒填时间。插话不断言底层中断机制，只断言运行中提交及最后回复包含第二要求。

## 动态预期绑定

除原绑定及夹具生成绑定外，执行前从本轮真实读取记录：

- `dialog_b_marker`、`flow_file`、本轮工作目录与session id；B标记在发送前选定，不能从错误回复倒填。
- `expert_longread_description_initial`：编辑前实际安装JSON字段。
- `work_steps_initial/changed`、`usage_initial`、`memory_initial/changed`、`evolution_initial/changed`、`experimental_initial/changed`、`developer_initial/changed`、`shortcut_new_initial`、`code_tools_initial`、`link_initial`、`busy_initial`、`sort_initial/changed`。开关为布尔值；changed在点击前选定反值。
- `link_path`：点击前确定的sidebar完整请求路径。

每个动态初值引用本轮read event；完整快照的字段集合开始/结束一致，键顺序固定。不要将“产品目前保存失败”写为开关changed预期false来让测试通过。

## 不纳入本轮的旧内容

用户体系、数据资产仍按用户确认的未实现范围处理；连接器对端、通信安装、市场安装、付款、现场控制、引用链依赖、故障注入、原生删除窗口、既有记忆文件编辑和体验优化计划不进入本任务。它们没有本轮安全且可控的执行依赖。

旧case中的市场升级、运行中资源快照、随机创建失败、复杂反馈提交等仍需独立隔离场景或严格时序/服务条件；本轮不靠反复试模型凑出来。创建入口已覆盖，生成业务与故障路径另建专项。当前任务每条必须实际尝试，完成状态仍只有通过/失败/不确定；入口消失不转为阻塞，也不无限找入口。
