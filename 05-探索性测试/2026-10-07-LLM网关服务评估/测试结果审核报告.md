# LLM 网关服务测试结果审核报告

日期：2026-10-07。范围：测试项 `04-测试项/saas-llm-test` 的本轮 API 测试、todo_1 补测及管理者复核。此报告不新增网关请求，不包含 TPT Work UI 测试。

## 一、总体结论

**已测范围内，公网网关具备提供基础文本、流式、上下文和工具往返能力；部分图片能力也取得成功样本。尚不能确认它完整满足当前 TPT Work 适配器，也没有测定最大支持用户数。**

不能用“没有bug”概括本轮：有真实的兼容性差异、语义待确认项及未验证路径；同时发现了测试器误判，已纠正。这些结果尚未全部完成协议定级及双方审核。

| 问题 | 当前回答 |
|---|---|
| 网关基本可用吗？ | 已测公网路径和可用模型的基础 API 样本成功 |
| 能给当前 TPT Work 完整使用吗？ | 基础契约有证据；当前宿主适配器身份/序列化方式未取得，完整适配未确认 |
| 性能是否达标？ | 已有短请求测量；SLO未确认，不出达标结论 |
| 支持多少用户并发？ | 最大用户数未知；只有短时并发和文本用户初筛 |
| 全部36项测完了吗？ | 没有。完整覆盖15、部分覆盖13、未验证8 |

“完整覆盖”表示必要检查点已观测，和“全部断言符合”是两个维度；不能将15/36解释成通过率。

- 已测可用目标：`https://tpt.supcon.com/tpt-work-router/v1`，模型目录及 `/responses`。
- 主要模型：`flash`；图片补测包含 `flash-backup-ds`、`pro`。后者本次返回503，上游不可用，不能据此判图片实现失败。
- 凭据：单key，环境变量引用；未知生产账户配额和限流策略。
- 两个内网候选地址本机不可达，属于环境前置限制，不作为公网网关缺陷。
- 当前 TPT 适配器版本、包哈希及实际 serializer 未取得；历史提取资料不能代替当前身份。
- 初始机读台账25个实例，原统计23通过/2环境失败；该数不包含所有补测检查点，也包含后来收窄的旧判定，**不作为当前最终通过率**。
- todo_1交付声明新增49次请求，分项计数相加为49；尚未逐请求完成独立去重审计，不称全任务总请求量。

| 能力 | 本轮观察 | 限制 |

| 非流式/流式文本 | 指定标记正确回显，正常终态可识别 | 只代表已测模型及请求形态 |

| 工具往返 | 加法参数17/25、call_id与回填链路有证据，最终得到42；流式参数聚合已检查 | 固定本地工具场景，不代表复杂工具或长业务流 |
| JSON输出 | 可解析，answer=42 | 单一结构样本 |
| 鉴权与非法请求 | 缺失/无效key被401拒绝，非法模型/输入被400拒绝；后续健康请求成功 | 隔离429/5xx/流内故障等未全部测到 |

## 四、差异与问题审核

| 编号 | 审核后的结论 | 建议处理 |
|---|---|---|
| DIFF-01 | flash可见推理与reasoning_tokens=0并存；计量组成语义待确认 | 向服务契约核对细分字段含义；吞吐只标服务返回总output_tokens，不断言隐藏推理归属 |
| DIFF-02 | 多个默认标记事实成立；没有唯一性要求和宿主影响证据 | 核对当前消费者默认选择规则后再定级 |
| DIFF-03 | flash-backup-ds图片样本成功；pro前置失败 | 上游可用时补pro，另有需要再扩展图片样本 |
| DIFF-04 | 两种历史形态200/400差异复现 | 精确核对输入契约和宿主serializer；不能直接认定网关拒绝了合法输入 |
| DIFF-05 | 直连200有落盘；代理502缺独立artifact | 保留通道观察，不升格网关缺陷 |
| DIFF-06 | 低预算达限时正文为空 | 不当完整成功，也不单凭空正文判bug；预算组成未确认 |
| DIFF-07 | 流式事件名response.completed承载内层incomplete，旧解析器把事件名当状态 | 解析器已修正；事件类型兼容性仍需具体契约定级 |
| DIFF-08 | 跨模型推理/usage/opaque ID结构不同 | 目前仅是结构差异观察；需要证明违反契约或破坏消费者，才能判缺陷 |

本轮保留8个DIFF编号，不表示8个已确认bug，也不表示所有候选均可撤销。原始观察不删除。

DIFF-07的重要纠正：原结论“非流式截断，流式完整完成”不成立。补测摘要反映流式内层状态同为incomplete，旧terminal字段仍保留当时解析结果。完整原始SSE未在所有补测请求中逐帧保存，因此摘要支持的结论与原始帧可回溯范围应分开，后续协议复核需补足相关wire。

## 五、性能测量

主力模型flash，单key、固定负载；无已确认SLO。

| 场景 | 样本 | 观察成功率 | 平均 / p50 / p95 |
|---|---:|---:|---|
| 串行短文本 | 30 | 30/30 | 0.381 / 0.359 / 0.422秒 |
| 原长输出，上限512 | 10 | 旧统计100%已撤回完整成功含义 | 3.933 / 3.907 / 4.016秒，保留为截断测量 |

原长输出10/10达到预算并为incomplete，不能算完成长回答。服务总output_tokens口径的截断吞吐约130.2 token/s，仅作该截断负载测量；不是可见正文吞吐，也不是模型完整任务吞吐。

尚缺上下文规模、输出规模、思考档性能对照、多目标网络、持续稳定性等充分样本。不从30次短请求推导长期稳定性。

## 六、并发与用户容量

| 已做实验 | 实际观察 | 能说明什么 |
|---|---|---|
| 同时在途1/5/10，各3波 | 共3/15/30次，全部200，观测峰值1/5/10 | 短时请求并发观察，不是用户容量 |
| 1文本用户，约60秒 | 26/26轮，轮次p95 0.437秒 | 对应短负载初筛 |
| 5文本用户，约60秒 | 125/125轮，轮次p95 0.625秒 | 对应短负载初筛，不是最大5用户 |
| 开放到达1轮/秒，60秒 | 60完成、0失败/拒绝，观测峰值1 | 低速率观察，未触及排队边界 |

文本用户实验思考间隔2秒、每轮一个请求、输出上限256。当前结果仅对应这一负载，不能套用到工具用户或累积历史。

**仍不能回答“最多支持多少用户”。** 60秒窗口不足正式持续验证要求；没有已确认SLO，没有工具用户容量和压力后恢复实测，也未找到失败边界。原开放到达调度的在途/排队约束存在测试器问题，已修正但尚未用新代码真实重跑，不据旧低负载样本证明约束正常。

后续需冻结SLO、最高负载、时间窗、请求/费用预算、凭据模式、输入输出和思考间隔；执行文本/工具分档，并在候选边界做两个独立持续窗口及压后恢复。参见 [容量补测计划](补测/todo_1/容量补测计划.md)。最低样本数不是请求预算；不能继续采用旧1500～1600请求的低估计划。

## 七、测试器与交付质量

已修正：候选JSON结构损坏、覆盖统计错误、计量表述过强、事件名误判终态、开放到达突破在途上限、闭环未充分排空。原性能结果保留，历史结论与修订分开。

复用代码已正式入库 [测试项代码入口](../../04-测试项/saas-llm-test/code/README.md)，必须指定探索任务输出目录。迁移后容量13项和原执行器8项离线验证通过；这些是本地模拟验证，不是新增网关成功样本，新容量入口还没有真实容量验证。

## 八、建议与交付状态

1. 接受已测基础API成功样本，继续按当前可用模型开展有限使用；不宣称完整宿主适配或生产容量已验收。
2. 优先完成DIFF-04/07的输入/事件契约核对，补对应原始wire及当前适配器身份，确定真实影响。
3. 冻结负载与SLO后执行容量补测，才能形成用户数区间；不要以请求并发10或用户初筛5作容量上限。
4. 隔离错误/断开、反压、长上下文和持续稳定性按缺失条件另派批次，不把未验证项凑成通过。
