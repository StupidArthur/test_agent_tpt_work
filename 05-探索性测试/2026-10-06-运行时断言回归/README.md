# 运行时断言回归：执行 Agent 入口

本任务由用户另行安排 Agent 执行。准备者与 Luna 不执行本任务，不能与其他 Agent 同时操作 TPT Work。五项质量审查后，本轮必跑 **140条用例、229个明确断言、14组共享场景**：保留原48条，新增92条。另5条依赖运行时竞态的用例保留在可选时序专项，不计必跑完成率。先读[五项质量审查](五项质量审查.md)，理解可执行与业务验证完成的边界。

## 渐进阅读

1. 本页 → [功能树](功能树.md) → [执行契约](执行契约.md)：先理解自顶向下覆盖、运行时断言与回溯证据。
2. 仓库根 `skills/exploratory-testing/SKILL.md`：共享场景、有限重试与恢复。
3. 需要接入时读仓库 `02-测试方法与技术参考/测试接入与执行指南.md`；启动或重连细节读同目录 `portable-agent-exe-ui-api-guide.md`。历史9234必须实际核验。
4. [场景顺序](场景顺序.md) → [扩展场景与夹具](扩展场景与夹具.md) → `用例/cases.json`：执行14组140条。每组先准备共享场景，不逐条重复导入。扩展文档规定场景顺序，跨组复用按此执行。
5. 写记录时看 [结果格式](结果格式.md)，运行 `node tools/progress.cjs` 自检。

可以直接发给 Agent：

> 执行本任务必跑140条case（不运行可选时序专项），使用当前可用标准/low、已有项目与本轮专用夹具。固定队列，不扩充探索，不读取旧结论作为本轮答案。Luna已释放UI，仍需确认无其他执行Agent占用。先按功能树确认一级入口，再按场景队列执行。每条按照指定对象、取值和比较规则记录运行时actual；保存原始读取/动作日志和对象身份，再留必要截图回溯。通过/失败/不确定均可，不允许逐条阻塞/暂缓。缺入口先实际查找并断言false，依赖断言无法取值则null写明原因；不能长时间反复找入口。每组恢复后继续，最后分别报告记录完整率、业务断言观测率、证据追溯和残留。

## 本轮改进

- 每条指定断言对象、取值和比较算子，校验器按actual计算，而非接受“我认为通过”。
- 已安装原对象与导入源包明确区分；副本导入前保存原安装对象快照，导入后比较同一路径。
- 坏包拒绝前保存源包哈希，拒绝后比较同一源包；不能拿事后哈希证明前后相同。
- 默认权限恢复后新增任务再验证，避免只恢复设置控件就忽略行为。
- 资源加载与唯一输出分别断言；用户请求不得含技能/专家预期输出串。
- G1–G6的48条与前轮一一对应；G7–G14新增92条另列覆盖与耗时，不把总量扩大混入原48条效率对比。

## 完成标准

140条都有实际尝试、229个断言有运行时actual或明确无法取值原因、证据可追溯、恢复核验完成。失败也算执行完成；不确定不是未尝试的替身。`record_complete`只代表记录完整，`business_fully_observed`才表示所有业务断言取得实际值。应用整体无法恢复时如实记录任务级环境失败及未执行数，不伪造全量完成。

校验器只检查格式、哈希与明确比较的一致性，不能独立证明Agent真的操作了界面。最终审核按 [审核指标](审核指标.md)核对原始日志/证据。本任务全部待双方审核，不自动入产品知识。
