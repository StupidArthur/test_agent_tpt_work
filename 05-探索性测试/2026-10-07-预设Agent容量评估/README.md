# 预设Agent真实负载与网关容量评估

## 目标与队列

当前阶段报告：[报告.md](报告.md)，逐项进度：[进度.md](进度.md)。已提取10轮产品预设负载并完成单用户基线；基线未达到冻结门槛，因此没有得出最大用户数。

1. LOAD-01：核验现有实例、内置预设和可取得的请求轨迹；优先复用真实完整记录。
2. LOAD-02：固定预设和任务，采样10个完整执行，提取逐请求输入、输出、工具时间和上下文增长。缺少真实请求不可用估算文本冒充。
3. LOAD-03：制作API负载回放，核验完整终态、工具链和可判定答案；执行健康单用户基线。
4. CAPACITY-01：逐档寻找达标/不达标边界，再细分。
5. CAPACITY-02：边界两个独立窗口，每窗至少15分钟且500个完整任务尝试；开放到达复核。
6. CAPACITY-03：排空、恢复检查、哈希审核及综合报告。

读取根AGENTS、skills/exploratory-testing/SKILL.md；API实现优先复用04-测试项/saas-llm-test/code。UI只提取产品负载，不纳入网关产品功能验收，使用tools/ui-operations。新增函数、代码和所有执行产物留在本目录待审。

## 冻结标准

用户已授权按上轮提出标准开始。请求及完整任务成功率≥99%；每次模型调用首有效输出p95≤5秒（正文/推理/工具分列）；整任务p95≤同配置单用户基线p95×1.5；开放到达客户端等待p95≤1秒、无静默丢弃和持续积压；排空后至少30轮全部成功，p95≤健康基线×1.2。失败、非预期截断及缺失值均保留。

这些数值为本项目工程阈值，并非行业统一秒数。方法来源：

- https://sre.google/workbook/implementing-slos/
- https://mlcommons.org/benchmarks/endpoints/
- https://grafana.com/docs/k6/latest/using-k6/thresholds/
- https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed/

## 执行边界

运行前保存本轮负载、凭据来源（不打印key）、最大用户/请求数/时间和超时。达到实验上限而未找到失败档时报告下界，不声称最大值；达到硬上限/缺必要链路时保留结果及精确补测条件。不同负载不能拼成同一容量。既有测试证据不改写，业务结果与记录校验分别判定。
