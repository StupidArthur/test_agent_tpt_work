## 解释

- **网关服务层**：简单 Responses 请求的主要限制首先表现为延迟增长，不是大量请求失败。
- **真实 Agent 层**：1～10 用户范围内 Gateway Service Success 均为 **100%**，但 Task E2E p95 从 **11.14s** 增至 **18.19s**。
- standard Agent 的主要体验问题是单任务本身较重、并发进一步增加等待，以及少量 `tool_not_called` 模型/任务质量波动；不能统称为“网关不稳定”。
- Task A已完成17窗、75,945次正式尝试，44条证据哈希及逐窗汇总已审核。通过档为 **60 / 85 / 100**；200/210受客户端限制，不能确定10秒网关上限。负载是flash/low、流式短marker、单key、同步波次排空后等待5秒；不是标准Agent容量或普遍生产承诺。
- “总用户≈同时活跃用户×5”是当前产品规划换算，不是注册容量或五倍同时在线保证。
