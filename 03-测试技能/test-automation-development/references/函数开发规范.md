# 测试函数开发规范（通用）

## 开发前：明确能力缺口

记录要实现的操作意图、目标对象、希望证明的断言、已搜索的工具及其不适用原因。区分“已有函数不易发现”“使用参数或上下文错误”和“确实缺少能力”；先修索引、示例或组合方案，再考虑新函数。

## 函数契约至少写清

- **名称与用途**：按业务能力命名，写适用版本/前置/授权边界，而不是绑定用例编号。
- **输入**：参数类型、必填项、取值范围、当前任务对象身份、样本来源及敏感字段。
- **动作**：实际操作表面、等待终态、可见副作用及可能改变的对象。不能暗中先执行正在测试的入口应完成的行为。
- **输出**：区分函数执行状态、真实观察值（含原文/对象标识/来源）、未观测值、错误和恢复凭据。只返回已真实读取或计算得到的数据；派生值保留组成原值与算法。
- **失败与超时**：指出失败阶段、是否有部分副作用、哪些断言没有读取到；捕获异常可以用于记录/恢复，不能吞掉失败并返回“成功”。
- **恢复**：说明初值或备份何时取得、恢复动作和最终独立回读；无法恢复时记录残留与处理条件。

## 实现规则

1. 复用现有连接、定位、请求、证据记录、重试和恢复能力；不要在每个业务函数里重复搭建驱动。
2. 查找目标时限定当前页面、frame、资源或 API 身份，避免全局模糊命中；状态变化后重新发现。
3. 使用本轮获得的资源标识、端口、路径、返回引用，不复制历史环境里的 session、call ID、用户名、硬编码盘符或坐标。
4. 对可重试操作先区分幂等与有副作用动作；只在能说明原因、确保归属并记录旧尝试时补做。不要无限重试以求“通过”。
5. 代码、参数、调用事件及原始返回建立关联；凭据脱敏且不可写入版本库。需要证据时记录时间、环境、来源、文件哈希和关联断言。

## 轻量合同示例

```text
函数：readSetting
输入：本轮目标对象身份
前置：已到达正确设置页
返回：{ executionStatus, observedValue, rawEvidenceRef, error }
副作用：无
验证范围：合同测试 / 本轮实机读取（分别注明）
```

这里是语义示例，不是任何产品的真实函数签名。具体工具库可能有 `ctx`、schema、事件结构或登记规则；开发时只查所选工具的实际契约，例如 [TPT Work 工具扩展文档](../../../04-测试工具/ui-operations/docs/扩展与边界.md)。

测试代码不得将 expected 填进实际读取字段；成功退出、API 200 或 UI 点击完成均不能替代业务断言。
