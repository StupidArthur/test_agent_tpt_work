# 测试代码验证与入库（通用）

## 逐层验证，不夸大覆盖

| 层级 | 可证明的范围 | 不能替代什么 |
|---|---|---|
| 语法、导入、静态检查 | 代码可以解析、依赖/导出存在 | 真实软件能够完成动作 |
| 单元或模拟/契约测试 | 输入校验、纯比较、异常分支、返回结构符合约定 | UI/API 的真实行为 |
| 集成/隔离环境试跑 | 接入、函数链路、对象绑定、记录或恢复在该环境下工作 | 未运行场景或正式产品版本的行为 |
| 真实目标版本试跑 | 本轮实际执行过的动作、读取及恢复在指定版本/环境得到证据 | 全部函数、全部 case 或全部场景均可靠 |

针对新增或修改的函数覆盖成功、拒绝、失败、超时、空值/不存在及恢复等相关边界。先运行项目约定的检查命令，再在授权范围内试跑受影响场景；没有真实环境或授权时明确标注未实测。

## 修改与复核

1. 保留原始异常、输入、原函数版本、尝试 ID 和证据；修正后用新 attempt、新版本及真实返回复核，不能将“脚本修复”当作“产品重测”。
2. 关注业务断言是否真的读取到了目标值、是否从同一对象比较前后状态；日志格式完整不等于业务通过。
3. 记录本轮改变的对象及恢复：备份/初值 → 操作 → 目标值 → 恢复 → 独立回读；恢复失败要单列。
4. 多条用例共用同一函数时，列受影响用例并按共享场景验证；未跑的编号保持未验证。

## 交付与审核清单

- 需求/用例与新增能力之间的关联、检索过的既有函数、为什么需要新代码。
- 新增或修改文件、函数契约、依赖、调用入口与版本/哈希；使用本轮真实参数及返回。
- 各层验证命令与结果、实测版本/环境、覆盖范围、失败记录、未验证条件。
- 证据来源、实际读值、恢复结果、残留、兼容性风险与复用范围。
- 评审决定及其审核者、范围和日期；若未审，状态保留**待审核**。

任务函数或工具缺口的产物先留本轮任务，不自动改写共享库。审核时分辨真正缺能力与“已有函数没被找到”，优先改善发现和接口；确认可复用、合同清楚、验证充分且经授权后再合并。保留原任务来源、历史尝试和代码版本，不覆盖原始记录。

具体产品可能另有注册格式、签名、验证脚本或入库要求；例如 [TPT Work 工具扩展约定](../../../04-测试工具/ui-operations/docs/扩展与边界.md)，应以该实现为准。
