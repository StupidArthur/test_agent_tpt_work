# 测试自动化代码开发

本技能回答**测试代码怎么写、怎么证明可靠、怎么复用与入库**。它独立于具体测试模式、产品和语言；不负责决定本轮测什么、判定产品是否通过，也不代替产品的接入技能或现有工具接口文档。

## 工作顺序

1. **明确任务**：读取本轮任务的目标、授权、输入样本、真实动作、必要读取、预期的依据以及状态恢复范围。优先区分“缺代码能力”“没找到已有函数”“产品不支持”。
2. **先发现再开发**：检查现有操作函数、断言、夹具和组合能力；核对输入输出契约、副作用、对象身份与适用场景。已有能力可复用就不重复实现。使用具体工具库时按其检索和调用文档操作。
3. **最小分层实现**：在现有结构中，将接入/定位/请求与取值、可复用业务操作、用例编排/结果判断分离；不为简单任务强制建立目录。参见 [代码分层设计](references/代码分层设计.md)。
4. **形成可核验契约**：明确参数、前置、动作、真实返回、等待条件、错误和副作用；保留原始证据、对象身份、恢复凭据。参见 [函数开发规范](references/函数开发规范.md)。
5. **验证后交付**：进行静态检查、单元/契约测试、必要的集成或真实产品试运行，逐层标明验证范围；改错留原 attempt 与新证据。参见 [代码验证与入库](references/代码验证与入库.md)。
6. **待审核入库**：新增/变更的任务函数先保留在本轮任务，写清已有候选为何不适用及代码与调用证据；由指定审核者决定是否合入共享库，不自行批准。

## 不得越过的边界

- **代码运行成功不等于业务断言成立**；输入、expected、实际观察及最终判断相互独立，不从预期伪造实际结果，也不从改后的结果反填预期。
- 不能用直接修改后台数据代替要求验证的 UI 操作；无法访问真实表面时按任务规则登记“未验证”，不要伪造成功记录。
- 错误、null、超时和拒绝要可区分；保留失败首次尝试、函数版本、真实调用、证据与恢复情况。运行日志中的凭据须脱敏。
- 只对本轮已授权对象实施准备、操作和恢复；不因调试测试函数而修改产品实现、删除用户资产或抢占其他执行者实例。

## 与其他技能、工具的关系

- **探索性测试**：需要探索执行、断言判定或补测时使用 [exploratory-testing](../exploratory-testing/SKILL.md)，不因开发代码而把本技能并入该技能。
- **TPT Work 接入**：需要启动或连接该产品时使用 [tpt-work-access](../tpt-work-access/SKILL.md)；它不是通用编码规范。
- **TPT Work 共享 UI 工具**：具体目录、`async (ctx,args)`、catalog、CLI 命令和版本验证以 [工具扩展与边界](../../04-测试工具/ui-operations/docs/扩展与边界.md) 为准。
- **钉钉通知**：属于独立的 [dingtalk-notify](../dingtalk-notify/SKILL.md)，本技能不处理通知发送。

仅在需要编写或修改测试代码时加载本技能；单纯调用已经具备的业务函数，不要求通读开发文档。
