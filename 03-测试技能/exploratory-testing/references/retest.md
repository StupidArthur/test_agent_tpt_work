# 测不对时，下一步怎么做

case失败、读不到值，或者页面原文与脚本判断矛盾时，先保存这次动作、错误和读取。然后按下表操作。没有软件操作权限时，先检查记录，留下需要实机补测的步骤。

## 看到了什么，就做什么

| 你看到什么 | 接下来怎么做 | 怎么写结果 |
|---|---|---|
| 点击报错或没有进入目标页 | 重新读取当前页的可见按钮，找到实际入口，修正后再点一次；读取目标页标题或独特控件，确认进去了 | 仍进不去：记不确定。依赖这一步的后续检查写“未验证：未进入某页面”，不能判后续功能失败 |
| 控件值是null | 在目标页面/弹窗查看实际控件和标签，修正读取一次；checkbox读checked，switch读aria-checked | 仍读不到：null+原因。不能写成关闭、0个或空字符串 |
| 原文正确，脚本却判错 | 对照原文检查比较代码，例如YAML名称带引号、未读状态叫idle；修正字段解析，再读一次 | 仅重算旧日志时注明“解析纠错，未重跑UI”；实际重跑才登记新执行 |
| 导入提示同名跳过，但case要测新增或字段错误 | 修改样本包内name、目录名和对应引用，保留要测试的异常字段；查列表/注册表确认新身份不存在，再导入一次 | 按新反馈判断。跳过不能证明缺字段被拒绝，也不能证明新增导入失败 |
| 设置点击后弹回原值 | 读这一项当前值和同页错误文字；关闭设置、重开，再读一次 | 明确保存错误或重开值不是所选值，记录保存差异候选；无需反复点击 |
| 全页能搜到技能名，但case要求证明调用 | 找本轮会话的执行记录，读取加载的技能/专家身份；助手回复另外读取 | 只有固定回复，仅支持输出效果。没有加载证据，加载断言写未验证 |
| 图片加载成功，但不确定是不是样本图 | 找目标卡片/预览那一张img，读取src/currentSrc和加载尺寸，对比样本资源 | 默认SVG加载成功不能证明样本PNG显示成功 |
| 现场结构和case假设不同，如横向容器要求测纵向滚动 | 保存现场结构、原case判据和具体差别，登记用例歧义 | 不改预期求通过；已验证部分照实写，不能验证的部分留待审核 |

每个问题最多修正一次有现场依据的定位/解析；需要新样本时最多重建一次。仍不能测清楚，就写清卡在哪一步、缺什么，继续下一条。有新证据支持另一种原因时，写明依据再追加尝试，不能不断盲换选择器。

## 三个可以照做的例子

### 记忆开关读到null

1. 打开“设置 → 记忆与进化”，查看“启用记忆”这一行的DOM。
2. 发现是普通checkbox，就读取这一行input的checked，不继续找role=switch。
3. 记下初值，点击一次，读点击后的值；按case等待保存结果，同时读取错误文字。
4. 关闭再打开设置，读取该项。若出现保存失败且回到初值，记录错误及回弹，判保存差异候选。
5. 恢复初值，再重开回读。保留原来null那次；这次操作登记为新attempt。

### 专家编辑入口点错了

1. 点“对话修改”失败，保存错误，先不要测确认写盘。
2. 读取专家详情按钮，发现实际是“去对话编辑”，修正后点击。
3. 确认进入该专家的编辑会话，再发修改请求；看到有效变更提案后，才点击确认并检查文件。
4. 仍进不去，后两步写“未验证：未进入编辑会话”，不能写“缺少确认功能”或“确认无法写盘”。

### 缺description的技能被跳过

1. 保存“已跳过同名技能”的原文，这次还没有测到缺字段处理。
2. 保持description缺失，只改新的合法name和对应目录名；确认这个身份尚未安装。
3. 导入一次，读取此次反馈以及是否产生正式对象。
4. 明确拒绝才支持拒绝断言；实际导入则记录产品差异；读不到反馈写未验证，不能凭弹窗还在判拒绝。

例子说明查找方法，实际控件名称和结构以当前版本页面为准。

## 修完代码，还要做什么

重新执行受影响的动作和读取，不能只改代码就报补测完成。例如修正了UA字段，但原链接带中文尾巴：还要重新生成准确链接、点击，并读取点击后新增的请求。

同一个错误函数被5条case使用，就列出这5条，修一次函数，按共享场景读齐5条需要的值。无关case不用重跑；不能只补一条就宣布5条通过。

新读取函数首次批量使用前，先查看它一份真实输出：是否来自指定frame/弹窗/消息，是否为目标身份，actual是否由该原值正确算出。若扫到style、底层设置框、用户请求或旧消息，先修函数再跑这一组。

## 怎么留下补测记录

用现有结果备注/表格写下面这些，不另建框架：

```text
用例：G12-04；原尝试：A01
原问题：checked=null，脚本转成false
修正：找到“启用记忆”行的checkbox，读取checked
新尝试：A02；关联实际动作、原始读取、日志引用及代码版本
结果：初值true → 点击false → 保存错误 → 重开true
恢复：重开后仍为初值true；或注明恢复失败、当前值和残留
```

原日志、失败尝试和使用过的代码版本保留，不覆盖删除。初值和恢复值须属于同一项设置；专家改了agent.md和metadata.json，两份都要恢复核验。最终恢复读取放在全部操作完成之后，覆盖实际改过的项。

必要动作/读取异常可以catch用于记录或恢复，不能吞掉后继续报成功。读不到写null+原因；确认目标区域可读且对象确实不存在，才能写真实false/0/空列表。

工具返回运行中session/cell时，等待脚本结束再操作同一软件。返回session_id不代表脚本执行完了。

提交报告前逐条看失败、不确定，以及有上述错误迹象的通过：新证据在哪，还是缺哪一步？未验证项单列，没有疑点的通过不重复跑。issues=[]只是格式检查，不能证明按钮真的点成功。

通过默认不截图；失败仅在图片有解释价值时留图。没有UI权限的补测写待执行；产品差异仍待双方审核，不自动入库。

### 函数调用成功后的业务复核

- 验证入口的作用时，准备代码不能先替入口做完动作。例如验证快捷使用是否新建会话，选不预先新建的函数，并读取该入口自身的前后 session。
- 自动恢复的函数须在同一次返回里比较 before、变化后、restored。不要跨两次调用取相同阶段的值证明“没变化”。
- 夹具返回的服务端口、URL、日志路径直接传给后续调用；先做服务健康对照，再读目标路径新增请求。没有日志文件是取证失败。
- 模型得到了预期文本，也要检查正确资源是否加载和实际调用。模型绕过坏技能直接读文件属于补偿，不能证明技能校验和加载正常。
- 导入比较身份集合的增量；搜索字段都加本轮唯一标记。发现目录名回退身份时记录实际身份，不猜成包内声明名。
