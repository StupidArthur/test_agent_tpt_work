# 05-探索性测试

## 开始与续跑

读本轮 README，确认范围、队列、样本、授权和交付位置。续跑先查现有结果，只列剩余检查点、缺失证据和下一动作，沿用原编号与 attempt，不重跑已完成项。

明确目标、固定编排和交付格式已具备时，核对必要契约与对象后执行首个检查点；出现缺契约、异常或明确实现评审需求再定向读源码。已给交付文件名与字段就直接使用，不横向搜索其他批次模板。机械哈希和事件关联优先复用[已有证据的机械核验入口](references/records.md#已有调用证据的机械核验)，避免反复生成临时脚本；工具审计不代替业务断言或现场恢复。

UI 任务遵循本轮指定产品的接入技能和操作工具；API 任务使用对应测试项的执行代码和环境要求，不套用 UI 的启动步骤。具体产品的安装、启动、登录、CDP/API 接入方法不属于本通用技能。

本机环境和对象身份必须实际核验，不复制其他 PC 的读值。核验可以由具备该契约的登记函数在本次调用内完成；明确输入已给出时，不要求先用临时shell重复探测相同进程、窗口或页面。先查必要契约并执行，实际返回有歧义或失败再定向排查。样本名带本轮唯一标记；操作前保存初值、备份及恢复办法。同一应用实例只由一个执行者操作，不抢占其他 Agent 的实例。

新执行环境先用 [环境检测工具集](../../04-测试工具/environment-check/README.md) 核验必需工具，并读取返回的本环境使用指南；大型任务编写系统命令前按已检测能力选择兼容语法。相同环境复用结果，工具、PATH、宿主、权限或项目依赖变化时更新；这不替代产品实例及业务对象核验。

## 按场景执行

- 广度优先覆盖范围内入口，再深入有价值的边界。共享准备的 case 一起执行，分别登记结果与证据引用，不按编号重复搭建相同场景。
- 观察 → 操作 → 等明确终态 → 读取 → 比较。已确定对象和参数的操作可批量顺序调用；导航、弹窗或控件变化后重新观察。脚本仍在运行时，先等待结束再操作同一 UI。
- 对象绑定本轮内部名/session。actual 来自指定对象与表面的真实读取；expected 来自用例或操作前独立取得的初值、夹具，不能从改后 actual 生成。
- 断言要证明目标行为：开关值不证明调用生效，模型复述标记不证明技能加载，全页命中名称不证明本轮对象存在。设置通常验证初值→改动→效果→重开回读→恢复；只证明保存时注明效果未验证。
- 读值失败保留错误和 null，不能转成 false/0/空列表；只有目标区域可读且确实不存在才记真实空值。派生断言保留组成原值及计算依据。

## 遇到问题

定位失败、读值矛盾、前置失败时读 [补测方法](references/retest.md)：保存原尝试，默认做一次有依据的修正或样本重建；仍无法判断则记录缺口并继续。新证据支持新假设时才追加尝试，不盲目重试。

页面通道不可见不等于不可自动化；动作超时或主窗口被模态禁用时，按产品接入技能检查原生窗口。UIA/Win32 读取和动作也需限定对象、通过主库或任务登记函数保留证据；未知窗口只取证并记录阻塞，探测失败不能记为“无弹窗”。

需要准备样本是下一步工作；确实缺身份、原生交互或对端等条件才记限制。开发中找不到入口，记录“目前没有发现入口”，不从请求失败推定未实现。范围外发现登记待审，不自动扩张任务。

## 记录与收尾

每条保留真实输入/动作、必要断言的预期与实际、判定、证据引用和恢复。复用工具自动生成的日志、快照与哈希，不手工重复抄录；首次组织结果或字段不清时查 [最小记录契约](references/records.md)。

通过默认不截图；失败或不确定仅在图片能说明问题时截图，视觉检查除外。同一现场共享证据。详细检索过程仅在工具查找失败/新增函数或专项要求时记录；耗时拆分仅在效率分析时需要。

完成分配队列并核验恢复后交付：实际尝试数、通过/差异/未验证/阻塞/暂缓、必要断言观测情况、候选问题、补测条件及残留。记录完整不等于业务全测完；短冒烟有必要断言未验证就不能给通过。各 PC 的结果分别保存。

持续探索队列耗尽后，检查范围内是否仍有明确高价值缺口；只剩重复验证、外部依赖或范围外项目则收尾。平台中断时保留可续跑状态，按根 AGENTS 的完成与中断规则报告。
