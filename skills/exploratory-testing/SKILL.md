# 高效探索性测试

目标：用尽量少的重复操作取得可审计的行为覆盖。遵循用户本轮范围、方法和授权；测试持续运行不等于持续制造重复任务。

## 接入与续跑

先读适用 AGENTS、任务入口、执行规则、当前台账与变更清单。沿用项目规定的操作通道。复用实例前确认目标；TPT Work 的具体入口见 [产品接入](references/tpt-work.md)，其他产品不要套用其端口和包格式。

接手时先输出一份唯一的**剩余检查点队列**：用例/配置项、缺失行为、现有证据、所需样本、执行办法、恢复办法。检查现有记录后才操作。历史尝试不因接手、压缩上下文或切换 Agent 而重新开始。

## 规划覆盖

- 广度优先：先确认各入口和一级功能，再对可用功能加深。
- 按场景而非 case 编号执行。一次导入可以同时证明来源、版本、默认状态、详情、搜索；分别映射检查点，共享证据，不重复导入。
- 按缺失行为归并同类样本，批量制作正常/异常字段、同名、文件结构、图标等变体；使用唯一内部名和标记，记录清单及哈希。
- 准备确定性回归任务时，按一级功能→二级功能→检查点标注用例；共享执行场景与功能层级分开。每条写清对象身份、场景初值、具体输入、动作、等待条件、取值、比较规则和恢复。需要运行窗口/故障注入的检查单列，不用“历史试成功过”承诺稳定可执行。
- 只在验证假设、处理证据缺口、检查恢复或复现候选问题时重测；记录重测原因。不要重复盘点已稳定的页面。
- 新发现可以独立观察或新增用例，不硬塞进不相关编号。新增编号应按当前台账契约注册；不能通过改弱校验器让记录通过。

## 执行一组操作

观察 → 顺序操作已确认的稳定控件 → 等待明确终态 → 取证与判定。表单填写可合并；导航、弹窗、控件重建或需要依据新内容决策时重新观察。不要并行操作同一个应用。

为每个检查点找最小有判别力的验证：描述搜索词不能同时出现在名称里；筛选交集需正反样本；开关状态不代替调用行为；模型复述用户标记不证明技能调用。实际调用需角色/资源加载或工具记录，加可区分输入输出。

断言只读指定对象，脚本不放宽case判据。动态预期从夹具或操作前选定对象独立读取，不用操作后的actual生成expected。拒绝须有本次对应错误反馈；图像须核对资源来源，不能将默认图标当样本图片。操作/读取异常保留错误并记null及原因，不catch后返回空串/false；确认表面可读且对象确实不存在才记录真实空值/false。缺少调用记录不能靠整页名称命中补成通过。

设置验证：保存初值 → 单项改动 → 检查行为效果 → 重开回读 → 恢复并核验。异步保存结束前不切下一项。只保存成功时标“保存已验证，效果未验证”；完全只读项和缺对端项单独登记。

## 控制耗时与排障

点击失败、控件读到null、导入被同名跳过，或者页面原文与脚本判定矛盾时，先保存这次记录，再按 [测不对时，下一步怎么做](references/retest.md) 的对应行处理。里面有记忆开关、专家编辑、缺字段导入三个可照做的例子。修完代码后重新执行受影响动作并读值；没有疑点的通过无需重复测。

默认每次自动化失败只做一次有证据支持的定位修正；仍失败则记录自动化限制，转下一项。只有明确新假设或用户要求才继续重试。重试前确认上次未提交或已完成，避免重复创建。

给每个场景设置与风险匹配的等待条件和诊断上限；超时先保存状态，再区分模型执行、等待输入、业务失败、定位错误。外部依赖缺失不做无限等待。

按批次汇报新检查点覆盖、阻塞、候选问题与恢复状态。估时使用最近同类场景的实际耗时和剩余队列，分别统计操作/等待、产品执行、取证登记、排障恢复。重复尝试和文档修复不冒充新增覆盖；没有计时依据就不报精确 ETA。

## 记录与审核

复用当前台账和取证脚本。新建辅助脚本时，统一采集时间、环境、限定表面的 DOM、输入/输出、哈希和证据归属；UTF-8 写入。独立数据回读与产品内工具回读要标明区别。

通过的case默认不截图，保留实际值、断言结果与操作/读取日志即可。仅在失败或不确定且截图能说明异常、发现用例外疑似问题，或布局/遮挡/样式等视觉检查确需图像时截图。不要每步或每条自动截图，也不为通过结果补拍；同一现场共享一张并关联相关case。截图按需采集，不代替运行时断言；历史证据保留。

用 [记录契约](references/records.md) 检查记录是否足以审查。原始证据不覆盖；纠错追加新版本与修订原因。结构/哈希通过不代替业务审核。

分别统计“每条已实际尝试且记录完整”和“业务断言已取得真实值”。依赖失败造成下游未观测时保留原因与失败依赖，不将台账齐全表述成全部业务测完。布尔或聚合断言留组成原值与计算依据；实际输入、对象身份、限定表面和原始读取要能对应到结论。

设计与实装不符先标差异。开发中尚无入口合理查找后记录“目前没有发现入口”；没有实现依据时不从请求失败推定未实现。用例外的常规预期异常同样登记候选问题。结论不得强于证据。

## 收尾与持续执行

用户授权持续探索时，继续处理当前去重队列；队列耗尽后按原范围检查是否有明确高价值缺口。若只有外部依赖、已声明范围外项目或重复验证，提交收尾，不为了保持运行重复巡检。范围是否已完成以检查点覆盖为准。

收尾分别统计已登记、实际执行、符合、差异、不确定、阻塞、暂缓；列出未验证检查点与精确补测条件。独立核验恢复与残留，本轮包按用户意图保留或安全清理。共享 UI 由一个执行者操作；只有用户或适用指令要求协作时才委派，审核者避免修改执行者正在写的文件。

探索产出在待审目录保留，是否正式入库按项目审核约定执行；此 skill 不授予额外权限，也不代替用户审核。
