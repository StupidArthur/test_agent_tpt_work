# A 用户体验

前置：生产路径 Smoke，负载/内容成功断言冻结；[方法](../docs/02-测试方法.md)与[指标](../docs/06-指标定义.md)统一计算。

## 普通交互

用 PERF-01固定短题和 PERF-03完整长回答。记录有效请求成功率、首次有效反馈和完整完成 p50/p95；長回答另报 Output tokens/s。逐样本核对正文与终态，空答案、截断不是成功。短请求慢意味着简单问答等待，长输出慢意味着长回答完成慢。

## 标准 Agent

按 [workload v1](../docs/07-标准Agent负载.md)完成工具调用→结果回填→最终答案，不操作 UI、不执行任意模型命令。默认30任务基线，保存任务及请求关联、工具等待、首反馈和全程耗时。

只保留三类核心输出：任务成功率、任务 E2E p50/p95、首有效反馈 p50/p95。未按要求调用工具计任务质量失败，协议成功另列。工具等待计入任务耗时。任务慢/失败对应用户工作慢/未完成。

## 长上下文

按 PERF-04固定短/典型/长，输出要求一致，标记探针确认历史被使用。报三档 TTFT/E2E和相对短档增加秒数与比例。cache仅解释；完整冷/热矩阵不默认跑。历史增长导致等待增加，是保留此核心场景的原因。

## 多人体验

用 [容量](04-容量.md)的两条负载曲线，分别给3/5/10秒活跃用户与×5规划数；短题请求 burst 不代替真实 Agent 用户数。尚无边界/有效任务不足明确写未确认。
