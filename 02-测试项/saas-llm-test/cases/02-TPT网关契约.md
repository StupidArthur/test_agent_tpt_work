# 02 TPT Work 所需网关契约（R2）

前置：记录当前适配器包版本/来源 SHA-256，核对 [契约依据](../docs/01-需求与范围.md)。直接测试网关，不操作 TPT Work。这里的成功仅表示对应 API 契约满足。

## TPT-01 原生 Responses 文本与指令

- 动作：POST 真实 Responses 路径，Bearer 鉴权；model 为目录 ID，`stream:true`，`input` 用户消息用 `input_text`，`instructions` 要求“只遵循用户的精确回显要求”，`max_output_tokens` 固定；回显标记。
- 断言：原生 Responses 200 流完成，正文准确；没有悄悄转成 Chat 或剥除所需字段。正文事件与成功终态能按对应适配器契约消费。
- 证据：wire 请求、路径、全事件与终态、正文。Chat 测试结果不能作为本项证据。

## TPT-02 目录与能力描述

- 动作：GET 目录，按实际返回的允许形状解析；查每个目标模型；检查已声明的目录字段。
- 断言：id 非空且目标存在。可选显示名、默认标记、上下文/输出上限、输入模态、思考声明若提供，类型和值符合当前目录契约；模型声明和实际 API 能力的差异关联后续项。
- 证据：目标原始模型条目、各字段实际值、能力矩阵。字段缺失可按适配器默认处理时，不人为判失败；响应形状只验证实际返回形状，不强求一个网关同时返回三种。

## TPT-03 正文、推理与帧结构

- 动作：执行短文本；有推理模型再执行该模型声明档位；记录 event/data、正文/推理增量与终态。检查实际存在的注释/未知事件不影响正文聚合。
- 断言：事件类型、正文字段和帧边界可解析；推理增量不混入正文；正文准确；首事件/首推理/首正文分开取值。首推理不存在可以为空，不能捏造。
- 证据：原始字节/帧、解析序列、增量与时间点。网络分片兼容先做执行器离线验证；本地制造的帧不能算真实网关已发送此类帧。

## TPT-04 Responses 工具往返

- 动作：提交平铺 function 定义（type/name/description/parameters），指定 add_numbers；按 item id/output index 读调用和参数；保留原始 JSON 字符串；用 `function_call_output` 与同一 call_id 回填 42；继续读取最终正文。
- 断言：工具名/参数/ID 对应准确，增量与最终参数一致；回填有效，最终正文 42，两轮均成功结束。不能用 Chat 的嵌套 function 或 tool message 替代。
- 证据：Responses 请求、item/argument 事件、调用对象与回填内容。可复用 API-06 的 Responses 场景。

## TPT-05 input_image（声明能力项）

- 前置：业务需要且模型声明图片输入；固定 PNG 和预期答案已给定。
- 动作：用户 content 同时传 `input_text` 与 `input_image`，图片采用宿主支持的数据 URL 方式；问预先确定的问题。
- 断言：请求未拒绝图片类型，正文准确反映图片且成功结束；正确答案不出现在文本问句或文件名中。仅“接收了图片字段”不足以证明图片内容生效。
- 证据：图片哈希、问题/预期、完整输入类型与原始响应。图片性能另行声明负载，不混入纯文本容量。

## TPT-06 思考档全遍历

- 前置：当前目录/服务约定给出支持档位及真实 wire 映射；不预置所有模型均有 off/low/medium/high。
- 动作：每个声明档位发送相同短探针；对 off 省略 reasoning 字段，其他档按真实 `reasoning.effort` 请求。每档单独实例。
- 断言：每档被接受且完成，正文正确；请求实参未被客户端自动降档或删除。目录声明与实测不一致单列；接受参数不能证明服务器内部思考预算真的改变。
- 证据：目录档位、请求字段、响应/推理/usage、实际模型。性能差别由 PERF-06 测，不由一次回显下结论。

## TPT-07 历史项目复用

- 动作：先做真实文本历史回忆，再复用工具第一轮真实 output items 和 function_call_output。出现 reasoning items 时按契约原样保留，不随意丢掉签名/关联字段；继续请求最终答案。
- 断言：请求的历史类型/顺序/ID 合法，真实历史可接受；文本记忆和工具结果正确。不能在第二轮新问句复制答案制造通过。
- 证据：第一轮输出项目、第二轮完整 input、各 ID 关联、最终答案。若模型没有 reasoning item，相关历史子项标未观测，不凭普通历史宣称已测。

## TPT-08 正常完成、截断与主动取消

- 动作：分别请求正常短回答、低 max_output_tokens 的长回答、读到事件后主动关闭的长流。
- 断言：正常为成功终态；达到上限的 incomplete/原因按适配器契约作为未完整完成呈现，不能被记成完整成功；客户端主动关闭记主动取消，不伪造 completed。终态 usage 保留，取消时无 usage 不填 0。
- 证据：三种请求、输出上限、最后事件/状态、取消原因。输出上限生效但模型提前结束时，不能称已覆盖截断，补充足够长输出或标该子项未验证。

## TPT-09 失败请求后的正常调用

- 动作：同一 API 客户端先请求不存在模型，再请求当前可用模型。若有明确“高级模型上游未购买”的测试模型，补做该失败→轻量模型请求，保持文本/工具场景实参一致。
- 断言：失败按服务约定返回，后续可用模型成功完成；客户端没有残留错误状态或污染请求。未购买模型的失败本身不直接作为产品缺陷。
- 证据：先后请求、错误、模型 ID、正常响应。**不宣称覆盖软件中同一会话切模型的历史 bug**；这仅验证 API 层独立请求恢复。

## TPT-10 流内错误与无终态（条件项）

- 前置：隔离网关/可控上游，可返回 Responses error/failed 和截断流。
- 动作：分别返回 HTTP 200 中的 `error`、`response.failed`、异常 incomplete、没有终态的 EOF；保留已收正文；再发健康请求。
- 断言：每类均被识别为错误/未完成，已收片段不成为完整成功结果；错误原文可追踪，客户端不挂死；健康对照成功。不能自动重试后抹去第一次错误。
- 证据：故障配置归属、完整已收帧、终止原因、计数和恢复。执行器离线验证与真实测试网关验证分开登记。
