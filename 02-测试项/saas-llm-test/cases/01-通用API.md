# 01 通用 LLM API（R1）

协议按网关声明展开。所有成功流需有终态且无错误，正文标记比较按 [方法](../docs/02-测试方法.md)。除另注外每实例至少 1 次，负向项每个子场景单独记录。以下不测试软件。

## API-01 模型发现与目标存在

- 前置：模型目录路径、有效凭据、待评模型 ID。
- 动作：GET 目录，保存返回；解析允许形状，精确查目标 ID。
- 断言：HTTP 200、可解析目录、模型项 ID 为非空字符串、待评目标存在。重复 ID 单列差异。不能仅凭显示名匹配。
- 证据：路径、状态、原始 JSON、目标匹配项。目录不可用时不擅自把历史目录当当前发现结果。

## API-02 非流式文本

- 前置：该协议声明非流式支持。
- 动作：请求 `stream:false`，要求仅返回 `GW_CHECK_7c91`，使用固定输出上限。
- 断言：200、有效响应结构、成功结束状态/finish_reason、正文 trim 后等于标记；无错误。usage 是否存在另由 API-09 评。
- 证据：完整请求、响应、实际模型、正文与结束原因。Responses/Chat 各自按结构取正文。

## API-03 流式文本

- 前置：流式支持。
- 动作：同标记请求 `stream:true`，读取至终态并正常关闭。
- 断言：200、SSE 响应；有效正文增量可拼接为标记；终态成功，无流内错误；有最终正文时与拼接一致。一个正文增量也可以合法，不强求多个块。
- 证据：原始帧、解析事件、各类时间点、拼接正文、终态。

## API-04 多轮上下文

- 前置：文本契约可用。
- 动作：第一轮输入随机标记并要求回答 OK；第二轮携带第一轮真实用户/assistant 历史，问之前标记，不在新问句重复答案。
- 断言：两次请求均成功；第二轮正文准确返回标记；历史角色/项目类型符合协议。第二轮无历史重试不可以代替本断言。
- 证据：两轮请求响应、随机标记、第二轮历史与新问句的边界。

## API-05 非流式工具闭环

- 前置：非流式与 function tool 声明支持；本地无副作用加法函数。
- 动作：提交 `add_numbers` 定义并强制调用，参数要求 a=17、b=25；验证参数后本地返回 42；用原调用 ID 回填工具结果，再请求只返回结果。
- 断言：第一轮工具名正确、ID 非空、参数是可解析 JSON 字符串且字段/整数值准确；第二轮成功且正文为 42。工具结果与 ID 精确对应。
- 证据：工具定义、调用对象、参数原文与解析值、本地计算返回、回填与最终响应。

## API-06 流式工具闭环

- 前置：流式工具支持。
- 动作：执行 API-05 相同场景但使用流式；按 call/item index 和 ID 聚合工具参数，回填后取最终回答。
- 断言：参数增量正确聚合；有最终参数时一致；调用名/ID/参数正确；两轮成功终态，最终正文 42。不能只用终态调用对象掩盖增量解析错误。
- 证据：各工具事件、ID/index 关联、聚合值、最终值和两轮请求。可与 TPT-04/07 共享场景。

## API-07 鉴权边界

- 前置：目标声明需鉴权；能区分凭据和模型额度问题。
- 动作：同一短请求分别用有效 key、缺 key、无效测试 key。
- 断言：有效 key 正常完成；缺/无效 key 返回约定的 401/403 或有文档依据的拒绝方式，反馈可解析且不泄露 key。不把 5xx/超时当鉴权正确拒绝。
- 证据：鉴权模式（无密钥）、状态、错误类型和原文。匿名服务不强行套此拒绝标准。

## API-08 无效模型与非法请求

- 前置：鉴权正常，已冻结服务预期错误约定。
- 动作：分别使用随机不存在模型；发送类型错误的 input/messages（例如整数）；发送空的必需模型字段。每次只改变一项。
- 断言：明确拒绝，常见 400/404/422，按服务约定判断；不返回伪成功正文，不偷偷路由其他模型；错误说明足以区分问题，不能凭通用报错断言已定位字段。随后有效请求仍成功。
- 证据：变更字段、完整错误响应、健康对照请求。服务若声明自动 fallback，独立记录声明与实际路由，不按无声明场景判断。

## API-09 计量与输出上限

- 前置：服务声明 usage，输出上限字段已核对。Chat 流式计量按声明发送 include_usage。
- 动作：短文本取 usage；另以很小输出上限（示例 32）请求明显更长的回答。
- 断言：输入/输出 token 为非负整数；总量按协议一致；限制请求的 output token 不超过请求上限。结束原因/完成状态与截断行为一致，不能把合法 length/incomplete 一律称网络故障。
- 证据：usage 原文、请求上限、结束状态/原因、实际输出。缺 usage 为计量未验证；不能以字符数证明 token 上限，也不要求必定生成到上限。

## API-10 JSON 输出模式

- 前置：网关/模型声明该协议的 JSON 模式支持。
- 动作：使用声明格式参数，请求仅输出 `{"answer":42}`。
- 断言：请求成功，正文是可解析 JSON 对象，answer 为整数 42，无 Markdown 包裹。格式合法与字段值正确分别记录。
- 证据：实际格式参数、原始正文、JSON 解析与字段断言。未声明时不为此项更换模型或删除参数。

## API-11 限流与服务端错误（条件项）

- 前置：隔离测试网关/可控上游，或服务方批准并提供明确故障条件；不在生产环境任意造故障。
- 动作：分别触发 429 和 5xx；保存响应头（含存在的 Retry-After/请求 ID）与错误；故障移除后发健康请求。程序测试阶段另验证这些样本进入失败统计。
- 断言：错误未伪装成功，状态/错误体可被客户端识别；有重试建议时记录实际值，不强求未承诺的字段；故障移除后恢复正常。重试若启用，每次 attempt 独立记录。
- 证据：注入来源与配置、状态/头/正文、失败计数、恢复请求。只遇到自然 429 时可覆盖该子项，不能连带声称 5xx 已测。

## API-12 超时、断开与客户端取消（部分条件项）

- 前置：取消可在普通目标测试；慢响应、读空闲、半途断开需隔离条件。
- 动作：各自测试连接失败/慢读/流半途断开；正常长流读取首事件后由客户端关闭；每个场景后发新的健康请求。
- 断言：各错误/取消可区分，等待不无限延长，客户端资源关闭；未完成流不计正常成功，健康对照成功。取消只证明客户端行为，不能证明服务端已停算或停计费。
- 证据：超时策略、已收帧、关闭原因、资源关闭记录、恢复请求。无故障条件的子项单列未验证。
