# 执行与证据规范

长期目录只放定义与可复用代码；每次运行在 `05-探索性测试/<任务>/` 保存 README、环境与负载、冻结配置、请求/任务结果、报告、问题、修订及原始证据。先读被分配任务，再按 case 查代码；不要求全读历史。

## 执行前

明确队列、生产配置、负载版本、成功断言、时间/费用/请求/用户/连接安全上限、停止与恢复。建议按共享场景10～20条断言一批；不因 checkpoint暂停剩余已分配队列。凭据使用环境变量或受控配置，报告注明单key/多key/共享配额模式，不展示凭据。

既有代码必须优先复用，能力与限制见 [code](../code/README.md)。缺能力才在任务 code 中登记驱动/函数，保留参数、返回、调用日志、版本与 SHA；完成后管理者审核入库。本方案不授权任何真实请求。

## 每个结果的最小记录

- 唯一 case/attempt、request/turn/user/window 关联；期望断言、实际值、状态及原因。
- 协议/有效请求/任务三层结果；开始、有效输出、结束/失败时间；实际 token、终态、错误分类。
- 原请求/流与解析结果路径、SHA-256；代码、配置、负载夹具哈希；计时/聚合口径与统计输入。
- 未验证或条件不满足写缺失依赖，不能算通过；暖机、正式、恢复独立分组。

证据不修改。修正解析或判定保留原 attempt和推断，新修订引用旧证据并说明理由。校验器通过仅代表记录结构，不代替内容和容量验收。

## 持续窗口与续跑

每个窗口的每次尝试使用独立attempt路径。先落开始记录，逐请求记录发起与完成，资源采样持续刷新到磁盘，最后落完成/中断记录。中断后重跑使用新路径，不覆盖同名JSON/raw；总请求/费用同时说明中断和正式尝试，不能只报正式窗口请求数冒充全部消耗。

不能以文件存在或done=true跳过。复用某个已完成窗口前，核对原件SHA、完整配置与执行器版本、实际时长、最小样本及排空状态；显式引用被复用attempt。预算或安全停止导致提前结束，不认定正式完成。复用证据与容量有效性分别判断，受限窗口即使完整也不能填网关失败边界。

正式窗口前记录非secret的credential_id，以及同endpoint/key或共享配额是否还有UI、其他Agent或压测器调用。`declared_exclusive`表示执行者已安排其他调用暂停，不是技术上证明服务端完全独占；已知共享写`observed_shared`，不能核实写`unknown`。后两者可留观测，不能无条件输出独占场景容量。

在发起与在途阶段周期采CPU、RSS、线程/句柄、TCP和调度情况，而不是只在排空后读取。周期样本不是精确峰值或服务端并发。采样失败记错误/未验证，不填0。闭环用户会有think time，不能仅因请求峰值小于用户数就判客户端受限；需要结合负载模型、启动跨度、在途记录和错误判断。

失败主类别必须互斥：客户端执行、连接、超时、HTTP、incomplete、空结果或协议；细诊断标签可重叠但不相加为失败总数。marker措辞不符单列内容质量；正文为空、传输异常及不合法终态仍是服务失败。恢复检查每次尝试都保留，后续成功不能抹去先前9/10等异常。

## 交付

使用 [报告模板](../templates/报告模板.md)，不以自动报告覆盖人工报告。正文 A体验、B指标，C兼容性小表；详细覆盖、DIFF、原始数据及代码/来源 SHA进附录。只有3～5个重要问题进正文。任务恢复、残留、边界、未完成项明确交付。
