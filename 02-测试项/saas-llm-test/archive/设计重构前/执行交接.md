# 交给实现与执行 Agent

## 任务边界

本次管理者已完成测试需求和方法设计，并落盘复用执行器。你接到明确执行任务后负责：优先使用 [现成代码](code/README.md)，缺能力才补函数，实际调用网关、执行性能和容量测试、交付可复盘的报告。所有软件 UI 操作不在范围内。

## 先准备，后分批执行

1. 读 [需求与范围](docs/01-需求与范围.md)，确认当前 TPT Work 适配器对应的包版本与接口契约。用源文件/协议资料核对即可，不启动软件。
2. 在独立探索性测试任务中复制 [环境与负载模板](templates/环境与负载.md)，填写 URL 路径、目标模型、权限/配额、能力声明、思考档映射、网络环境、SLO 与最大测试负载。标清未知项。
3. 按 [代码入口](code/README.md) 使用现成执行器并显式传本轮 task-dir；按 [执行器约定](docs/04-执行器与交付约定.md) 检查缺失能力。历史 v1 可参考，不直接照搬指标。先用本地可控 HTTP/SSE 服务验证取值与失败计数，再请求真实目标。
4. 按 [用例入口](cases/README.md) 分批：通用基础 → Responses 契约 → 性能基线 → 容量。每批共享已取得的证据，避免为了不同编号重复同一请求。
5. 容量按 [指标与容量](docs/03-指标与容量.md) 推进。先低负载试运行，确认计时、成功判定和计量正确，再执行声明的负载档位。网关契约前置失败时记录容量前置不成立，不能据失败请求计算“可用用户数”。
6. 恢复临时环境，生成报告与证据索引；按 [交付约定](docs/04-执行器与交付约定.md) 自查。完成全部分配实例后交付，不以 checkpoint 为暂停点。

## 必须取得的信息

- 测试网关 URL、模型目录路径、Responses 路径；如需评估 Chat，再给出 Chat 路径。
- 测试凭据引用与账户限流/额度；凭据用环境变量，不进入请求日志和报告。历史测试 key 不保证仍有效。
- 可用模型与实际路由身份；未购买的模型单列“当前不可用/不评容量”，不能悄悄换模型补成功。
- 主力模型、上下文规模、输出上限、思考档、每用户思考间隔、文本/工具场景占比、用户鉴权方式。
- SLO 与允许的最高负载/测试窗口。模板数值是设计示例，未经确认不能冒充产品要求。
- 隔离故障注入条件。缺少时，API-11/12、TPT-10 中相应故障实例登记未验证，不作为真实网关通过结论。

## 缺信息时怎么做

可实现和离线验证代码，列出缺失字段及影响。可执行的普通契约项正常推进。未知 SLO 的性能结果只作测量；未知用户负载模型只能报告请求并发，不能给“最多支持 N 用户”。

不要自行编造线上参数，也不要把本地模拟服务通过写成目标网关通过。新增任务函数与实测结果留在任务目录供双方审核；本目录保持测试定义与经审核的复用执行器，不放实际任务结果。
