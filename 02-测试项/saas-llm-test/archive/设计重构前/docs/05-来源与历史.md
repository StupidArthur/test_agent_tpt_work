# 05 来源与历史

## 原材料保留

原 `llm-bench-kit`、压缩包、两份报告和日志整体放入 [archive/v1](../archive/v1/)。[来源清单](../archive/来源清单.json) 保留 12 个文件的原路径、归档路径、字节数与 SHA-256。旧结果和原规则不覆盖。

旧 kit 标注 1.0.0；旧结果来自既往测试环境，不能表示当前网关和模型的状态。旧 key 原样保存在原配置中，新执行任务应使用有效环境变量，不抄入报告。

## 新设计修正了什么

| 旧版观察/设计限制 | 新设计处理 |
|---|---|
| 以 Chat 请求为主 | 增加 TPT Work 原生 Responses 契约，分别给结论 |
| 首 data 事件当 TTFT | 首事件、推理、正文、工具分开计时 |
| tok/s 与 chunk/s 用于推断并行路线 | 保留各自单位，取消无依据的路线推断 |
| 部分内部失败可能未进入 section_errors | 每个 attempt 进入台账与失败分布，errors 空不等于业务全通过 |
| 缺 usage 可能记 0 | 记 null，报告计量完整率 |
| “重复/全新”上下文被解释成缓存/纯 prefill | 测端到端路径；仅有服务缓存字段才报告命中事实 |
| 一次并发波次被用于容量解释 | 区分请求扫描、闭环用户、开放到达与持续复核 |
| 同名 low、同 suite 被当作可比 | 保存 wire 参数、模型/路由、prompt、版本、网络和样本，再判断可比性 |
| 流集中到达被直接解释成伪流式 | 记录事件节奏，不凭客户端时间点确定内部实现 |

这些是方法修正，不撤销历史观察。新版正式实测还未执行。

## 协议依据与版本边界

- [本地 @tpt-work/llm-tpt README](../../../01-产品资料/安装包技术资料/原始提取/dsh/node_modules/@tpt-work/llm-tpt/README.md)：宿主请求、模型目录、推理档和流事件。当前设计用它描述网关契约；执行前核对实际目标包版本。
- [OpenAI Responses 流事件参考](https://developers.openai.com/api/reference/resources/responses/streaming-events)：Responses 正文、工具、完成/失败事件。
- [OpenAI 工具调用指南](https://developers.openai.com/api/docs/guides/function-calling)：函数调用与工具结果回填的协议结构。
- [OpenAI Chat 流事件参考](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)：delta、finish_reason 与流式计量边界。
- [OpenAI Chat 请求参考](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)：请求字段及 stream_options。

OpenAI 资料是兼容格式的参照，不代表第三方网关已经支持所有可选字段。TPT Work 必需契约与网关声明能力优先，差异逐项登记；不得无提示换协议或删字段让请求通过。
