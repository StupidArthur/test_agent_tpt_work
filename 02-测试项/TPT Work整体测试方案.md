# TPT Work 整体测试方案框架

[返回测试项](README.md)

本文定义整体测试方案的范围、功能分类和验收结构，供后续逐章编写测试设计与用例。它不是当前版本功能清单，也不是测试通过报告。框架依据用户确认的产品定位与章节划分；具体功能是否存在、如何操作和预期如何，须结合当前版本、已审核实测及明确的产品约定确认。

## 一、总体目标与组织原则

### 1. 产品定位与测试目标

TPT Work 是基于 dsh harness 的桌面 Agent 产品，具备类似 WorkBuddy 的工作形态，面向工业用户提供项目、任务、连接器、技能和专家等功能。工业特色主要体现在中控既有产品及工业通用组件的连接能力，以及偏向工业场景的技能与专家内容。

整体测试以用户可操作的功能为主线，判断功能能否使用、结果是否正确、权限是否有效、异常是否可理解以及状态能否保留和恢复。同类产品只用于理解形态，不直接作为功能或验收标准。

连接器是重点测试章节；技能与专家的专业效果另设附加测试项，基础功能结果与专业效果评分分别报告。

### 2. 范围划分

整体功能范围由以下六章构成，文件与产物归入项目与任务，安装启动独立于账号，设置单独成章。项目与任务暂不拆章，待功能盘点后再决定。

| 编号 | 章节 | 核心问题 |
|---|---|---|
| F1 | 安装与应用生命周期 | 软件能否正确安装、升级、启动、关闭和重新进入？ |
| F2 | 账号与登录 | 用户能否建立、识别和结束正确的登录状态？ |
| F3 | 项目与任务 | 用户能否组织项目、完成任务并查看和使用结果？ |
| F4 | 连接器 | 用户能否连接目标系统并完成连接器提供的操作？ |
| F5 | 技能与专家 | 用户能否获取、管理并在任务中调用指定能力？ |
| F6 | 设置 | 配置能否正确展示、修改、保存并在约定范围生效？ |

六章是当前约定范围的划分。后续发现无法归属的实际功能，先记录分类缺口，再明确调整父节点范围或新增子项，不把它随意塞进相近章节。基础功能、专业效果附加题及后台专项测试的结论不混算。

### 3. 渐进阅读与分解规则

全文采用“总体范围 → 分项验证 → 综合验收”。总体给出边界和入口；分项逐层展开；综合部分通过场景和覆盖汇总判断用户流程是否成立，不只重复各章摘要。

- 每个父节点先定义范围与排除项，再列子节点；子节点范围的并集应覆盖父节点，重叠处指定唯一主归属。
- 每层通常保留 3～5 个子节点；顶层六章按已确认的功能边界保留，不为凑数量强行合并。
- 父页只提供摘要、边界和下一层入口；详细前置、动作、断言、参数与恢复放在叶子用例。已知目标可直接进入叶子，不要求通读全部资料。
- 每项功能有唯一编号。跨章节场景引用已有编号，不复制同一用例形成多个维护版本。
- 子节点结果向父节点汇总时，保留失败、未验证与阻塞；关键断言缺失不能被其他子项通过抵消。

### 4. 依据与通用验证维度

当前操作知识优先查[产品特性与操作导航](../00-产品特性与操作导航/README.md)、[冒烟用户确认结果](TPT Work冒烟测试/smoketest-1012-用户确认结果.md)和[工具场景入口](../04-测试工具/ui-driver/docs/功能索引.md)。保留来源版本与环境，工具存在不等于业务已验证。设计文档可用于预期对照，不能单独证明功能已经实现。

各章按适用性考虑四个维度：正常操作与结果；输入边界与权限；失败反馈与恢复；状态持久化与实际生效。性能和 Windows 兼容性按实际支持范围建立专项组合，不要求每条用例重复全部维度。未确认入口标“待盘点”，未确认判据标“待明确”，不擅自给出通过标准。

## 二、分章节测试设计

### F1 安装与应用生命周期

范围：软件包在本机的部署、进程与窗口生命周期，以及再次启动时的应用状态。账号身份由 F2 负责，具体任务内容恢复引用 F3。

| 子项 | 测试范围 |
|---|---|
| F1.1 安装 | 支持的安装方式、安装路径、完成反馈、安装后可启动性；具体方式以发布支持范围为准 |
| F1.2 升级 | 支持的升级入口、版本变化、用户数据保留、失败反馈；回滚仅在产品支持时测试 |
| F1.3 启动与窗口 | 首次及再次启动、已有实例、主窗口显示、最小化与恢复；按实际产品行为区分窗口与进程 |
| F1.4 关闭与退出 | 关闭窗口、托盘行为、完全退出、重新启动；存在执行中任务时的反馈和影响 |

汇总要求：明确哪个版本、哪种安装方式和系统环境已验证；关闭窗口成功不能替代应用退出成功。

### F2 账号与登录

范围：认证入口、登录状态及用户身份，不包含软件安装和一般偏好设置。

| 子项 | 测试范围 |
|---|---|
| F2.1 登录入口与输入 | 实际支持的登录方式、字段、协议勾选、按钮状态、无效输入与认证错误 |
| F2.2 登录成功与身份 | 首页到达、账号显示、身份一致性；有多账号能力时验证相应隔离规则 |
| F2.3 登录状态保持 | 记住密码、重新打开后的状态；凭据失效等按可复现条件验证，不推定产品必有某种机制 |
| F2.4 退出登录 | 确认交互、回到登录页、正在执行任务的影响、再次登录 |

汇总要求：区分“认证成功”“显示了正确账号”“状态被保留”，并记录退出前后任务与数据状态。

### F3 项目与任务

范围：用户组织工作、发起与管理任务、与执行过程交互，以及在任务中使用文件和查看成果。连接器协议操作归 F4，技能与专家自身管理归 F5。

| 子项 | 测试范围 |
|---|---|
| F3.1 项目管理 | 创建、打开、选择及移除项目，名称与目录绑定，项目内任务归属；重命名等按实际入口盘点 |
| F3.2 任务输入与配置 | 新建任务、草稿、输入、附件和引用、模型与推理配置、当前任务权限 |
| F3.3 执行与过程交互 | 发送、运行状态、工具调用、审批允许/拒绝、问题卡、取消与继续、异常反馈；只验证实际提供的操作 |
| F3.4 会话与任务管理 | 历史会话切换、搜索、排序、未读、归档等实际能力，任务身份与内容对应关系 |
| F3.5 文件与成果 | 项目文件的读取/生成/修改，附件发送后的表现，产物链接与预览；保存/导出仅在有对应能力时展开 |

边界：附件进入草稿由 F3.2 验证，发送后处理与产物表现由 F3.5 验证；当前任务权限由 F3.2/3 验证，默认权限配置归 F6。文件实际变化与助手声称完成分别取证。

汇总要求：用同一项目、session 和本轮请求关联输入、过程与结果。审批卡与问题卡分别处理，不能用历史回复判定新任务完成。项目与任务是否拆章暂不决定。

### F4 连接器

范围：连接器自身的配置、认证、连接与能力调用。此章是工业特色的主要测试重点，按实际交付的连接器逐个建立覆盖，不把“支持 MCP”当作所有连接器均可用的证明。

先盘点连接器，再展开测试：

| 分组 | 内容 |
|---|---|
| F4.1 中控产品连接器 | 按具体中控产品、连接器版本和支持的业务操作建立子目录；具体名单待盘点 |
| F4.2 工业通用连接器 | OPC UA 等实际提供的工业组件连接能力 |
| F4.3 其他连接器 | 实际提供的其他外部系统或服务连接能力；与前两组互斥归类 |

每个连接器统一按以下四项分解；连接器特有内容写在对应子项中，不平铺出另一套重复分类：

1. **配置与鉴权**：参数、凭据、账号权限、配置保存及错误反馈。
2. **连接与资源发现**：连接状态、可访问资源、资源身份和读取范围。
3. **支持的操作**：对照该连接器能力清单验证读取及其实际支持的写入/动作；结果、权限与副作用分别核验。
4. **异常与恢复**：不可达、超时、断连、部分失败、重连与重试，检查反馈及重复执行影响。

工业数据按实际接口检查对象/测点身份、时间、单位和质量状态。OPC UA 的浏览、读取、订阅、写入等均须先确认实际提供哪些能力，再纳入用例；不默认全部支持。涉及控制或生产写入时，必须使用经授权的测试系统或模拟设备，明确可操作对象和恢复方法。

汇总要求：给出“连接器 × 版本 × 支持操作 × 验证状态”覆盖表。连接成功不等于每项操作正确；某个连接器通过不代表其他连接器通过。任务如何发起调用并展示结果，由 F3 引用本章能力编写集成场景。

### F5 技能与专家

范围：技能与专家的基础功能生命周期。两类对象分别执行适用用例，共用分类结构，不把其中一类的通过结论迁移给另一类。

| 子项 | 测试范围 |
|---|---|
| F5.1 发现与获取 | 市场列表、搜索、详情、安装或导入、校验反馈；仅纳入实际入口 |
| F5.2 本地管理与配置 | 本地列表、对象身份、启停及配置、文件与详情查看，按两类对象实际能力区分 |
| F5.3 引用与调用 | 从入口引入指定对象、会话关系、内容加载、实际调用轨迹；避免组合函数提前完成被测行为 |
| F5.4 更新与移除 | 更新或覆盖、冲突处理、无效内容反馈、停用/移除及状态变化；不存在的操作标不适用 |

基础功能判据是“指定内容是否正确获得并用于本轮调用”，不是“模型回答是否达到行业专家水平”。引用标签出现、模型复述名称、实际加载和规则生效分别取证。

汇总要求：按对象类型报告可用范围和缺口，专业效果单独进入附加项 A1。

### F6 设置

范围：设置界面内的配置展示、修改、保存与生效。按配置对象划分，每组内部检查初值、修改、重开回读、作用范围与恢复。

| 子项 | 测试范围 |
|---|---|
| F6.1 外观与显示 | 主题、语言、字号、用量或步骤展示等实际设置 |
| F6.2 任务默认行为 | 默认权限、场景及其他任务默认配置，既有任务与新任务的作用范围 |
| F6.3 交互与入口偏好 | 快捷键、链接打开方式等实际交互配置 |
| F6.4 扩展与运行配置 | 插件、记忆相关开关/参数、实验或开发选项等实际设置 |

边界：连接器凭据和连接配置归 F4，技能/专家对象配置归 F5。记忆设置的保存与效果入口归本章；记忆条目管理、注入和自动沉淀等已有专项继续引用[记忆与进化测试项](记忆与进化功能测试/README.md)，详细归属在功能盘点时确认，不用“开关已打开”代替记忆行为通过。

汇总要求：选中值正确、保存成功、重开保持、实际效果成立分别核验；保存错误保留原文，不通过直接改文件补成 UI 成功。

## 三、综合场景与验收

### 1. 综合冒烟

从各章选取已定义用例组成少量贯通场景，复用原编号和断言：

| 场景 | 跨章链路 | 最终判定 |
|---|---|---|
| 基础工作闭环 | F1 启动 → F2 登录 → F3 选项目/发任务/看结果 | 用户可以完成一个最小工作任务，结果属于本轮对象 |
| 连接器工作闭环 | F4 配置连接 → F3 发起指定操作并展示结果 | 调用了正确连接器和对象，结果及实际副作用符合预期 |
| 技能/专家工作闭环 | F5 获取并引用 → F3 执行并查看调用 | 指定能力实际参与本轮任务；专业质量另评 |
| 配置与恢复闭环 | F6 修改默认行为 → F3 创建任务验证 → 恢复 | 配置在正确范围生效，恢复后状态可核验 |

连接器场景须按重点连接器分别选样，不能只用一个通用示例代表全部工业连接能力。

### 2. 覆盖汇总与发布判断

分项用例至少记录功能编号、来源/版本、前置与样本、动作、独立预期、实际结果、证据引用及恢复。执行按[任务约定](执行任务约定.md)另建探索任务，正式方案不写入未经审核的通过结论。

叶子用例汇总到子项，再汇总到六章和综合场景：列出通过、差异/失败、阻塞、未验证、不适用及对应依据。综合场景通过不能覆盖分项缺陷，分项均通过也不能自动代替组合场景。

优先级建议：关键闭环、身份与权限、数据完整性及重点连接器为优先范围；其余主功能其次；外观细节和低频组合按发布目标安排。具体发布必测清单在版本计划中确定。关键项失败或未验证时，明确其发布影响，不以平均通过率抵消。

### 3. 附加项 A1：技能与专家工业效果

在 F5 基础功能可用的前提下，单独准备工业样本、输入条件、参考依据和业务评价标准，评价专业准确性、任务适用性、解释依据及结果可用性。需要工业领域人员参与判断的内容明确标注，不由测试 Agent 自行替代专家结论。

效果测试固定技能/专家版本、模型与关键配置，记录重复执行差异。结果以独立报告呈现，不混入基础功能通过率；是否纳入某次发布门槛由该版本计划明确。

### 4. 后续展开与资料归属

本文件作为总纲。下一步先盘点六章的实际功能与连接器清单，标记“已观察、待验证、待盘点、不适用”，再按需拆分章节文档和叶子用例，不提前批量创建空文档。

- 00 保存基于实测的功能与操作导航；本方案及正式用例留在 02。
- 03 提供执行方法，04 提供工具；工具调用成功不代替业务断言。
- 05 保存每轮执行证据与待审核结果，审核后的结论进入 06。

最终交付同时回答三个问题：约定的功能范围是否覆盖；各功能在什么条件下可用；组合后能否完成关键用户流程。未完成和未知部分明确列出，供下一轮继续验证。
