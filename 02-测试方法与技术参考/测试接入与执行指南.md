# 测试接入与执行指南

这份整理将通用接入方法、历史实测与外部依赖分开。详细代码保留在 [启动与测试实操指南](portable-agent-exe-ui-api-guide.md)，这里先说明使用条件，避免复制历史参数就开始执行。

## Agent 操作 TPT Work 的默认方法

真实 UI 探索和回归优先走 **Electron 调试端口 + Playwright/CDP**：确认旧实例与端口归属 → 以 `--remote-debugging-port=9234` 启动或复用实例 → 验证 `/json/version` 和 `/json/list` → 连接目标页面 → 观察并分组操作 → 等待结果、重新观察与断言。同一稳定界面上的已确认操作（如填写登录表单）可在一次工具调用中顺序执行；提交、导航、弹窗或其他流程状态变化后，先重新发现页面和控件，再执行下一组动作。详见[操作分组规则](portable-agent-exe-ui-api-guide.md#操作如何分组)。登录页可能是 `file:///.../renderer/welcome.html`，主界面是 `dsh-app://app/`；两者可能同时出现在 target 列表，按当前可见页面选择。可运行命令和代码见[原指南的 Agent 默认执行路线](portable-agent-exe-ui-api-guide.md#agent-默认执行路线先读)与[第 2 层](portable-agent-exe-ui-api-guide.md#第-2-层启动并操作-ui)。

本机 2026-10-05 的一次接入验证中，CDP 返回 TPT Work 的 `dsh-app://app/` target；Playwright 连接后读到登录页，并完成手机号与账号密码选项卡往返切换。该结果只证明当时安装包的 CDP 接入和这一项 UI 操作。测试网关使用 `--test --port --token`，用于 API / wire 验证，需按独立模式启动与验证。

## 接入前先确认什么

1. 确认实际 exe 路径、用户配置目录、项目目录、模型和权限；不要使用原记录中的其他机器用户名与 F 盘路径。
2. 记录 exe 版本及 app.asar 的实际身份；旧批次同版本号换过包，仅版本号不够。
3. 确认已有进程、端口与任务归属。Electron 多进程不能按进程名称统一结束；原记录也区分主进程、renderer 与宿主运行时。
4. 阅读对应批次 RULES。原生弹窗限制与自主执行范围来自不同历史批次，不能合并成无条件授权。

## 两种入口，以及它们证明什么

| 入口 | 参数 / 方法 | 验证成功的最低条件 | 边界 |
|---|---|---|---|
| 真实 UI | --remote-debugging-port=9234；Playwright 连接 CDP | /json/version 与 /json/list 可达，目标确为 TPT 页面，并核对当前可见状态 | 9234 是历史使用值；CDP 可达不等于业务通过 |
| API / wire | --test --port=18471 --token=<token>；HTTP Bearer | 原指南要求带 token 的 /__verbs 返回 200，网关仍存活 | 来自指南的接入约定，不把早期“文档中支持”升级为本次验证 |

原指南提到的 tests/ui/fixtures/app.ts、npm ci 与测试 case 依赖配套测试仓库；现有资料目录不能仅凭这些文字被视为完整可运行工程。fixture 默认端口 9223 与示例 9234 不同，复用时需要一致配置。当前整理没有安装依赖、启动应用或验证 API 网关。

来源：[原指南：两条入口、第 1—2 层](portable-agent-exe-ui-api-guide.md)；[早期启动参数验证范围](../03-%E6%B5%8B%E8%AF%95%E6%89%B9%E6%AC%A1/%E6%97%A9%E6%9C%9F%E6%8E%A2%E7%B4%A2_%E5%8E%9F%E6%A0%B9%E7%9B%AE%E5%BD%95/01-product-info.md)。

## UI 执行要识别哪种表面

| 表面 | 已有经验 | 执行规则方向 |
|---|---|---|
| Electron renderer | dsh-app://app/；窗口尺寸在批次中变化 | 先读当前页面和弹窗，按语义定位，不复用截图坐标 |
| 内嵌模块 | 技能、连接器、资产、专家使用 iframe；插件在顶层 | 检查 frame 与当前内容，不把顶层找不到当成功能不存在 |
| Windows 原生弹窗 | 不在 DOM；早期删除确认曾阻塞 CDP | 记录阻塞并遵守批次人工处理规则，不连续点击后台 |
| 拖拽与菜单 | 项目会话 treeitem 与最近/置顶 button 不同；合成拖拽事件未达效果 | 区分实现表面，失败的合成事件不等于实际拖拽功能失败 |

## 把一次运行变成可追溯的质量信息

建议后续新批次记录：包身份与环境 → 目标行为与预期依据 → 输入及夹具 → 实际动作 → UI/磁盘/请求证据 → 结论与未验证范围。这是整理后的使用建议，不是宣称现有资料已经具备全部字段。

截图规则：通过的case默认不截图，保留实际值、断言结果和操作/读取日志。失败或不确定、用例外疑似问题仅在图像能说明异常时截图；布局、遮挡、样式等视觉检查确需图像时例外。同一现场共享一张，关联相关case；不每步或每条自动截图，不为通过结果补拍。历史证据保留，截图不代替断言。

不同证据不能互换：源码/设计描述预期；人工夹具只描述输入；截图和实际输出描述观察；模型复述的注入内容不是独立的进程捕获。导出的 refs 属于对应包与批次，不能自动代表最新实现。
