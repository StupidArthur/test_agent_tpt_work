## Agent 的最短路径

1. 明确当前 case 的对象、动作和需要证明的结果。
2. 有编号查 `--plan`；没有编号查 `--find`，默认只返回5个候选。
3. 对少量候选查 `--describe`，核对额外动作、实际取值和恢复要求。
4. 现场确认前置，调用，再用原始值判定。搜不到时换词、查模块；最后才读源码或补函数。

```powershell
node tools/ui-operations/call.mjs --modules
node tools/ui-operations/call.mjs --find "技能 快捷使用" --module skills --limit 3
node tools/ui-operations/call.mjs --describe skills.useSkillDirect
```

这是本地关键词检索，不调用模型，不需要向量库或网络。空格分隔关键词，按命中词数量和字段权重排序；名称、关键行为词优先于模块关键词。limit为1～20。搜索结果是候选，不是自动推荐执行的决定。任务新增函数可带 `--task` 一起发现。

## 存放方式确实影响查找

| 层次 | 存放与命名原则 |
|---|---|
| 功能模块 | `business/<模块>/`，例如 `business/skills/`；对应 `conversation.*`、`skills.*`、`experts.*` 名称 |
| 子功能 | 模块内按会话、权限、导入、查看等业务拆文件；优先沿用现有划分 |
| 底层操作 | CDP、定位、控件和记录放 `automation/`，不要求 Agent 逐项选这些底层实现 |
| 测试材料 | 夹具放 `fixtures/`，case映射放 `coverage/`，原来源放 `sources/` |

不按测试执行先后给函数文件编号；函数名称与参数保持稳定。文件系统默认顺序不承担工具推荐职责。功能索引按固定模块顺序→子功能路径→函数名排序，不再按迁移/追加顺序排列。后续模块新增函数自动进入对应分组。

## 两份小登记，职责分开

- `business/catalog.json`：函数实现位置、参数、前置和恢复契约，是调用入口的依据。
- `business/discovery.json`：模块顺序、功能同义词，以及少量容易选错的函数提示。不复制全部参数，不再造第二套调用库。

目前补充关键函数的 effects、evidence、limits，在 `--find/--describe` 中展示。其他函数尚未补这类具体提示时，不应把通用返回描述当成完整断言说明；按实际返回核对，逐步补齐。

维护函数时更新 catalog；只有功能关键词、模块顺序或选用陷阱改变才更新 discovery。运行 `node tools/ui-operations/maintenance/build-tool-docs.mjs` 同步功能文档。实际场景中查找不到或选错的词，再补同义词，不提前构建复杂分类系统。
