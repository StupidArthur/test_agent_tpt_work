## 选择与创建

先用 conversation.readProjectControls 读取当前项目、列表及入口。新建任务 → “选择项目”，根据实际出现的界面选路线：

| 当前界面 | 操作路线 | 工具入口 |
|---|---|---|
| 已有项目菜单 | 选择准确项目，回读输入区项目名称，再发送与该目录有关的请求 | [项目选择](../04-测试工具/ui-operations/docs/scenarios/conversation.project.entry.md)：clickSelectProject / clickMenuItem；SMK-06 |
| “新建项目”表单 | readProjectForm → fillProjectForm 填名称 → “选择文件夹” → 完成系统选择器 → “创建” → 回读项目行与选中项 | [项目表单](../04-测试工具/ui-operations/docs/scenarios/conversation.project.form.md)；SMK-07 观察到该路径 |
| 直接出现 Windows 文件夹选择器 | 按下节选目录，回到产品后读项目是否选中；同时记录没有表单的行为 | SMK-05/05R 在 0.1.3 空项目列表观察到此路径，但用户对“缺少新建项目表单”判失败；可完成目录绑定不等于创建流程符合预期 |

不根据“首次”二字硬编码唯一流程。新组合工具见[打开本地项目](../04-测试工具/ui-operations/docs/scenarios/conversation.project.open.md)和[创建项目](../04-测试工具/ui-operations/docs/scenarios/conversation.project.create.md)；工具入口注明待现场验收的部分，不能借用旧分步成功替代组合验收。

## Windows 文件夹选择器

产品入口触发后，使用 [nativeWindow 分类](../04-测试工具/ui-operations/docs/modules/nativeWindow.md)：probe 发现属于本次应用的窗口 → describe 读取结构 → act setPath 输入本轮实际目录 → 回读路径 → act confirm → 产品内回读项目。

smoketest 中 DOM 没有弹窗时，原生“选择文件夹”仍可能阻塞主窗口。句柄和 PID 每轮取得；不能复制历史数值。选择器消失仅表示原生交互结束，不代表项目创建成功。

## 项目内工作与移除

- 创建项目会话：用 conversation.newSessionInProject；发请求后同时核验会话归属及实际文件。SMK-06/08 已观察项目目录相关操作。
- 移除：目标项目行 → 操作菜单 → “移除项目” → 确认；[管理工具](../04-测试工具/ui-operations/docs/scenarios/conversation.project.manage.md) readProjectRow / readProjectMenu / removeProject。
- SMK-05R 的确认文案明确“文件夹与会话记录会保留”。移出项目列表不能用作删除文件或重置用户数据的替代方法；需验证保留性时另行取证。
